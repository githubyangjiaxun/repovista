# v1.0 前端开发文档：Explanation History

状态：已实现并验收（2026-08-25）

## 1. Finding 内历史入口

每个 Guardrail Finding 卡片增加只读“Explanation history”入口。历史只在用户展开时请求，避免报告
加载时为所有 Finding 发起额外请求。

状态为 `idle`、`loading`、`ready`、`empty`、`error`。切换 Repository、Snapshot 或关闭卡片后，旧
响应不能覆盖当前状态。

## 2. 历史列表

- 按 API 顺序展示 Commit、创建时间、Answer status、provider/model、prompt 和 Profile fingerprint。
- 摘要明确标记为已保存的 verified explanation，不把它显示成当前重新生成结果。
- 空历史说明“尚未为该逻辑 Finding 保存解释”；Viewer 仍可查看历史。
- 支持“Load more”，仅使用服务端 cursor，不在客户端拼接 offset。
- 新解释生成成功后重新加载该 Finding 的第一页，使当前结果立即进入历史。

## 3. 两版本比较

历史不少于两条时提供 Base/Head 两个 select，默认选择较旧记录为 Base、最新记录为 Head。两者相同
时禁用比较。

比较视图分区显示：

- provenance：Commit、parser、algorithm、Profile、provider/model、prompt；
- Finding：severity、message、location、metric、evidence；
- verified Answer：status、summary、steps、limitations、citations。

每项只显示 `same` 或 `changed`，并提供 base/head 值或完整解释详情。界面必须写明比较是字节/结构
差异，不评价模型质量。Base/Head citation 分别打开各自 Snapshot 的固定源码范围。

## 4. 可访问性、隐私与竞态

- 展开按钮使用 `aria-expanded`，加载容器使用 `aria-busy`，比较结果有可读 section label。
- 历史摘要不在浏览器 URL、localStorage 或日志中保存源码 quote。
- 通过 request sequence 或 effect cleanup 丢弃过期历史、分页和比较响应。
- API 错误展示 Request ID；已有 Finding/解释内容不能因比较失败而消失。

## 5. 测试

- 按需加载、空状态、分页追加、错误和旧响应丢弃。
- Viewer 能查看历史但不能生成解释。
- 默认 Base/Head、同项禁用、成功比较和跨 Finding 不兼容错误。
- Base/Head citation 打开正确 Snapshot，而不是当前页面 Snapshot。
- Chromium 覆盖历史展开、两版本比较和固定证据跳转。
