# v0.2 前端开发文档

状态：已冻结，待实现

## 1. 用户目标

v0.2 前端要让用户直接看懂三件事：本次结果固定在哪个 Commit、静态分析是否复用了上一快照、结果如何被带出 RepoVista。AI 继续是可选解释层，增量状态、Python 图谱和导出都必须在没有模型的情况下工作。

## 2. 页面变更

### Repository Workspace

现有 `/repositories/:repositoryId?snapshot=:snapshotId` 继续作为主工作区，并增加：

- Topbar 显示 `full index` 或 `incremental index` Chip。
- Ready Snapshot 的操作区增加 Markdown 和 SVG 下载操作。
- Overview 增加 `Update delta` Panel：
  - Parsed：本轮实际进入 Tree-sitter 的文件数。
  - Reused：从同 Parser 基线复用的 ParsedFile 数。
  - Changed：新增或内容变化的全部扫描文件数。
  - Deleted：基线存在、当前快照不存在的文件数。
  - Base：基线 Snapshot/Commit；全量索引显示 `No compatible baseline`。
- Language Distribution 正常展示 Python。
- Automation Panel 展示：
  - Server GitHub App Webhook `enabled/disabled`。
  - 当前仓库是否收到过有效 Push。
  - 最近一次 Webhook 时间。
  - Public repositories only 的边界说明和 Docs 链接。

下载必须绑定当前页面已经选中的 `snapshot.id`，不能偷偷切换到 Repository Latest Snapshot。

### Index Job Progress

- Parsing 阶段的 SSE Message 必须区分 `Parsed X changed files; reused Y unchanged files`。
- 空变化或全部复用仍应显示有效进度，不得停在 45%。
- 完成后继续跳转到请求创建时的固定 Snapshot。

### Home 与 Docs

- 首页能力文案从 TS/JS-only 更新为 TS/JS + Python。
- Docs 页面增加增量索引、GitHub App Webhook 配置和导出说明。
- 不展示“私有仓库自动同步”“Installation Token 已支持”等未实现能力。

## 3. 数据访问

新增读取：

```text
GET /v1/integrations/github
```

Repository、Snapshot Contract 扩展后仍由 `apps/web/lib/api.ts` 统一导出类型。导出使用原生下载 URL，不把可能很大的 SVG/Markdown 先读取进 React State：

```text
GET /v1/snapshots/:snapshotId/exports/markdown
GET /v1/snapshots/:snapshotId/exports/svg?level=package
```

API Origin 必须继续由 `NEXT_PUBLIC_API_ORIGIN` 构造；不能假设 Web 与 API 同源。文件下载的新窗口或链接需要 `noopener` 语义。

## 4. 组件设计

- `RepositoryExplorer` 负责选中 Snapshot、集成状态和下载入口的编排。
- `SnapshotDelta` 作为纯展示组件，接收 Snapshot Contract，不自行请求 Latest。
- `AutomationStatus` 作为纯展示组件，区分 Server Enabled 与 Repository Connected。
- 下载按钮使用语义化 `<a>`，因此键盘、浏览器下载和无 JavaScript 降级都可工作。
- 继续复用现有 Design Tokens、Panel、Chip、Button，不引入第二套组件库。

若简单组件没有形成真实复用，不为“组件数量”强行拆文件。

## 5. 状态与错误体验

- Integration Status 请求失败不应阻断 Source、Map、Ask；Automation Panel 显示 Unavailable。
- Export 只有 Ready Snapshot 可用；Loading/Failed Snapshot 不渲染有效下载链接。
- 下载接口失败由浏览器展示服务端结构化错误，不生成空文件或 HTML 冒充 SVG。
- 旧 v0.1 Snapshot 的 `stats.indexing = null` 时显示 `Legacy full index`，不能伪造复用数据。
- 所有时间以 API ISO Timestamp 为准，前端只负责本地格式化。

## 6. 响应式与无障碍

- Topbar 操作在窄屏允许换行，不覆盖 Repository Identity。
- Delta 指标在桌面四列、平板两列、手机一列。
- Chip 不能只用颜色表达 full/incremental/enabled/disabled。
- 下载链接必须有可读文本和文件类型；Icon 设置 `aria-hidden`。
- Automation 状态使用文本，不用自动播放动画。

## 7. 前端验收

- Component Test：旧 Snapshot、Full、Incremental 三种 Delta。
- Component Test：Integration Enabled/Disabled/Unavailable。
- Playwright：固定 Snapshot Workspace 显示正确增量元数据并构造正确下载 URL。
- Playwright：Markdown/SVG 下载事件的建议文件名和响应类型正确。
- Playwright：Python 文件可出现在 File List，并能打开源码。
- 回归：Overview → Source → Map → Ask → Citation → Share 旅程继续通过。

修改 App Router 代码前遵守 `apps/web/AGENTS.md`，以仓库安装版本的 `node_modules/next/dist/docs` 为准。
