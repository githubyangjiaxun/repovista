# 前端开发文档

状态：v0.2 已实现并验收（2026-08-20）

## 1. 技术栈与边界

- Next.js 16 App Router。
- React 19 与 TypeScript strict mode。
- React Flow (`@xyflow/react`) 展示架构地图。
- Lucide React 图标。
- 原生 `fetch` 加共享 Zod Contract；当前没有认证。
- Vitest、Testing Library、jsdom 和 Playwright。

依赖中保留 TanStack Query 与 Zustand，但当前页面状态由 React state/effect 管理。引入额外状态
层前必须证明它解决跨页面缓存、复杂共享状态或离线一致性问题，不能只为了堆叠技术名词。

前端不解析仓库、不自行计算增量状态、不伪造图关系。它展示 API 返回的不可变 Snapshot 事实。

## 3. 路由

| 路由 | 类型 | 用途 |
|---|---|---|
| `/` | 静态 | 产品首页和 GitHub URL 入口 |
| `/docs` | 静态 | 功能、自动更新、导出与信任说明 |
| `/repositories/new` | 动态交互 | URL、Ref、Ignore 导入表单 |
| `/jobs/[jobId]` | 动态 | SSE/轮询任务进度与恢复 |
| `/repositories` | 静态外壳 + 客户端数据 | Public Workspace 仓库列表 |
| `/repositories/[repositoryId]` | 动态 | 总览、Delta、Automation、地图、源码、问答、导出、分享 |
| `/share/[slug]` | 动态 | 公开、固定 Snapshot 的导览 |

Repository Workspace 使用
`/repositories/:repositoryId?snapshotId=:snapshotId` 固定结果。省略 `snapshotId` 时才读取
Repository 的最新 Ready Snapshot。当前没有 `/login`、独立 `/map` 或独立 `/ask` 路由。

## 4. API Client

`lib/api.ts` 是浏览器请求边界：

- Origin 来自 `NEXT_PUBLIC_API_ORIGIN`，默认 `http://localhost:4000`。
- 自动发送 `Content-Type: application/json`。
- 解析 `{data, meta}` 成功信封。
- 将 `{error}` 转换为带 `code`、`retryable`、`requestId` 的 `ApiError`。
- Health、SSE 和下载是明确的非 JSON 信封路径。
- `snapshotExportUrl` 统一构造固定 Snapshot 的 Markdown/SVG URL。

组件不能硬编码另一个 API Origin，也不能静默吞掉 Request ID。新增返回类型优先复用
`packages/contracts`。附件用浏览器下载链接，不先读取进 React State。

## 5. 关键组件

### ImportRepositoryForm

- 浏览器先校验 HTTPS GitHub 两段路径。
- Advanced Options 接受 Ref 和每行一个 Ignore Path。
- POST 成功后把 `repositoryId/snapshotId` 放进 Job 页 Query，支持刷新恢复。
- 失败时显示服务端 Message 和 Request ID。

服务端仍执行完整校验；前端校验只改善反馈速度。

### JobProgress

- 首先读取 Job 当前状态。
- 建立 SSE 连接接收持久化 Event 和 Worker Message。
- SSE 不可用或页面恢复时继续轮询。
- 增量 Parsing Message 展示 Parsed 与 Reused，而不是只显示百分比。
- 成功跳转请求创建时的固定 Snapshot；失败/取消保留可诊断状态。

### RepositoryExplorer

初始化：

1. 读取 Repository。
2. 选择 URL 中的 `snapshotId`，否则使用 `latestSnapshotId`。
3. 并行读取 Snapshot 和最多 100 个文件。
4. 验证 Snapshot 属于该 Repository。
5. 加载包级地图。
6. 独立读取 GitHub Integration Status；失败不能阻塞 Workspace。

交互：

- Topbar 显示 Ref、短 Commit、Full/Incremental Chip、Ready、Reindex 和 Share。
- Overview 显示统计、Snapshot Delta、Automation、语言、Package Preview、Export 和 AI 边界。
- Map 在 package/file/symbol 级别切换并支持 Query。
- Source Panel 读取整个文件或引用行范围。
- Ask 固定传当前 Snapshot ID。
- Reindex 创建新 Snapshot，不覆盖旧 Snapshot。
- Share 创建固定 Snapshot 的报告并安全打开新窗口。
- Download 链接固定当前 Snapshot，使用 `download`、`noopener noreferrer`。

### SnapshotDelta

- `stats.indexing` 存在时展示 Scanned、Parsed、Reused、Changed、Deleted 和 Mode。
- Incremental Snapshot 的 Base 链接使用精确 `baseSnapshotId`。
- Full Snapshot 显示 `No compatible baseline`。
- 旧 Snapshot 的 `stats.indexing = null` 显示 `Legacy full index` 和不可用计数横线，不能补零
  冒充历史事实。

### AutomationStatus

- 分开显示 Server Webhook Enabled/Disabled 与 Repository Connected/Not Connected。
- 展示最近一次有效 Webhook 时间。
- 明确 Public/default-branch/HMAC 边界。
- Status Endpoint 不可用时显示非阻塞提示，地图、源码和问答继续可用。

### ArchitectureMap

- 服务端返回语义图，前端只负责确定性网格布局和视口交互。
- 节点可拖动但不能连接。
- 点击带 Source 的节点打开对应行范围。
- 大图截断由 API 的 `truncated` 标志表达。

## 6. 状态与一致性

每个远程动作至少区分 idle、loading、success、failure。按钮在提交期间禁用，避免重复动作。
错误消息必须说明下一步；服务端提供 Request ID 时必须展示或保留。

Repository 页的核心一致性规则：

- 任何 Source、Map、Ask、Share、Export 请求都使用当前 `snapshot.id`。
- Reindex 成功只进入新 Job，不直接替换当前页面数据。
- Base Snapshot 链接显式改变 URL 中的 `snapshotId`。
- Integration Status 是附加能力，失败不能污染 Snapshot 加载结果。
- Repository Latest 发生变化时，已打开的固定 Snapshot 页面不自动漂移。

## 7. 错误处理

Repository 页把动作错误集中显示在 Workspace Alert；首次加载失败显示可返回导入页的 Empty
State。全局 `error.tsx` 负责未被组件处理的渲染错误。

常见处理：

- `SNAPSHOT_NOT_READY`：引导返回 Job 或稍后刷新。
- `REPOSITORY_HOST_NOT_ALLOWED`：保留输入并要求修正。
- Export 失败：保留当前 Workspace，不影响地图/源码。
- Integration Status 失败：只影响 Automation Panel。
- AI Provider 失败：说明静态结果仍可使用。

不能向用户显示 Stack、SQL、Secret 或 Clone 临时路径。

## 8. 可访问性

- 表单控件使用可见 Label。
- 导航、Tab Button、Panel 标题和进度条使用可查询的语义角色。
- API 表单错误使用 `role="alert"`。
- 图不是唯一入口：文件列表与 Citation 仍可打开源码。
- 图标按钮必须有文字或可访问名称。
- Delta 与 Automation 不能只靠颜色表达状态。
- 动画不能阻止用户完成核心流程。

## 9. 样式

当前使用单个 `globals.css` 维护设计语言：深色编辑器风格、绿色证据强调、响应式双栏
Workspace。新增样式应复用现有颜色、圆角、间距、Panel 和 Button Class，避免组件级风格漂移。

桌面布局为 Sidebar、Workspace、可选 Source Panel；窄屏转为纵向，同时保留文件、下载和
Citation 的可操作性。

## 10. 测试

Vitest/Testing Library 覆盖：

- 导入表单的客户端拒绝和成功跳转。
- Snapshot Delta 的 Full、Incremental、Legacy 状态。
- Automation 的 Server/Repository 分离、Disabled 和 Endpoint 不可用降级。

Playwright 使用确定性 API Mock，覆盖四条 Chromium 旅程：

1. 导入 → 增量进度 → Overview/Delta/Automation → Python Source → Map → Ask/Citation → Share。
2. 下载固定 Snapshot 的真实 Markdown/SVG 附件并核对内容。
3. Repository List → 固定 Snapshot Workspace。
4. 结构化 API 错误与 Request ID。

E2E 不依赖 GitHub、数据库或真实模型。真实 API/Worker/PostgreSQL/公共仓库链路由发布 Smoke
Test 单独验证。

## 11. 开发命令

```bash
pnpm --filter @repovista/web dev
pnpm --filter @repovista/web typecheck
pnpm --filter @repovista/web test
pnpm --filter @repovista/web build
pnpm --filter @repovista/web test:e2e
```

`typecheck` 先执行 `next typegen`。`next-env.d.ts` 是 Next 自动生成文件，未纳入 Git 跟踪。
Playwright 端口由 `PLAYWRIGHT_BASE_URL` 决定，避免与其他本地项目争用固定端口。
