# 前端开发文档

状态：v0.1 已实现基线

## 1. 技术栈

- Next.js 16 App Router。
- React 19 与 TypeScript strict mode。
- React Flow (`@xyflow/react`) 展示架构地图。
- Lucide React 图标。
- 原生 `fetch` 加共享 Zod Contract；当前页面没有启用认证。
- Vitest、Testing Library、jsdom 和 Playwright。

依赖中保留 TanStack Query 与 Zustand，但 v0.1 页面状态目前由 React state/effect 管理。新增状态层前先证明它解决了跨页面缓存或复杂共享状态，而不是仅为“技术栈完整”。

## 3. 路由

| 路由 | 类型 | 用途 |
|---|---|---|
| `/` | 静态 | 产品首页和 GitHub URL 入口 |
| `/docs` | 静态 | 产品内功能与信任说明 |
| `/repositories/new` | 动态交互 | URL、Ref、Ignore 导入表单 |
| `/jobs/[jobId]` | 动态 | SSE/轮询任务进度与恢复 |
| `/repositories` | 静态外壳 + 客户端数据 | Public Workspace 仓库列表 |
| `/repositories/[repositoryId]` | 动态 | 总览、地图、文件、源码、问答、分享 |
| `/share/[slug]` | 动态 | 公开、固定 Snapshot 的导览 |

v0.1 没有 `/login`、独立 `/map` 或独立 `/ask` 路由。仓库相关视图是同一 Workspace 内的 Tab。

## 4. API Client

`lib/api.ts` 是浏览器请求边界：

- Origin 来自 `NEXT_PUBLIC_API_ORIGIN`，默认 `http://localhost:4000`。
- 自动发送 `Content-Type: application/json`。
- 解析 `{data, meta}` 成功信封。
- 将 `{error}` 转换为带 `code`、`retryable`、`requestId` 的 `ApiError`。
- Health Endpoint 是少数不使用数据信封的接口。

组件不能硬编码另一个 API Origin，也不能静默吞掉 Request ID。新增返回类型优先复用 `packages/contracts`。

## 5. 关键组件

### ImportRepositoryForm

- 浏览器先校验 HTTPS GitHub 两段路径。
- Advanced Options 接受 Ref 和每行一个 Ignore Path。
- POST 成功后把 `repositoryId/snapshotId` 放进 Job 页 Query，支持刷新恢复。
- 失败时显示服务端 Message 和 Request ID。

服务端仍执行完整校验；前端校验只改善反馈速度。

### JobProgress

- 首先读取 Job 当前状态。
- 建立 SSE 连接接收持久化 Event。
- SSE 不可用或页面恢复时继续轮询。
- 成功跳转 Repository 页；失败/取消保留可诊断状态。

### RepositoryExplorer

- 初始化加载 Repository、指定的 `snapshotId`（若无则使用最新 Ready Snapshot）、最多 100 个文件和包级地图；若 Snapshot 不属于 Repository 则显示错误。
- Overview 显示文件/符号/边/语言统计。
- Map 在 package/file/symbol 级别切换并支持 Query。
- Source Panel 读取整个文件或引用行范围。
- Ask 固定传当前 Snapshot ID。
- Share 创建报告并在新窗口打开。
- Reindex 创建新 Snapshot，不覆盖旧 Snapshot。Job 成功跳转时把返回的 Snapshot ID 放入 URL，避免漂移到之后创建的最新 Snapshot。

### ArchitectureMap

- 服务端返回语义图，前端只负责确定性网格布局和视口交互。
- 节点可以拖动但不能连接。
- 点击带 Source 的节点打开对应行范围。
- 大图截断由 API 的 `truncated` 标志表达。

## 6. 状态与错误

每个远程动作至少区分：idle、loading、success、failure。按钮在提交期间禁用，避免重复动作。错误消息必须说明下一步；服务端提供 Request ID 时必须展示或保留。

Repository 页把数据错误集中显示在 Workspace Alert；首次加载失败显示可返回导入页的 Empty State。全局 `error.tsx` 负责未被组件处理的渲染错误。错误保留服务端 Request ID，便于和 API/Worker 日志关联。

## 7. 可访问性

- 表单控件使用可见 Label。
- 导航、Tab Button 和进度条使用可查询的语义角色。
- API 表单错误使用 `role="alert"`。
- 图不是唯一入口：文件列表与证据列表仍可打开源码。
- 图标按钮必须有文字或可访问名称。
- 动画不能阻止用户完成核心流程。

## 8. 样式

v0.1 使用单个 `globals.css` 维护设计语言：深色编辑器风格、绿色证据强调、响应式双栏 Workspace。新增样式应复用现有颜色、圆角、间距和 Button Class，避免组件级风格漂移。

## 9. 测试

Vitest 覆盖导入表单的客户端拒绝和成功跳转。Playwright 在浏览器网络层 Mock API，覆盖：

1. 首页导入、Advanced Options、进度、总览、源码、地图、问答引用和分享页。
2. 仓库列表打开不可变 Snapshot。
3. 结构化 API 错误与 Request ID。

E2E 不依赖 GitHub、数据库或真实模型，因此 CI 确定可重复。涉及浏览器与真实后端的完整链路由发布 Smoke Test 单独验证。

## 10. 开发命令

```bash
pnpm --filter @repovista/web dev
pnpm --filter @repovista/web typecheck
pnpm --filter @repovista/web test
pnpm --filter @repovista/web build
pnpm test:e2e
```

`typecheck` 先执行 `next typegen`。`next-env.d.ts` 是 Next 自动生成文件，已从 Git 跟踪中移除。
