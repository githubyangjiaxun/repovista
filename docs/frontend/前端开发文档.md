# 前端开发文档

状态：proposal  
适用版本：v0.1

## 1. 前端目标

前端不是一个普通的后台管理系统，而是一个“探索代码地图”的产品界面。用户第一次打开后，应当在不阅读长文档的情况下完成：

1. 粘贴仓库地址。
2. 看到索引进度。
3. 理解项目入口和核心模块。
4. 点击节点查看真实源码。
5. 提出问题并看到可验证引用。
6. 生成可分享报告。

## 2. 推荐技术栈

| 领域 | 选择 | 使用边界 |
|---|---|---|
| 框架 | Next.js + React + TypeScript | 页面、路由、服务端渲染 |
| 样式 | Tailwind CSS + Design Tokens | 不在组件中散落颜色值 |
| 数据请求 | TanStack Query | 服务端数据缓存和失效 |
| 本地交互状态 | Zustand | 地图视口、选中节点、面板状态 |
| 图可视化 | React Flow 或 Cytoscape.js | 先做适配层，不让业务依赖库 API |
| 源码 | Monaco Editor | 只读展示和行号跳转 |
| 表单 | React Hook Form + Zod | 客户端校验与错误提示 |
| 图标 | Lucide | 统一图标风格 |
| 测试 | Vitest、Testing Library、Playwright | 单元、组件和端到端 |

## 4. 路由与页面

| 路由 | 页面 | 登录 |
|---|---|---|
| / | Landing Page | 否 |
| /demo | 公共示例选择 | 否 |
| /repositories/new | 导入仓库 | 公共仓库可免登录 |
| /repositories/[id] | 仓库总览 | 按仓库权限 |
| /repositories/[id]/map | 架构地图 | 按仓库权限 |
| /repositories/[id]/ask | 仓库问答 | 按仓库权限 |
| /repositories/[id]/tour | 新人导览 | 按仓库权限 |
| /share/[slug] | 固定版本分享页 | 由分享策略决定 |
| /settings | 用户和模型设置 | 是 |

仓库详情页使用嵌套路由和共享布局，保持左侧仓库导航、顶部 Snapshot 选择器和右侧上下文面板稳定。

## 5. 服务端数据与本地状态

### 5.1 TanStack Query 负责

- 仓库列表和详情。
- Snapshot 状态。
- 地图节点、边和源码。
- 对话历史。
- 分享报告。

Query Key 必须带上 workspace、repository 和 snapshot：

~~~text
['repository', repositoryId]
['snapshot', repositoryId, snapshotId]
['map', repositoryId, snapshotId, level, filters]
['source', repositoryId, snapshotId, filePath]
['conversation', conversationId]
~~~

### 5.2 Zustand 负责

- 当前地图层级。
- 选中的节点 ID。
- 地图缩放和中心点。
- 打开的源码文件。
- 右侧面板是否折叠。
- 导览当前步骤。

不要把从 API 获取的对象复制进 Zustand。服务端数据只有一个来源。

## 6. API 客户端规则

所有请求通过统一客户端发送：

~~~text
apiClient.get<T>(path, options)
apiClient.post<T>(path, body, options)
apiClient.stream(path, body, onEvent)
~~~

客户端必须自动处理：

- Authorization。
- X-Request-ID。
- JSON 序列化。
- 统一错误转换。
- 401 跳转登录。
- 429 展示重试时间。
- 网络错误和超时。

组件不允许直接调用 fetch。这样可以保证错误、追踪和 API 版本策略一致。

## 7. SSE 使用规则

索引进度和 AI 流式回答都使用 Server-Sent Events。

客户端要求：

- 连接建立后立即显示连接状态。
- 保存最后一个 event_id。
- 断开后指数退避重连，最多 5 次。
- 重连失败则回退为 GET 状态轮询。
- 页面卸载时关闭连接。
- 不把半截 AI 文本当作已完成答案保存。

事件处理器必须按事件类型分发，未知事件只记录日志，不阻塞已知事件。

## 8. 架构地图实现

### 8.1 视图层级

1. package：展示目录或逻辑包。
2. file：展示文件关系。
3. symbol：展示函数、类和方法。

后端返回统一节点模型，前端通过 adapter 转为图组件需要的格式。未来替换 React Flow 或 Cytoscape 时不修改领域组件。

### 8.2 大图策略

- 首次只请求当前层级和视口附近节点。
- 节点超过 500 个时默认聚合。
- 节点超过 2,000 个时禁用逐节点动画。
- 只渲染可见节点，使用虚拟化或图引擎的 viewport culling。
- 布局计算放进 Web Worker。
- 搜索结果可以临时聚焦，不改变后端数据。
- 点击边显示关系类型和证据，不自动打开大量文件。

### 8.3 地图交互

- 单击节点：选中并显示摘要。
- 双击节点：进入下一层级。
- 点击边：显示关系类型。
- 按住 Shift 点击：加入对比集合。
- 键盘 Enter：打开源码。
- 键盘 Escape：关闭详情面板。
- 面包屑：返回上一级地图。
- “聚焦调用链”：只保留指定方向和深度。

## 9. 源码查看器

源码面板必须显示：

- 仓库名。
- Snapshot Commit 的短 SHA。
- 文件路径。
- 语言。
- 行号。
- 当前引用的起止行。
- “在 GitHub 打开”链接（公共仓库）。

源码来自固定 Snapshot，不从默认分支实时拉取。若文件不存在或行号超出范围，显示明确的引用失效状态。

## 10. AI 问答界面

答案卡片分成四层：

1. 结论：一句话回答。
2. 解释：按步骤说明。
3. 证据：文件、符号、行号和关系。
4. 限制：数据不完整、解析失败或模型不确定时的说明。

禁止只展示大段 Markdown 文本。引用必须可点击，并且在源码面板中高亮。

AI 生成期间展示：

- 正在检索哪些模块。
- 已找到多少条证据。
- 当前使用的模型。
- 取消按钮。

## 11. 响应式和可访问性

### 桌面端

- 地图为主区域。
- 左侧仓库导航。
- 右侧节点和源码面板可折叠。

### 平板端

- 导航转为抽屉。
- 源码和节点详情使用底部面板。

### 移动端

- 默认展示列表化架构摘要，而不是强行缩小大图。
- 用户可以查看节点、源码和问答。
- 复杂地图提示“建议使用桌面端”但不阻塞核心功能。

可访问性要求：

- 所有核心功能可用键盘操作。
- 图节点有文本替代列表。
- 颜色不是唯一的关系编码。
- 支持 prefers-reduced-motion。
- 对比度符合 WCAG AA。
- 所有异步状态有 aria-live 提示。

## 12. 前端性能预算

- Landing Page LCP 目标 < 2.5 秒。
- 已缓存仓库总览可交互目标 < 1.5 秒。
- 地图拖拽不因 React 全量重渲染卡顿。
- Monaco 只在用户打开源码时加载。
- 图可视化库使用动态导入。
- 分享页支持静态生成和 CDN 缓存。

每次性能优化必须附 Chrome Performance 记录或 Lighthouse 结果。

## 13. 前端测试

- 组件测试：加载、空态、错误态和键盘操作。
- Hook 测试：SSE 重连、Query 缓存和筛选逻辑。
- 地图测试：节点选择、层级切换、调用链聚焦。
- Snapshot 测试：关键分享页和错误页面。
- E2E：导入示例仓库到生成分享页的完整路径。
- 可访问性扫描：Playwright + axe。

## 14. 开发顺序

1. Design Tokens、布局和路由骨架。
2. 示例仓库总览和静态地图。
3. 真实 API 客户端和索引进度。
4. 源码面板与节点跳转。
5. AI 问答和引用高亮。
6. 导览、分享页和 Open Graph。
7. 性能、可访问性和 E2E。
