# v1.1 前端开发文档：Bundled Demo 入口

状态：已完成验收（2026-08-27）

## 1. 首页入口

首页保持 Server Component，只嵌入一个最小 Client Component 查询现有
`GET /v1/repositories`。组件按保留的 Demo `canonicalUrl` 查找 Repository：

- 找到 Ready Head 时显示“Open bundled demo”，链接必须固定携带 `snapshotId`。
- Seed 尚未完成或 API 暂不可用时显示“Browse repositories”，不得让首页报错或无限 Loading。
- 不在浏览器保存源码、Explanation 或任何凭据。

Client boundary 只覆盖动态链接，避免把整个首页转为 Client Component。实现遵守仓库所用 Next.js 16
本地文档中的 Server/Client Component 与数据请求规则。

## 2. Fixture 身份与能力边界

Web 通过共享 Contract 常量识别保留的 Fixture URL，而不是根据 Repository 名称模糊判断。

- Repository List 显示 `Bundled demo` 标记。
- Explorer 顶部显示“synthetic fixture revision”，不将合成 Commit 链接成真实 GitHub Commit。
- 隐藏或禁用 Reindex 和 Pull Request Impact，因为保留 URL 不是可克隆的外部 Repository。
- Map、Source、Search、Ask、Guardrails、Explanation History、Export 继续使用正常 API，不开后门。

## 3. 状态与可访问性

- Demo 发现状态：`loading`、`ready`、`fallback`。
- Link 文案必须在无图标时仍可理解；加载不使用不可操作的假按钮。
- Demo 标记不能只靠颜色表达。
- API 失败只影响 Demo 快捷入口，不影响公共 URL 导入表单。

## 4. 测试

- 首页找到 Ready Demo 后生成固定 Snapshot URL。
- 没有 Demo、API 失败和 Demo 无 Ready Snapshot 时安全降级。
- Repository List 正确标记 Fixture，普通 Repository 不被误标。
- Explorer 对 Fixture 禁止 Reindex/PR，对普通 Repository 保留原行为。
- Chromium 从首页快捷入口进入 Head，打开 Source、Guardrails 历史和 Base/Head Citation。
