# v1.4 前端开发文档：批量 Review 与适配器设置

## Guardrails 工作台

- 每个 Finding 卡片提供多选框；选中项显示固定工具栏，可统一选择状态并填写一条批量备注。
- “应用批量 Review”只发送 Finding ID、状态和 note，自动生成 `Idempotency-Key`；重复点击不会重复写入。
- 成功后按响应更新当前卡片，并刷新受影响 Finding 的历史；确定性报告状态和 CI 提示保持不变。
- 任一 Finding 无效时显示原子失败提示，不把局部成功误显示为成功；服务端 request ID 可复制。
- Viewer、匿名和 Bundled Demo 保持只读；键盘可操作，复选框/工具栏有 label 与 `aria-busy`。

## Notification 设置

- 创建/编辑 Endpoint 增加 Adapter 选择：Generic Webhook、Slack Incoming Webhook。
- 选择 Slack 时显示仅允许官方 `hooks.slack.com`/`hooks.slack-gov.com` HTTPS 地址的提示；URL 仍由服务端
  最终校验。
- Delivery 表显示适配器快照、事件类型、状态、尝试次数和安全错误摘要。
- Signing Secret 只在创建成功时显示一次；不写 localStorage、URL、日志或埋点。

## 状态与竞态

- 批量请求使用 Snapshot epoch；切换 Snapshot 或 Repository 后丢弃过期响应。
- 批量提交期间保留用户选择和草稿，失败不覆盖草稿；成功只清空已应用项。
- 所有网络访问通过 `apiFetch`，不在浏览器请求 Webhook/Slack。
