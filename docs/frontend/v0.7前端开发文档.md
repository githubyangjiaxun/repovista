# v0.7 前端开发文档：Guardrails Baseline Workspace

状态：已实现并验收（2026-08-23）

## 1. 入口

Repository Workspace 的 Guardrails 页面保留当前 Snapshot 报告，并在顶部增加“Compare with
baseline”选择器。历史列表来自当前 Repository 的 Snapshot API，只展示 `ready` 且不是当前快照的
项；不允许用户手动输入任意跨仓库 UUID。

## 2. 状态

- `idle`：尚未选择基线，显示当前报告。
- `loading`：读取比较 API，保留选择器并显示明确进度。
- `ready`：显示总体 `improved/regressed/unchanged`、新增/解决/持续/变化计数和 Finding 列表。
- `error`：显示 API Request ID 和可重试提示，不清空当前快照报告。

## 3. 双侧证据

每条比较 Finding 显示 base/head 侧路径与行号。点击按钮调用现有 `onOpenSource`，并携带对应
Snapshot ID；源码面板标题必须显示 Commit 短 SHA，防止把基线证据误看成当前源码。

## 4. 可访问性与隐私

- 选择器有可见 label，状态使用 `role=status` 或 `role=alert`。
- 颜色之外同时使用文字和图标表达回归/改善。
- 不在比较卡片渲染源码正文；私有 Snapshot 沿用 credentials 请求。
- 基线切换后清理旧比较结果，避免竞态响应覆盖新选择。

## 5. 测试

组件测试覆盖历史选择、比较请求参数、added/resolved/changed 渲染、双侧证据导航、加载/错误和
切换竞态。浏览器 E2E 至少增加一次基线比较旅程。
