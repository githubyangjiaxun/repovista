# v0.9 前端开发文档：Verified Guardrail Explanations

## 1. 交互入口

在 Guardrails Finding 卡片增加“Explain with AI”按钮。按钮只提交 Finding ID 和可选 Provider/Model，不提交 Finding 内容或源码。

状态：`idle`、`loading`、`ready`、`refused`、`error`。切换 Snapshot 或 Finding 时取消/忽略旧响应，不能让旧解释覆盖新 Snapshot。

## 2. 展示规则

- 顶部显示 `verified explanation`、status、provider/model 和 prompt 版本。
- 独立显示固定 Finding provenance：rule、severity、fingerprint、Commit、显式 `profileFingerprint`、路径和行号；模型 limitations 单独列出。
- AI summary/steps/limitations 与固定 Finding 分区展示，避免把模型文字误认为规则事实。
- 每个 citation 可打开当前 Snapshot 的固定源码行；不生成没有 API 返回的链接。
- `refused` 必须解释“证据不足”，仍显示 Finding 固定事实；Provider 失败显示 request ID。
- Viewer 可查看已有解释；是否能触发新解释由服务端权限和匿名公开规则决定。

## 3. 可访问性与隐私

- 按钮有包含 Finding 标题的可读 aria-label，加载时 `aria-busy`。
- 不在 URL、日志或客户端缓存中写入源码全文、API Token 或模型密钥。
- 私有结果不使用公共缓存；跨 Snapshot 响应必须丢弃。

## 4. 测试

- Finding 卡片显示、加载、成功、refused、错误和固定证据跳转。
- 快速切换 Snapshot 时旧响应不会污染当前卡片。
- Viewer/匿名展示权限和无 Finding 场景。
- Chromium E2E 覆盖一次成功解释和一次无证据拒答。
