# v1.2 前端开发文档：Finding Review 工作流

## 交互

每张 Finding 卡片显示确定性 severity/status 与独立的 Review badge。Review 控件包含状态选择、
2,000 字符以内备注、保存和清除按钮，并显示审阅者与 UTC 时间。状态文案明确说明：Review
metadata 不会改变 deterministic Guardrail status 或 CI 结果。

## 权限

- 未登录用户可读公开 Demo/公开 Snapshot，但控件隐藏或只读。
- 已登录 Viewer 可以读取，不能保存/清除。
- Editor/Owner 和具备写 scope 的 Token 可以修改；API 仍是最终权限边界。
- Demo 页面即使显示控件也必须在 API 层拒绝写入。

## 数据与竞态

- 进入 Snapshot 时并行加载 Report 与 Reviews，按 `findingId` 建立 Map。
- Snapshot/repository 变化时递增 epoch，忽略过期响应。
- 保存期间禁用该卡片按钮，成功后只替换对应 Finding 的 Review；失败保留用户输入并显示
  request ID。
- `unreviewed` 由 DELETE 清除，清除成功后恢复空备注/空 reviewer。

## 可访问性和安全

- 状态选择有显式 label，错误使用 `role=alert`，加载使用 `aria-busy`。
- 备注以纯文本渲染，不使用 `dangerouslySetInnerHTML`。
- 所有 mutation 通过共享 `apiFetch`，自动带 HttpOnly Session 的 credentials 和 CSRF header。
- 不把 review note 放入 URL、localStorage 或分析埋点。
