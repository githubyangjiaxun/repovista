# 页面与交互规范

状态：v0.1 已实现基线

## 1. 产品体验原则

1. 先展示确定性结构，再展示 AI 解释。
2. Commit、文件路径和行号在用户需要验证时始终可见。
3. 长任务展示阶段和进度，刷新页面后可以恢复。
4. 错误必须可行动，并在存在时显示 Request ID。
5. 公共仓库无需登录即可完成完整体验。

## 2. 首页 `/`

目标是让首次访问者在几十秒内理解差异：RepoVista 不是“把整个仓库丢给聊天模型”，而是先构建可验证地图。

主动作接受公共 GitHub URL，点击后带 URL 跳转 `/repositories/new`。首页不直接发起分析，避免用户没有看到边界说明和 Advanced Options。

## 3. 导入页 `/repositories/new`

字段：

- Public GitHub Repository：必填，仅 HTTPS `github.com/owner/repo`。
- Branch, Tag, or Commit：可选，默认远端默认分支。
- Ignored Paths：可选，一行一个仓库相对文件或目录。

提交后：

1. Button 进入 Starting 状态并禁止重复提交。
2. API 返回 202 后跳转 Job 页。
3. URL 保留 Repository、Snapshot 和 Job ID，使刷新可恢复。
4. 校验或 API 失败时留在当前页并展示具体错误。

## 4. Job 页 `/jobs/[jobId]`

显示状态、Phase、百分比以及处理数量。典型 Phase 为 cloning、scanning、parsing、building_graph/persisting、completed。

- succeeded：自动进入 Repository Workspace。
- failed：显示错误代码和消息，可回导入页重试。
- cancelled：明确说明任务已停止。
- SSE 中断：页面轮询 API，不把网络断开误报成任务失败。

## 5. 仓库列表 `/repositories`

展示 Public Workspace 已导入仓库：Owner/Name、最新状态、Commit 和更新时间。没有数据时引导 Analyze Repository。选择条目进入最新 Ready Snapshot。

## 6. Repository Workspace

顶部固定显示：仓库链接、Ref、短 Commit、Indexed 状态、Reindex、Share Tour。

左侧同时承担 Tab 导航和文件过滤。核心 Tab：

### Overview

- Snapshot 文件、符号、关系和语言数。
- 语言分布。
- 包级地图预览。
- “AI optional / evidence first”信任说明。

### Architecture map

- package/file/symbol 三档。
- 文本过滤。
- 节点和边数量。
- 点击节点打开固定范围源码。
- 空结果给出清除过滤或切换级别的建议。

### Ask repository

- 提供可点击示例问题。
- 提交时固定当前 Snapshot。
- Answer 显示 Grounding Status、Provider/Model、Explanation、Limitations。
- 每个 Citation 显示 `path:start-end`，点击打开 Evidence Lines。
- 没有合法证据时显示 Refused，不渲染伪造 Source Link。

### Source panel

- 显示路径、Commit、行号和代码。
- 引用打开时突出显示“Evidence lines x-y”。
- 支持关闭返回当前 Tab，不改变 Snapshot。

## 7. Reindex

Reindex 对同一 Canonical URL 创建新的 Snapshot/Job，并进入 Job 页。旧 Snapshot 和旧 Share Report 保持不变。界面不能暗示“更新原 Snapshot”。

## 8. Share Tour `/share/[slug]`

公开页包含：标题、仓库、Commit、文件/符号统计、Overview、包级地图和最多八个推荐阅读文件。它读取创建时保存的内容，不自动切换到仓库最新 Commit。

v0.1 只允许公共仓库导入，分享页没有登录或私有权限状态。

## 9. 错误文案

优先使用服务端 Message。常见错误的用户动作：

| 类别 | 建议动作 |
|---|---|
| URL/Ref/Path invalid | 修正输入，不自动重试 |
| Repository clone failed | 检查公开性、Ref 和网络后重试 |
| Snapshot not ready | 返回 Job 页或稍后刷新 |
| Rate limited | 等待限制窗口，不重复提交 |
| AI provider failed | 静态地图仍可用；检查 Provider 配置 |
| Request failed | 提供 Request ID 便于定位日志 |

不要向用户直接显示堆栈、数据库错误、模型密钥或 Clone 临时目录。

## 10. 响应式行为

- 桌面：Sidebar、Workspace 和可选 Source Panel 并排。
- 窄屏：内容转为纵向，确保文件和 Citation 仍可操作。
- 图可以缩放和平移，但文本与源码路径不能依赖 Hover 才能发现。
- Loading Skeleton/Spinner 不应引起大幅布局跳动。
