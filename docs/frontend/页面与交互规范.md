# 页面与交互规范

状态：proposal  
适用版本：v0.1

## 1. 产品体验原则

### 先展示事实，再展示解释

地图、文件、符号、Commit 和引用是事实层；AI 总结、导览和自然语言说明是解释层。界面视觉上也要让用户分辨两者。

### 每个异步动作都可解释

不要只显示“加载中”。告诉用户正在 clone、扫描、解析、建立关系还是生成 Embedding。

### 每个错误都给下一步

错误信息必须包含：

- 发生了什么。
- 是否可以重试。
- 用户可以怎么修复。
- 需要时提供 request_id。

## 2. Landing Page

首屏结构：

~~~text
[Logo] RepoVista                 [Docs] [GitHub]

把代码迷宫，变成一张可以探索的地图。
输入 GitHub 仓库，查看架构、调用链和带证据的 AI 导览。

[ GitHub URL 输入框                         ] [开始分析]

[15 秒演示 GIF]

[交互式架构地图] [源码级证据] [Local-first]
~~~

首屏不能要求注册，也不能先展示大段技术愿景。公共示例使用真实开源仓库。

## 3. 导入页面

### 输入

- GitHub HTTPS URL。
- 可选分支或 Commit。
- 可选忽略目录。
- “只在本地分析”开关。

### 校验

- 只允许 HTTPS GitHub URL 和明确允许的 Git Provider。
- 拒绝 URL 中的凭据。
- 显示仓库归属、默认分支和预估规模。
- 超过限制时在提交前说明。

### 进度

~~~text
✓ 已确认仓库
✓ 已获取 Commit a81f2c7
● 正在解析 TypeScript 文件 128 / 342
○ 正在建立调用关系
○ 正在生成搜索索引
~~~

## 4. 仓库总览页

顶部固定显示：

- 仓库名称和来源。
- Snapshot 短 SHA。
- 索引状态。
- “重新索引”按钮。
- “分享报告”按钮。

首屏卡片：

- 项目一句话摘要。
- 入口文件。
- 核心模块。
- 语言分布。
- 代码规模。
- 最近变化。
- 推荐阅读路径。

指标必须标注来源和计算时间，不把估算值伪装成精确事实。

## 5. 架构地图页

布局：

~~~text
┌────────────┬───────────────────────────────┬──────────────┐
│ 仓库导航    │                               │ 节点详情      │
│            │          架构地图              │ 或源码面板    │
│ 总览        │                               │              │
│ 地图        │      [节点]──[节点]           │ 文件路径      │
│ 导览        │          │                    │ Commit       │
│ 问答        │       [节点]                  │ 关系和摘要    │
└────────────┴───────────────────────────────┴──────────────┘
~~~

工具栏：

- 层级切换：包 / 文件 / 符号。
- 搜索节点。
- 关系筛选。
- 聚焦入口。
- 聚焦调用链。
- 显示热区。
- 重置视图。

空态：

- 说明当前层级没有足够数据。
- 提供切换层级或重新索引操作。

## 6. 新人导览页

导览由一组有序步骤组成，每一步包括：

- 标题。
- 为什么重要。
- 地图聚焦节点。
- 推荐阅读文件。
- 源码证据。
- 上一步 / 下一步。

用户可以把导览导出为 Markdown。AI 生成的步骤必须显示“由哪个 Snapshot 生成”。

## 7. AI 问答页

### 提问前

提供示例问题：

- 这个项目从哪里启动？
- 登录请求经过哪些模块？
- 修改这个文件会影响什么？
- 新人应该先读哪些文件？

### 生成中

- 显示检索阶段。
- 允许取消。
- 不清空旧答案。
- 标记当前答案为草稿。

### 生成后

每条引用展示：

~~~text
[src/routes/login.ts:18-32]
AuthService.login()
Commit a81f2c7
~~~

点击引用后：

1. 打开源码。
2. 跳转到行号。
3. 高亮范围。
4. 显示所属符号和关系。

### 不确定时

使用明确措辞：

> 当前索引没有找到足够证据，无法可靠判断。你可以查看相关文件，或换一个更具体的问题。

不显示虚假的百分比置信度。若展示评分，必须说明计算方法。

## 8. 分享页

分享页面向不熟悉 RepoVista 的访客：

- 显示项目名称和固定 Commit。
- 显示一张可缩放的架构图。
- 显示项目摘要和阅读路径。
- 源码引用可打开。
- 清晰标注数据生成时间。
- 私有仓库分享默认关闭。
- 页面底部提供“用自己的仓库试试”入口。

分享页不能暴露访问者不应看到的 workspace、Token、内部日志或模型设置。

## 9. 颜色和状态 Token

不要在业务组件中直接写颜色值，统一使用语义 Token：

| Token | 用途 |
|---|---|
| surface | 页面和卡片背景 |
| surface-raised | 面板和弹窗 |
| text-primary | 主文本 |
| text-secondary | 次文本 |
| accent | 选中和主要操作 |
| relation-import | import 关系 |
| relation-call | call 关系 |
| relation-inherit | 继承关系 |
| status-success | 完成 |
| status-warning | 部分成功 |
| status-danger | 失败 |

关系同时使用线型、箭头和文字，不能只用颜色区分。

## 10. 交互验收清单

- [ ] 无模型配置时地图和源码仍然可用。
- [ ] 刷新页面后索引进度可以恢复。
- [ ] SSE 断线时有可见提示并自动回退。
- [ ] 所有引用可跳转。
- [ ] 分享页固定到 Commit。
- [ ] 键盘可以完成导入、选节点和打开源码。
- [ ] 移动端有列表化替代视图。
- [ ] 错误页面不显示内部堆栈。
