# 页面与交互规范

状态：v0.2 已实现并验收（2026-08-20）

## 1. 产品体验原则

1. 先展示确定性结构，再展示 AI 解释。
2. Commit、Snapshot、文件路径和行号在用户验证时始终可见。
3. 长任务展示阶段、进度和实际 Parsed/Reused 信息，刷新后可以恢复。
4. Full、Incremental 和 Legacy 必须明确区分，不能伪造缺失统计。
5. 错误必须可行动，并在存在时显示 Request ID。
6. 公共仓库无需登录即可完成完整体验。
7. Webhook 是可选自动化；禁用或状态不可用时手工导入仍完整可用。

## 2. 首页 `/`

目标是让首次访问者快速理解：RepoVista 不是把整个仓库直接交给聊天模型，而是先构建固定
Commit 的可验证地图。

主动作接受公共 GitHub URL，点击后带 URL 跳转 `/repositories/new`。首页不直接发起分析，
避免用户没有看到边界说明和 Advanced Options。

能力文案必须准确包含：

- TypeScript、JavaScript、Python 静态分析。
- 不可变 Full/Incremental Snapshot。
- 可选可信 AI。
- Signed GitHub Push 自动更新。
- Markdown/SVG 确定性导出。

不得暗示私有仓库、OAuth、Installation Token、PR 分析或向量检索已经可用。

## 3. 导入页 `/repositories/new`

字段：

- Public GitHub Repository：必填，仅 HTTPS `github.com/owner/repo`。
- Branch, Tag, or Commit：可选，默认远端默认分支。
- Ignored Paths：可选，一行一个仓库相对文件或目录。

提交后：

1. Button 进入 Starting 状态并禁止重复提交。
2. API 返回 202 后跳转 Job 页。
3. URL 保留 Repository、Snapshot 和 Job ID，使刷新可恢复。
4. 校验或 API 失败时留在当前页并展示具体错误和 Request ID。

手工 Reindex 与首次导入使用相同安全入口。

## 4. Job 页 `/jobs/[jobId]`

显示 Status、Phase、百分比、处理数量和 Worker Message。典型 Phase 为 cloning、scanning、
parsing、building_graph/persisting、completed。

- Parsing Message 显示本轮 Parsed 与 Reused 文件数。
- succeeded：进入创建任务时返回的固定 Snapshot。
- failed：显示错误 Code/Message，可回导入页重试。
- cancelled：明确说明任务已停止。
- SSE 中断：页面轮询 Job API，不把网络断开误报成任务失败。
- 页面恢复：先读取当前 Job，再接收新 Event，避免错过终态。

## 5. 仓库列表 `/repositories`

展示 Public Workspace 已导入仓库：Owner/Name、最新状态、Commit 和更新时间。没有数据时引导
Analyze Repository。

选择条目进入列表响应对应的 Ready Snapshot，并在 URL 带 `snapshotId`；页面不会因后续
Reindex 或 Webhook 自动更新而漂移。

## 6. Repository Workspace

URL：

```text
/repositories/:repositoryId?snapshotId=:snapshotId
```

Topbar 固定显示仓库链接、Ref、短 Commit、Full/Incremental、Indexed、Reindex、Share Tour。
左侧承担 Tab 导航和文件过滤，右侧按需打开 Source Panel。

### Overview

- Snapshot 文件、符号、关系和语言统计。
- Update Delta：Scanned、Parsed、Reused、Changed、Deleted、Mode 和 Base。
- GitHub Automation：Server Enabled、Repository Connected、Last Valid Webhook。
- Language Distribution，包含 Python。
- 包级地图预览。
- 固定 Snapshot 的 Download Markdown / Download SVG。
- “AI optional / evidence first”信任说明。

Full 没有兼容基线时显示 `No compatible baseline`。旧 Snapshot 没有增量统计时显示
`Legacy full index` 和不可用计数，不显示伪造的零。

### Architecture map

- package/file/symbol 三档。
- 文本过滤。
- 节点和边数量。
- 点击节点打开固定范围源码。
- 空结果给出清除过滤或切换级别建议。
- `truncated` 时说明当前图被安全限制。

### Ask repository

- 提供可点击示例问题。
- 提交时固定当前 Snapshot。
- Answer 显示 Grounding Status、Provider/Model、Explanation、Limitations。
- 每个 Citation 显示 `path:start-end`，点击打开 Evidence Lines。
- 没有合法证据时显示 Refused，不渲染伪造 Source Link。

### Source panel

- 显示路径、Commit、行号和代码。
- 引用打开时突出显示 Evidence Lines。
- 支持关闭返回当前 Tab，不改变 Snapshot。
- Python 与 TS/JS 使用相同交互，不按语言建立分叉页面。

## 7. Snapshot 导航与 Reindex

Reindex 对同一 Canonical URL 创建新 Snapshot/Job，并进入 Job 页。旧 Snapshot、旧问答和旧
Share Report 保持不变。界面不能暗示“更新原 Snapshot”。

点击 Delta 的 Base 链接会显式进入：

```text
/repositories/:repositoryId?snapshotId=:baseSnapshotId
```

Source、Map、Ask、Share、Export 必须继续使用页面当前 Snapshot，不读取 Repository Latest
替换参数。

## 8. GitHub Automation

Automation Panel 分开表达：

- Server webhook：当前服务是否配置 Secret。
- This repository：是否收到过有效、可入队的 Push。
- Last valid webhook：最近时间或 `Not received`。

Status Endpoint 临时失败时显示“Workspace remains usable”。Webhook Disabled 不是 Repository
错误；Repository Not Connected 也不代表 Server Disabled。

文案必须说明只支持公共仓库、默认分支 Push、HMAC-SHA256。前端不展示 Secret，也不声称已经
完成 GitHub 托管网络回调或私有仓库安装认证。

## 9. Snapshot 导出

Overview 中 Ready Snapshot 才显示下载：

- Markdown：架构报告、Provenance、Delta、语言和阅读路径。
- SVG：包级架构图。

链接固定当前 `snapshot.id`，在新上下文打开时使用 `noopener noreferrer`。浏览器负责下载，
React 不缓存正文。下载失败不能让 Workspace 丢失现有地图、源码或问答状态。

导出是确定性静态事实，不添加 AI 生成段落。相同 Snapshot/Level 的正文和 ETag 应稳定。

## 10. Share Tour `/share/[slug]`

公开页包含标题、仓库、Commit、文件/符号统计、Overview、包级地图和最多八个推荐阅读文件。
它读取创建时保存的内容，不自动切换到仓库最新 Commit。重复创建报告使用随机尾部 Slug。

当前只允许公共仓库导入，分享页没有登录或私有权限状态。

## 11. 错误文案

优先使用服务端 Message。常见错误的用户动作：

| 类别 | 建议动作 |
|---|---|
| URL/Ref/Path invalid | 修正输入，不自动重试 |
| Repository clone failed | 检查公开性、Ref 和网络后重试 |
| Snapshot not ready | 返回 Job 页或稍后刷新 |
| Rate limited | 等待限制窗口，不重复提交 |
| AI provider failed | 静态地图仍可用；检查 Provider 配置 |
| Export failed | 保留当前页面，稍后重试并提供 Request ID |
| Integration unavailable | 继续手工导入/浏览，稍后刷新状态 |
| Request failed | 提供 Request ID 便于定位日志 |

不要显示 Stack、数据库错误、模型/Webhook Secret 或 Clone 临时目录。

## 12. 响应式与可访问性

- 桌面：Sidebar、Workspace 和可选 Source Panel 并排。
- 窄屏：内容转为纵向，文件、下载和 Citation 仍可操作。
- 图可缩放和平移，但文本和源码路径不能依赖 Hover 才能发现。
- 图不是唯一入口，文件列表与 Evidence Link 提供等价源码路径。
- Delta/Automation 状态不能只依赖颜色。
- Loading Skeleton/Spinner 不应引起大幅布局跳动。
