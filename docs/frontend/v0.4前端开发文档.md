# v0.4 前端开发文档

状态：已实现并验收（2026-08-20）

## 1. 产品目标

前端要让用户一眼区分“普通代码搜索”“真实语义检索”和“AI 回答”。页面不允许只放一个
搜索框后把所有结果统称为 AI。每个能力都必须展示来源与降级状态。

v0.4 的两个主要展示面：

1. Repository Workspace 内的 Evidence Retrieval Lab。
2. 可公开分享、无需登录的 Architecture Story v2。

## 2. Repository Workspace 信息架构

主导航调整为：

```text
Overview | Architecture map | Search evidence | Ask repository
```

`Search evidence` 是独立 Tab。Ask 可以链接到 Search Trace，但不能隐藏或重算结果。

### Retrieval Lab 布局

```text
┌ Query + Search ───────────────────────────────┐
│ [text] [symbol] [semantic] [hybrid]  Limit   │
└───────────────────────────────────────────────┘
┌ Semantic index status ───────────────────────┐
│ Provider / Model / Dimension / Chunk progress│
│ [Build index] [Retry] [View job]             │
└───────────────────────────────────────────────┘
┌ Results ──────────────────────┬ Trace ────────┐
│ Path · symbol · lines · code  │ used channels│
│ fusion score + channel chips  │ degrade reason│
│ ...                           │ profile facts │
└───────────────────────────────┴───────────────┘
```

窄屏时 Trace 移到 Results 上方，Source Drawer 改为页面内 Dialog/Section，不能让横向滚动成为唯一
操作方式。

## 3. 状态模型

组件维护：

```ts
type RetrievalMode = "text" | "symbol" | "semantic" | "hybrid";

interface RetrievalLabState {
  query: string;
  submittedQuery: string;
  mode: RetrievalMode;
  limit: number;
  status: RetrievalStatus | null;
  result: SearchResult | null;
  searching: boolean;
  building: boolean;
  error: string | null;
}
```

- 每次 Search 使用 `AbortController` 或 Request Generation ID；旧响应不能覆盖新 Query。
- Snapshot 切换后清空 Search/Trace，并重新加载 Retrieval Status。
- Build Index 返回 Job 后跳转现有 Job 页面或在卡片中轮询；Job 终态后刷新 Status。
- Query 只在提交后进入 URL `?tab=search&q=&mode=`，便于复制与浏览器后退；不为每次键入更新。

## 4. Mode 与透明降级

- `text`：说明“Full-text + path”；隐藏 Semantic Profile 并不等于不可见，Status 卡仍存在。
- `symbol`：说明“Symbol/name/path exact + fuzzy”。
- `semantic`：Index 未 Ready 时按钮可选，但提交后显示明确 Build CTA；不得偷偷切 Hybrid/Text。
- `hybrid`：结果页展示实际 `usedChannels`。如果 Trace degraded，在结果上方显示非阻塞警告和
  `index_not_ready/provider_unavailable/...` 的人类说明。
- 每个 Channel Chip 使用文字+图标，不能只靠颜色；Score 保留 4 位小数，Rank 显示整数。

## 5. Result Card

每条 Search Hit 包含：

- `path:start-end`，Symbol（如有），Snapshot 短 SHA；
- 受限源码摘要，默认最多约 14 行，可展开；
- Fusion Score；
- 每个参与通道：`Text #2 · 0.1731`、`Semantic #1 · 0.8124`；
- “Open source”按钮，调用现有 `openSource(path,start,end)`；
- Commit 固定提示和 Content Hash 的短形式。

不能使用 `dangerouslySetInnerHTML` 渲染源码或 Story Quote。Query Highlight 使用 React 文本节点
拆分，必须正确处理正则特殊字符和 Unicode。

## 6. Semantic Index 状态卡

状态：

- `provider_disabled`：显示配置示例，Build disabled；
- `index_missing`：Provider/Model 已配置，显示 Build；
- `queued/running`：进度条、embedded/total、当前 phase、Job link；
- `ready`：Provider/Model/Dimensions、Chunk Count、Ready 标识；
- `failed/cancelled`：稳定 Error、Retryable、Retry 按钮；
- `model_mismatch`：显示已有 Profile 与当前配置不同，允许为当前配置新建 Index。

上游 Endpoint 和 API Key 永不显示。

## 7. Ask 升级

- Answer Card 增加“Retrieval used”摘要：通道、是否降级、Profile Model、Evidence 数量。
- Citation Card 可显示对应 Search Hit 的 Channel Signal，但不改变 Citation 验证语义。
- Ask 失败时保留问题；Provider Answer 失败与 Retrieval 失败分别给出说明。
- Fake Provider 明确标注“deterministic evidence summarizer”，不能叫 LLM。

## 8. Architecture Story v2

Story Page 区块顺序：

1. Hero：Owner/Repo、Headline、固定 Commit、生成日期。
2. Metric Strip：Files、Symbols、Edges、Languages。
3. “System shape”：Package Map 与图例。
4. “Key modules”：最多 6 张卡，显示 Why selected、Importance、Connections、Representative Path。
5. “Start here”：编号阅读路线与理由。
6. “Evidence highlights”：固定源码 Quote、Symbol、Line Range、Hash。
7. Provenance：Snapshot ID、Commit、Parser、Story Algorithm、可选 Embedding Provider/Model。
8. CTA：Map your repository。

Story 不加载 Provider、不重新 Search、不依赖创建者本机状态。复制链接后页面内容必须稳定。

### v1 兼容

`ShareReportView` 使用 Discriminated Union：

- `content.version === 2` 渲染 Story；
- 没有 version 的旧记录作为 v1 Tour 渲染现有 Map + Reading Path。

## 9. 可访问性

- Mode 使用可聚焦按钮组并设置 `aria-pressed` 或 Tab 语义。
- Search Status 使用 `aria-live=polite`；错误使用 `role=alert`。
- Progress 有可读百分比、已完成/总数，不只显示动画。
- Result Card、Story Module、Evidence Button 保持可见 Focus Ring。
- 图之外提供模块卡和文本摘要，不能要求屏幕阅读器理解 Canvas/SVG。
- 色彩对比至少满足 WCAG AA；Degraded/Failed 不只使用黄色/红色。

## 10. Next.js 16 约束

实现前必须阅读 `apps/web/node_modules/next/dist/docs/` 中与 App Router、Client Components、
Search Params、Data Fetching 和 Testing 相关的当前版本文档。保持：

- Page Server Component 只解析 params/searchParams；交互放 Client Component。
- 不在 Render 中读取浏览器 API。
- `useEffect` 的网络请求具备 Cleanup。
- 外部 API 仍经 `apiFetch`；下载端点除外。
- 不引入已被 Next 16 废弃的 Router/API。

## 11. 自动化测试

Vitest/Testing Library：

- Mode 切换和 Search Request 参数；
- 旧请求不会覆盖新请求；
- Semantic 未 Ready CTA；
- Hybrid degraded Trace；
- Ready/Running/Failed Index 卡；
- Result Open Source Range；
- Story v1/v2 分支、Quote 安全渲染和 Provenance。

Playwright：

1. 加载 Repository → Search Tab → Text Result → Source Drawer。
2. Build Embedding → Job Progress → Ready Status → Semantic/Hybrid Trace。
3. Provider 不可用 → Hybrid degraded 仍返回结果 → Semantic-only 错误。
4. Ask 显示 Retrieval Summary 与固定 Citation。
5. 生成 Story → 新 Tab → Map/Modules/Reading/Evidence/Provenance 完整。
