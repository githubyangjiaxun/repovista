# RepoVista v0.5 前端开发文档

状态：开发中（2026-08-20）

## 1. 产品目标

v0.5 前端要让用户始终知道三件事：“我是谁”、“我正在哪个 Workspace”、“这个仓库/分享是否私有”。
私有仓库不能只靠一个小锁图标暗示，关键操作必须使用文字说明授权范围和分享后果。

公开仓库匿名体验仍是首页主路径，登录不得成为查看公开 Demo 的强制门槛。

## 2. Next.js 16 实现约束

修改 Web 代码前必须完整阅读当前安装版本 `apps/web/node_modules/next/dist/docs/` 中的：

- App Router / Layout / Page。
- Server 与 Client Components。
- `cookies`、Redirects 和 External URL Navigation。
- Data Fetching、CORS Credentials 和 Environment Variables。
- Async `params/searchParams`、Testing 和 Error Handling。

原则：

- Auth State 交互放 Client Provider，Page 仍优先作 Server Component。
- 不将 Session Token 读到 JavaScript；Browser 只能读 CSRF Cookie。
- `apiFetch` 默认 `credentials: "include"`，Mutation 自动添加 CSRF Header。
- 不在 Server Component 中把用户 Cookie 直接转发到不受信任 Origin。
- Auth/Workspace 变化使用显式 State Refresh，不依赖整页面隐式全局变量。

## 3. 全局 Auth State

```ts
interface AuthState {
  status: "loading" | "anonymous" | "authenticated" | "disabled" | "error";
  user: AuthUser | null;
  workspace: WorkspaceSummary | null;
  workspaces: WorkspaceSummary[];
  csrfToken: string | null;
  capabilities: {
    githubLogin: boolean;
    githubApp: boolean;
    privateRepositories: boolean;
  };
}
```

`AuthProvider` 在首次 mount 请求 `/v1/auth/session`。未配置 Auth 与已配置但未登录是两种明确状态：

- disabled：显示“Public mode”，不显示无效 Login CTA。
- anonymous：显示“Sign in with GitHub”。
- authenticated：显示 Avatar/Login/Workspace Switcher/Settings/Logout。

## 4. Header 与 Workspace Switcher

Desktop：

```text
RepoVista | Repositories | Docs        [Workspace ▾] [Avatar ▾]
```

Mobile：Workspace 和 Account 放入同一 Menu，但当前 Workspace 名称仍在 Header 可见。

- Workspace Switch 调用 `PUT /v1/auth/session/workspace`。
- 成功后清除 Repository/Job/Retrieval 的 Client Cache，并导航到 `/repositories`。
- Viewer 不显示 Import Button；直接输入 URL 访问写页面时显示权限说明。

## 5. Auth 页面

### `/auth/error`

只显示稳定错误码的人类文案，不显示 OAuth Code/State/GitHub Raw Error。提供重试登录和回到 Public Mode。

### Login CTA

使用正常 `<a href="API_ORIGIN/v1/auth/github/start?returnTo=...">`顶层导航，不用 `fetch` 启动 OAuth。`returnTo` 仅传递站内相对路径。

## 6. Settings 信息架构

`/settings` 使用可键盘访问的 Tab/Section：

1. **Workspace**：名称、Slug、当前 Role，新建 Workspace。
2. **Members**：Avatar/Login/Role/Joined At，Owner 可添加已登录 GitHub Login、更改 Role、移除。
3. **GitHub App**：配置状态、Install Button、Installation Account/Selection/Suspended State、可访问 Repository Count。
4. **API tokens**：Name/Prefix/Scopes/Created/Last Used/Expires/Revoke，原始 Token 仅创建后一次 Dialog显示。
5. **Audit log**：v0.5 只读最近 100 条，显示操作、Actor、Resource 和时间，不显示敏感 Metadata。

非 Owner 仍可查看 Workspace 和 Members，但所有管理控件 Disabled 并有说明。

## 7. Import Repository

页面顶部使用两个显式模式：

```text
[ Public GitHub URL ] [ Installed repositories ]
```

### Public URL

- Anonymous：保持 v0.4 行为，写入 Public Workspace，限额。
- Authenticated Editor/Owner：写入 Active Workspace。
- Viewer：只读权限提示。

### Installed Repositories

- 只对 Authenticated Editor/Owner 展示。
- Installation Select + Search + Pagination；列表项显示 Owner/Name、Private/Public、Default Branch、是否已导入。
- 安装为 Selected Repositories 且目标不在列表时，给出“Manage on GitHub”，不诱导用户提供 PAT。
- Submit 发送 Canonical URL + Installation ID，不发送 Clone Token。

## 8. Repository 与 Share 可见性

- Repository Card/Header 使用 `Private repository` / `Public repository` 文字 Chip + Icon。
- Private Repository 的 Export Link 不能用纯 `<a>` 无凭据下载；使用 Authenticated Fetch + Blob Download。
- Share Dialog 在 Private Context 中将 Visibility 锁定为 Private，并说明“Only members of this workspace can open it”。
- Private Share Page 未登录时显示通用 Not Found，不暴露 Repository 名称。
- Public Share 保留当前可索引的 Stable Story；Private Share 设置 `robots: noindex, nofollow`。

## 9. API Client

`apiFetch` 统一行为：

```ts
fetch(url, {
  credentials: "include",
  headers: {
    Accept: "application/json",
    ...(body ? { "Content-Type": "application/json" } : {}),
    ...(isMutation && csrf ? { "X-RepoVista-CSRF": csrf } : {}),
  },
});
```

- CSRF 来自 Auth Provider State/可读 Cookie，不从 Local Storage 伪造。
- 401 只将 Auth State 变为 Anonymous，不自动循环重试 Mutation。
- 403 保留服务端稳定文案；404 使用通用不存在页面。
- Workspace 切换后不保留前 Workspace 的资源数据。

## 10. 可访问性与安全 UI

- Workspace/Account Menu 支持 Escape、Arrow Key、Focus Return。
- Role/Visibility/Installation Status 不只用颜色表达。
- Raw API Token Dialog 有明确 `aria-describedby`，Copy 后不自动关闭。
- 删除 Member、Revoke Token、Disconnect Installation 要求确认，并显示具体对象。
- 不把 Token 放入 Toast、URL、Telemetry 或 Error Boundary。
- GitHub Login/Install 是外部导航，必须有对用户可见的说明。

## 11. 测试

Vitest/Testing Library：

- Auth disabled/anonymous/authenticated/error 四种 Header。
- Workspace Switch 请求、Cache Clear 和 Viewer 禁用写操作。
- `apiFetch` credentials/CSRF/401/403/404，确保不泄露 Token。
- Public URL/Installed Repository 切换、分页、Private Chip、已导入状态。
- GitHub Installation Suspended/Selected/All 状态。
- Token 创建只显示一次、Revoke 后消失。
- Private Share Visibility 无法选 Public。

Playwright：

1. Anonymous 导入 Public Repository，公开流程不回归。
2. GitHub Login Mock -> Personal Workspace -> Logout -> Session 失效。
3. Owner 连接 Installation -> 列出 Private Repository -> Import -> Job -> Explorer。
4. Viewer 可读 Private Repository 但无法 Import/Rerun/Share。
5. 切换 Workspace 后旧 Repository URL 返回 Not Found。
6. Private Share 成员可见，Logout 后 Not Found；Public Share 仍可见。
7. Create API Token -> CLI-style Bearer Request -> Revoke -> 401。
