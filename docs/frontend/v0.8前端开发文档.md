# v0.8 前端开发文档：Policy Profile 工作台

## 1. Guardrails 页面

- 在报告标题附近显示 `profileKey vN`、algorithm 和 fingerprint 前 12 位。
- 显示当前 Snapshot 的快照策略，明确文案：“只影响新 Snapshot”。
- 列出当前 Workspace 可见的所有 profile 版本，不把不同 Workspace 的 ID 混入选项。
- 有写权限时提供“应用到后续 Snapshot”按钮；viewer 只读。

## 2. 状态与竞态

- profile 列表：独立 loading/error 状态，不阻塞已有 guardrail 报告。
- 绑定操作：防重复提交，在成功响应返回后用服务端返回的 profile 更新本地 repository 状态。
- 如果用户在操作期间切换 Snapshot，异步响应不得覆盖新 Snapshot 的状态。
- 后端返回 409 时保留 Request ID，并提示策略兼容性而非网络故障。

## 3. 可访问性与安全

- 所有快照源码仍使用固定 Commit 证据链接。
- profile 描述不允许渲染 HTML；React 默认文本输出。
- 不在界面上提供任意规则脚本、prompt 或 model 参数。

## 4. 测试

- 显示内置 default 和自定义多个版本。
- 切换只影响后续 Snapshot 提示与 API 请求。
- viewer 不显示或禁用绑定操作。
- profile 请求竞态不会覆盖当前 Snapshot 报告。
