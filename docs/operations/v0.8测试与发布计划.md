# v0.8 测试与发布计划：Policy Profiles

## 1. 门禁

- `pnpm openapi:check`
- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`
- `pnpm test:e2e`
- `pnpm benchmark`
- `docker compose config --quiet`
- `docker compose build api worker web`
- `git diff --check`
- `git fsck --full`

## 2. 必测行为

### Contracts/Guardrails

- 阈值输入过滤、fingerprint 稳定、策略 provenance 不包含源码。
- 旧报告与新报告的默认策略兼容。
- 不同 profile fingerprint 的比较返回不兼容。

### API/Database

- 完全相同的最新 profile 请求保持版本不变并幂等复用；同 key 的内容变化才自增版本。
- 跨 Workspace profile 返回 404，viewer 创建/绑定返回 403。
- 仓库绑定后新 Snapshot 捕获新 profile，旧 Snapshot 报告不变。
- 私有 profile 和关联报告使用 `private, no-store`。

### CLI/Web

- CLI profiles 列表、创建版本、绑定仓库的摘要/结构化输出。
- Web 展示策略版本和指纹，成功切换后防竞态。
- 基线比较显示策略不兼容错误与 Request ID。

## 3. 外部联调边界

真实 GitHub Private Fixture 和真实 PostgreSQL 若未提供环境，必须明确记录 Skip/待联调，不得冒充通过。发布记录需包含数据库集成测试实际结果、提交 SHA、远端 `main` SHA 与 Private 状态。
