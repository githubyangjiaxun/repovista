## 1. 自动化测试矩阵

- Git Scanner：`.py -> python`。
- Python Parser：声明、Decorator、Import、Call、Inheritance、行号和稳定键。
- Graph：Python 相对/绝对 Import Linking；歧义目标保持 unresolved。
- Incremental Planner：full、no-op、changed、added、deleted、language changed、parser incompatible。
- Webhook Signature：valid、invalid、malformed、missing、Unicode/raw bytes。
- Exporter：确定性、Markdown Provenance、XML escaping、node truncation。

- 0001 → 0002 Migration 与重复执行。

## 3. 真实仓库验收

至少两组：

1. 一个小型 TS/JS Repository，证明 v0.1 回归。
2. 一个小型公共 Python Repository，选择相邻两个真实 Commit：
   - 先索引旧 Commit，得到 Full Snapshot。
   - 再索引新 Commit，得到 Incremental Snapshot。
   - 核对 Changed/Reused/Parsed/Deleted 计数和实际 Git Diff。
   - 验证 Python Symbol/Import Graph、Source、Search、Fake Ask。

验收记录 Repository URL、两个完整 SHA、Parser Version 和输出计数。不要在对外 README 声称未经记录的性能倍数。

## 4. Webhook 验收

在真实 Compose API 上用固定 Fixture 和 HMAC 发送：

- Ping。
- 默认分支 Public Push。
- 完全相同 Delivery 重放。
- 同 Delivery 不同 Body。
- 错误签名。
- 非默认分支和删除 Push。

验证数据库只出现一个自动 Snapshot/Job，且 Worker 最终完成该 Commit。此测试不需要真的创建公网 GitHub Webhook，也不能声称已验证 GitHub 托管网络回调。

## 5. Export 验收

- `curl --fail --remote-header-name` 下载 Markdown/SVG。
- Markdown 中完整 Commit、Snapshot ID、Parser Version 正确。
- SVG 通过 XML Parser，并在 Chromium 打开无 Console/Page Error。
- 仓库名、路径等包含 `& < > \" '` 的 Unit Fixture 不破坏 XML。
- 重复请求相同 Snapshot/Level 得到相同主体内容。
