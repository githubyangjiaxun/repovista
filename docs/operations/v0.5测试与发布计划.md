# RepoVista v0.5 测试与发布计划

状态：自动化门禁完成；真实 GitHub Private Fixture 待外部联调（2026-08-22）

## 1. 风险优先级

v0.5 的主要风险不是页面是否能打开，而是私有源码是否可被跨 Workspace、通过 Share、通过 Job/Snapshot
子资源、通过 Export/SSE 或通过 Log/Error 侧漏。测试按以下优先级执行：

1. Authorization Isolation。
2. Credential Non-disclosure。
3. OAuth/Session/CSRF Replay Resistance。
4. Installation/Repository Binding。
5. Public v0.4 Regression。
6. UI/CLI Usability 与部署完整性。

## 2. 纯函数和 Contract

- Cookie Parse/Serialize；重复 Cookie、非法编码、超长 Token。
- SHA-256 Hash、Timing-safe Compare、Token Prefix，原值不出现在 Serialized Record。
- Return-To 只允许站内绝对路径，拒绝 `//host`、backslash、encoded protocol。
- Role/Scope 矩阵，Owner/Editor/Viewer 不存在权限倒置。
- App JWT Header/Claims/Clock Skew/Expiry，Private Key 非法时稳定失败。
- GitHub OAuth/Installation/Repository/PR Schema 正反例、分页上限、非安全 URL。
- Token Cache 命中、提前过期、并发 Mint 收敛为一次请求。
- Clone AskPass 清理、错误红洗、Token 不进 Argv/Remote URL。

## 3. PostgreSQL Integration

### Migration

- 空库完整应用 0001..0005；v0.4 备份应用 0005；二次执行 no-op。
- 复合 Membership FK、Identity/Installation/Provider Repo Unique、Private Repository Check。
- Installation Delete 对 Repository 是 Set Null 而不是删除历史。

### Auth

- OAuth State 原子消费；并发回调只有一个成功。
- 首次/重复登录 User/Identity/Personal Workspace 幂等。
- GitHub Login 变更后 Identity 以 Provider User ID 跟随更新。
- Session Expiry/Revocation/Disabled User/Removed Membership 立即失效。
- API Token Scope/Expiry/Revocation/Owner 移除和 Last-used 节流。

### Workspace Isolation

构造 Public Workspace、Workspace A、Workspace B，每个包含 Repository/Snapshot/Job/Analysis/Share。对每个 Store Access Query 验证：

- Anonymous 只看 Public/Public。
- A Viewer 看 A + Public/Public，不看 B。
- B Editor 不能通过 A 的 Snapshot/Job/Analysis UUID 读取。
- Public Repository 若存在 Private Workspace A，Anonymous/B 仍不可见。
- Private Share 只跟随 Repository Workspace，不因 Slug 可知而放行。

## 4. API 安全矩阵

对每个原有路由至少覆盖 Anonymous/A Viewer/A Editor/B Owner：

- Repository List/Detail/Snapshots。
- Snapshot Detail/Map/Files/Source/Symbol/Search/Retrieval/Export。
- Job Detail/SSE/Cancel。
- PR Create/Detail/Impact/SSE/Rerun。
- Embedding Create、Ask、Share Create/Read。

额外测试：

- Cookie + 无 Origin/错 Origin/无 CSRF/错 CSRF -> 403。
- Bearer Mutation 不带 CSRF 仍可按 Scope 工作。
- Cookie 与 Bearer 同时出现时拒绝 Ambiguous Credential，不猜测优先级。
- 无权 Resource 返回 404，已知 Workspace 中的 Role/Scope 不足返回 403。
- Rate Limit Key 已登录时使用 User/Workspace，Anonymous 才使用 IP。

## 5. GitHub App Fixture

用本地 Mock HTTP Server 覆盖：

- OAuth Success、Denied、Bad Code、Missing Verified Email、Rate Limit、Timeout、Invalid JSON。
- App JWT `GET /app/installations/:id`、Token Mint，401/403/404/429/5xx。
- Installation Repository 多页、selected/all、private/public、renamed repo。
- PR Metadata/Files 通过 Installation Token 读取 Private Repo。
- Authorization Header 只出现在 Mock 收到的 HTTP Header，不出现在 Error Snapshot。

Webhook：

- 正确/错误 Signature，Delivery 幂等与 Payload Hash Conflict。
- Private Push 的 Installation ID/Provider Repo ID/Owner/Name 全部匹配才 Enqueue。
- Installation 跨 Workspace、Suspended、Removed Repository、未导入 Private Repo 均 Ignore。
- Event Payload 不会把私有源码、Token 或 Webhook Secret 写入 Delivery/Audit。

## 6. Worker 与 Git

- Public Job 不 Mint Token，保持 v0.4 Clone。
- Private Job 在 Clone 前 Mint，成功、Git Failure、Timeout、Cancel、Lease Lost 都清理 AskPass。
- 同 Installation 并发 Job 共享内存 Token Future/Cache，不将 Token 写入 Job Event。
- Token 在 Clone 前已过期时重新 Mint；GitHub 401 只允许清缓存后重试一次。
- 错误红洗 Fixture 将真 Token 嵌入 stdout/stderr/URL，最终稳定 Error 不得包含它。

## 7. Web 与 CLI

- Web 按[ v0.5 前端文档](../frontend/v0.5前端开发文档.md)的 Vitest/Playwright 矩阵验收。
- CLI Config 文件权限必须为 User-only；测试不读写真实 Home，使用临时路径。
- `auth login` 不接受命令行 `--token` 以避免 Shell History；从 stdin Hidden Prompt 或 `REPOVISTA_TOKEN` 读取。
- JSON Output 不输出 Raw Token，只有 Token Create API 的立即响应可出现原值。
- Revoke 后已保存 CLI Token 获得稳定 401 和重新登录指引。

## 9. 真实 GitHub 验收

使用专用测试 GitHub App 和一个不包含真实密码/客户数据的 Private Fixture Repository：

1. 配置 Callback/Setup/Webhook URL 与最小权限 `Contents: Read-only`、`Metadata: Read-only`、`Pull requests: Read-only`。
2. GitHub Login，记录应用 ID/Installation ID（不记录 Secret）。
3. 只安装到 Selected Fixture Repository，确认其他 Private Repo 不在列表。
4. Import -> Clone -> Index -> Search -> Map -> Ask -> Private Story。
5. 触发 Push，新 Incremental Snapshot 到 Ready；取消一次 Job 验证清理。
6. 分析一个 Private PR，确认 Fixed Commit Evidence。
7. 将 Installation Suspend/Remove Repository，新 Job 失败为稳定 Credential Error，历史数据仍可对成员读取。
8. Logout/Viewer/Other Workspace/Anonymous 尝试所有直接 URL，均不可见。
9. Reinstall/Restore，后续更新恢复。

验收记录只保存 Repository Fixture 名称、Commit SHA、Job/Snapshot ID、耗时和结果，不保存任何凭据。

```bash

```

额外门禁：

- 使用 `rg` 扫描所有 Canary Secret 和常见 Token Pattern。
- 检查进程 Argv 与 Git Remote URL 不包含 Installation Token。
- Production Config 缺少任一 GitHub Auth/App Secret 时能力明确 Disabled，不进入半可用状态。
- CORS 只允许精确 `WEB_ORIGIN` 且 Credentials=true，不返回 `*`。
- Docker Worker/API 均通过 Secret Environment/File 获取 Private Key，镜像 Layer 不包含 PEM。
