状态：已执行并验收（2026-08-25）

## 2. 必测场景

- `subjectKey` 对六类规则的稳定计算，与 Snapshot baseline 配对规则一致。
- Migration 0001～0008、v0.9 行回填、非空/长度约束和历史索引。
- 同 Repository 同逻辑 Finding 的多 Snapshot 历史，稳定倒序和 cursor 分页。
- 相同 `createdAt` 的记录无重复、无遗漏。
- 当前 Finding 不存在、非 Ready Snapshot、非法 cursor、跨 Workspace/Repository。
- 比较同一记录、缺失记录、不同 `subjectKey` 和合法两版本。
- 比较结果对 provenance/Finding/Answer 每个字段的 same/changed 判定。
- 证明历史与比较不会调用 Provider，也不产生写入或 audit create 事件。
- CLI 人类输出、JSON Contract、参数校验和错误 Request ID。
- Web 按需加载、空状态、分页、竞态、Viewer、比较和双 Snapshot Citation。
- Chromium 完整历史/比较旅程。

## 3. 发布与安全审计

- 所有 package、CLI User-Agent、SARIF 默认工具版本和 OpenAPI 升为 `1.0.0`。
- 主仓库只提交 RepoVista 根项目；`extensions/vscode` 独立 Git 仓库保持忽略。
- 扫描常见 Token、Private Key、密码和 `.env`，不输出或保存用户凭据。
- 功能与文档分两次 Git 提交，推送私有 `main`，核对本地/远端 SHA、默认分支、Private 状态和
  GitHub Actions。

## 4. 真实验收边界

确定性 Fake Provider 与持久化 Fixture 足以验证历史/比较链路，但不构成真实外部模型质量证明。
发布记录必须区分自动化结构比较、真实模型内容质量和私有 GitHub Fixture。
