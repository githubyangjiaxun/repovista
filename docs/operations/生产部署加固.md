# RepoVista 生产部署加固

状态：v1.3 最小基线（2026-08-28）

默认 `compose.yaml` 面向本地评估：包含固定开发数据库密码、Host 端口和 Bundled Demo。它不能直接
暴露到互联网。生产最小基线使用覆盖层：

```bash
export POSTGRES_PASSWORD='<secret-manager-value>'
export WEB_ORIGIN='https://repovista.example.com'
export API_ORIGIN='https://api.repovista.example.com'
export NOTIFICATION_SIGNING_SECRET='<secret-manager-value>'

docker compose -f compose.yaml -f compose.hardened.yaml config --quiet
docker compose -f compose.yaml -f compose.hardened.yaml up --build -d --wait
```

不要把上述变量写入 Git。Shell History 也不是 Secret Manager；真实部署应由平台 Secret、受控 CI 或
编排器注入。

## Overlay 提供的边界

- `APP_ENV=production`、HTTPS Origin、Secure Cookie。
- 显式数据库密码，PostgreSQL 不发布 Host Port。
- Bundled Demo Seed 被关闭，Worker 不依赖 Seeder。
- API/Worker/Web 使用只读文件系统、`no-new-privileges` 和 Drop Capabilities。
- 必需临时目录通过有界 `tmpfs` 开放。
- Notification Worker 使用有界超时、禁止重定向、DNS/IP SSRF 检查和有限重试；部署平台仍应为
  Webhook 出口设置网络 Allowlist，避免把应用当作任意 URL 代理。

## 仍需部署平台负责

- TLS 终止、HSTS、请求体/速率限制、DDoS/WAF 和可信反向代理头。
- API/PostgreSQL 私有网络、出口 Allowlist、主机和 Container Runtime 补丁。
- GitHub OAuth/App、Webhook、模型和数据库凭据的 Secret Manager、轮换和审计。
- PostgreSQL 加密备份、恢复演练、容量、连接上限、Vacuum 和可用性。
- 日志汇聚与脱敏；禁止收集完整源码、Authorization、Cookie、PEM 或模型 Key。
- Worker 资源限制和租户隔离。RepoVista 不执行导入代码，但当前 Worker 仍不是完整恶意多租户沙箱。

## 发布顺序

1. 备份并验证恢复点。
2. 用新 API Image 执行 Forward Migration；不要修改已发布 SQL。
3. 等 API Ready，再滚动 Worker/Web。
4. 检查 `GET /v1/health/ready`、匿名公开读取和授权私有路径。
5. 确认 `DEMO_SEED_ENABLED=false`，且 PostgreSQL 没有 Host Port。

回滚应用版本不能回滚已应用 Schema。若旧版本不兼容新 Schema，应前滚修复，而不是删除 Migration
或还原生产数据库。
