## 2. Fixture 与 Seed 测试

- 两版 manifest hash 在文件枚举顺序变化时稳定，内容变化时改变。
- Scanner 只读取允许的普通文件，拒绝 symlink，Fixture 不含 Secret/Private Key。
- TS/Python/Go 都产生真实 Symbol；TS package cycle 能稳定产生同逻辑 Finding。
- Base Full；Head Incremental 且统计包含预期 changed/reused/parsed/deleted。
- 精确 Claim 面前存在更早的普通 queued Job 时，Seeder 仍只领取目标 Job。
- 重复 Seed 后 Repository、目标 Snapshot、Succeeded Job、Explanation 数量不增加。
- 两条 Explanation 的 Citation 路径、行号、Commit、Snapshot 和内容哈希均有效。

## 3. Demo Smoke

Smoke Script 只使用公开 API，并验证：

1. Readiness 为 200。
2. 保留 Demo Repository 存在，latest 指向 Head Ready Snapshot。
3. Snapshot 列表包含 Base/Head，Head `indexMode=incremental` 且 `baseSnapshotId` 正确。
4. Map 有 Node/Edge；Source 返回固定 Commit；Text Search 命中已知符号。
5. Guardrails 包含预期 cycle Finding。
6. 从 Head Finding 查询历史得到 Base/Head 两条 Fake Explanation。
7. 比较两条记录成功，且响应不评价“更好/更差”。

Smoke 不调用 GitHub、Ollama 或 OpenAI-compatible Endpoint。

## 4. Hardened 部署验收

- `APP_ENV=production`、HTTPS Origins、`AUTH_COOKIE_SECURE=true`。
- 数据库密码必须显式提供，PostgreSQL 不暴露 Host Port。
- Demo Seed 被强制关闭。
- API/Worker/Web 使用 `no-new-privileges`、Drop Capabilities 和只读文件系统；所需临时目录通过
  `tmpfs` 明确开放。
- 文档说明反向代理/TLS、Secret Manager、备份、日志脱敏、数据库网络隔离和升级顺序。
- Overlay 是最小安全基线，不宣称替代 Kubernetes/Cloud IAM/WAF 或完整多租户沙箱。
