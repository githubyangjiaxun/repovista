# 测试与质量

状态：v0.1 已实现基线

## 1. 质量目标

RepoVista 的测试要证明：

- URL、Path、Git 和扫描边界不会执行或逃逸。
- Parser/Graph 对固定输入产生稳定 Symbol、Edge 和行号。
- PostgreSQL 能持久化完整 Snapshot，并恢复 Job/证据/分享。
- OpenAPI 与 Fastify Route 不漂移。
- 模型不能伪造 Citation。
- Web 的关键用户旅程可重复。
- 三个生产镜像和 Compose 配置可以构建。

## 4. PostgreSQL 集成测试

测试使用真实 PostgreSQL，不使用 Testcontainers。CI 在 GitHub Actions Service Container 中启动 `pgvector/pgvector:pg17`。

本地示例：

```bash
DATABASE_TEST_URL=postgresql://repovista:repovista@127.0.0.1:5432/repovista_test \
pnpm --filter @repovista/database test
```

未设置 URL 时该 Test Suite 是 Skip。发布报告必须单独确认它实际执行且 Passed，不能只引用 `pnpm check` 的 Exit Code。

## 5. Browser E2E

Playwright 启动独立 Next Dev Server，Browser Route Mock `http://localhost:4000/v1/**`。这样验证真实 React、Routing、Hydration、Accessibility Selector 和 Network Contract，同时不依赖 GitHub/DB/Model。

覆盖旅程：

1. 首页 → 导入选项 → Job Progress → Overview → Source → Map → Grounded Ask → Evidence Source → Share。
2. Repository List → 固定 Snapshot Workspace。
3. API 结构化失败 → 可见 Message/Request ID。

CI 使用一个 Chromium Worker、最多两次 Retry，并上传 Screenshot/Video/Trace HTML Report。Retry 不能成为忽略 Flaky 的理由；本地可复现的竞态必须修复。

## 6. CI

### Quality Job

- PostgreSQL/pgvector Service。
- Install Frozen Lockfile。
- OpenAPI、Lint、Typecheck、Test、Build。
- `DATABASE_TEST_URL` 传入 Turbo，避免错误复用 Skip Cache。

### Container Matrix

- 独立 Build API、Worker、Web Dockerfile。
- BuildKit GHA Cache。
- 不 Push Image。

### Browser Job

- 安装 Chromium 与系统依赖。
- 运行 Playwright。
- 上传 Report Artifact。

## 7. 安全测试重点

当前已有一部分边界测试，继续补充时优先：

- URL Credentials、非 HTTPS、非 GitHub Host、额外 Path Segment。
- Git Ref 参数注入和非法格式。
- Ignore/Source 目录穿越、Windows Separator。
- Symlink、二进制、超大文件、文件数/总字节上限。
- Prompt Injection 文本和伪造 Evidence ID。
- Model 无效 JSON、空 Content、非 2xx、超时。
- SSE 重连、租约丢失和双 Worker 完成竞争。
- Share Slug 注入和 Snapshot 归属。

## 8. Parser 变更

每个 Parser 修复必须有最小 Source Fixture 和明确断言：Symbol Kind/Name/Qualified Name/Signature/Start-End Line、Edge Type/Target/Confidence/Evidence。不要用“整个巨大 Snapshot 自动更新”掩盖非预期变化。

## 9. 性能

`benchmarks` 提供 Parser Harness，但 v0.1 README 不公布未经复验的吞吐数字。性能报告至少记录：Commit、Fixture、文件/字节数、机器、OS、Node、命令、Wall Time、CPU 和 RSS。

先度量以下热路径：扫描、Tree-sitter、关系解析、完成事务、Map 构建、Search、Web 大图渲染。没有数据前不引入 Redis、图数据库或复杂分布式组件。
