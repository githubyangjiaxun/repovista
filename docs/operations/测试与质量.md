# 测试与质量

状态：v0.2 已实现并验收（2026-08-20）

## 1. 质量目标

RepoVista 的测试要证明：

- URL、Ref、Path、Git 和扫描边界不会执行或逃逸。
- TS/JS/Python Parser 与 Graph 对固定输入产生稳定 Symbol、Edge 和行号。
- 增量 Planner 只复用兼容、成功解析的 ParsedFile，并在新 Snapshot 中完整重新链接。
- PostgreSQL 能持久化自包含 Snapshot，并恢复 Job、证据、Webhook、答案和分享。
- OpenAPI 与 Fastify Route 不漂移，附件 Header 和错误状态码符合 Contract。
- 模型不能伪造 Citation，AI 关闭时静态功能仍可用。
- Web 的 Full/Incremental/Legacy、Automation、Python Source、导出和固定导航可重复。
- 三个生产镜像和 Compose 配置可以构建、启动和健康检查。

## 4. PostgreSQL 集成测试

测试使用真实 PostgreSQL 17 + pgvector，不使用 Testcontainers。未设置 URL 时该 Test Suite
会 Skip，Skip 不能作为发布通过证据。

本地示例：

```bash
DATABASE_TEST_URL=postgresql://repovista:repovista@127.0.0.1:65432/repovista \
pnpm --filter @repovista/database test
```

发布时必须确认：

- 空库先执行 `0001_initial.sql` 和 `0002_incremental_github.sql`。
- 重启或重复 Migration 不产生第三条记录，也不重复执行 DDL。
- 同 Delivery 并发只生成一个 Snapshot/Job。
- Lease Lost 时完成事务不可见。
- 增量 Snapshot 的 Base、Mode、Tree Hash、Stats 和 Latest Pointer 同步提交。

## 5. Browser E2E

Playwright 启动独立 Next Dev Server，Browser Route Mock
`http://localhost:4000/v1/**`。这样验证真实 React、Routing、Hydration、Accessibility Selector、
固定 Snapshot URL 和下载链接，同时不依赖 GitHub、数据库或模型。

四条旅程：

1. 首页 → 导入选项 → Job Progress → Incremental Delta/Automation → Python Source → Map →
   Grounded Ask → Evidence Source → Share。
2. 选定 Snapshot 下载 Markdown 与 SVG，核对请求使用的 Snapshot ID 和附件正文。
3. Repository List → 固定 Snapshot Workspace，不随 Latest 漂移。
4. 结构化 API 失败 → 可见 Message/Request ID，且 Workspace 保持可用。

CI 使用 Chromium、最多两次 Retry，并上传 Screenshot/Video/Trace。Retry 不能成为忽略 Flaky
的理由；本地可复现的竞态必须修复。

## 7. Webhook 验收

真实 Compose API 使用固定 Fixture 和 HMAC 发送：

- Ping。
- 公共默认分支 Push。
- 完全相同 Delivery 重放。
- 同 Delivery 不同 Body。
- 错误签名。
- 非默认分支和删除 Push。

必须验证：

- Ping/忽略事件不创建 Job。
- 有效 Push 返回 202，并由正常 Worker 完成指定 Commit。
- 重放返回 Duplicate，不新增 Snapshot/Job。
- Body 冲突返回 409。
- 错签名返回 401，Secret 不出现在响应或日志。

这证明 Endpoint 和业务事务，不等同于已经验证 GitHub 托管网络回调。

## 8. Export 验收

- Markdown/SVG 只允许 Ready Snapshot。
- `Content-Type`、安全 `Content-Disposition`、`ETag`、`nosniff` 和 SVG CSP 正确。
- Markdown 含完整 Commit、Snapshot ID、Parser Version、Delta 和限制说明。
- SVG 通过 XML Parser，并在 Chromium 打开无 Console/Page Error。
- 仓库名、路径等包含 `& < > " '` 的 Fixture 不破坏 XML。
- 重复请求相同 Snapshot/Level 得到相同主体内容。

## 9. 安全测试重点

继续补充时优先：

- URL Credentials、非 HTTPS、非 GitHub Host、额外 Path Segment。
- Git Ref 参数注入和非法格式。
- Ignore/Source 目录穿越、Windows Separator。
- Symlink、二进制、超大文件、文件数/总字节上限。
- Prompt Injection 文本和伪造 Evidence ID。
- Model 无效 JSON、空 Content、非 2xx、超时。
- SSE 重连、租约丢失和双 Worker 完成竞争。
- Webhook 原始 Bytes、Unicode、Header 格式、Delivery 冲突。
- Share Slug 注入和 Snapshot 归属。

## 10. 性能纪律

`benchmarks` 提供 Parser Harness，但 README 不公布未经复验的吞吐数字。性能报告至少记录：
Commit、Fixture、文件/字节数、机器、OS、Node、命令、Wall Time、CPU 和 RSS。

优先度量扫描、Tree-sitter、关系解析、完成事务、Map 构建、Search 和 Web 大图渲染；没有数据
前不引入 Redis、图数据库或复杂分布式组件。
