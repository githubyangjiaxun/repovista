# 测试与质量

状态：proposal

## 1. 质量目标

测试的重点不是追求一个漂亮的覆盖率数字，而是保证：

- 静态分析结果稳定。
- API 契约不漂移。
- 数据迁移安全。
- AI 引用真实。
- 恶意仓库不能突破隔离。
- 核心用户路径在发布前可重复通过。

## 2. 测试金字塔

### 单元测试

- URL 和路径规范化。
- 状态机转换。
- stable_key 生成。
- AST 到领域符号转换。
- 图关系构建。
- Chunk 切分。
- Token 预算。
- 权限规则。
- 引用校验。

### Golden Tests

每种语言维护输入仓库和期望输出：

~~~text
fixtures/typescript/basic/
├── repository/
├── expected-files.json
├── expected-symbols.json
├── expected-edges.json
└── expected-chunks.json
~~~

Parser 变更时必须人工审阅 Golden Diff，不能无条件更新快照。

### Property-based Tests

- 任意输入路径不能逃出工作目录。
- 任意图环不会导致无限递归。
- Chunk 拼接不会丢失内容。
- 同一 Job 重试结果保持幂等。
- 任意无效 evidence_id 都不能形成引用。

### 集成测试

使用 Testcontainers 测试 PostgreSQL + pgvector、MinIO、本地 Git Fixture、Fake Model Provider、Worker 租约接管和 RLS 越权。

### E2E

1. 打开首页。
2. 导入 medium-ts。
3. 等待索引完成。
4. 打开包级和符号级地图。
5. 点击节点并查看源码行号。
6. 提问并验证引用。
7. 创建分享页。
8. 退出登录后访问公开分享页。

## 3. 安全测试

- SSRF URL 和重定向到私网。
- 符号链接逃逸和路径穿越。
- 超大仓库和压缩炸弹。
- 二进制伪装成源码。
- Prompt Injection。
- Markdown / SVG XSS。
- 跨 workspace 资源 ID。
- Git Token 日志泄漏。
- 模型输出恶意 HTML。

## 4. AI 评估

固定仓库和固定问题集进入版本控制。影响检索、Prompt、模型适配或引用校验的改动运行：

- Retrieval recall。
- Citation precision。
- Citation coverage。
- Refusal behavior。
- Schema validity。
- Prompt Injection resistance。
- 延迟和 Token 成本。

AI 测试使用 Fake Provider 保证 CI 确定性；真实模型评估在定时任务或发布候选阶段执行。

## 5. 性能 Benchmark

| 规模 | 文件数 | 用途 |
|---|---:|---|
| small | < 1,000 | 每个 PR |
| medium | 1,000～10,000 | 主分支 |
| large | > 10,000 | 发布候选或定时 |

记录 clone、扫描、解析、建图、Embedding 时间，峰值 RSS 和 CPU，数据库增长量，地图和搜索 p50/p95，增量索引时间，以及 AI 首 Token 和总延迟。

Benchmark 报告必须记录机器、操作系统、Node、数据库和 parser 版本。

## 6. CI 门禁

Pull Request：

- 格式检查、Lint、Type Check。
- Unit、Golden、Integration 和 Migration Test。
- OpenAPI Diff、Secret Scan、Dependency License。
- Build 和 small Benchmark。

主分支：

- Playwright E2E。
- 可访问性。
- 容器构建、SBOM、容器扫描。
- medium Benchmark。

发布候选：

- 真实模型评估。
- large Benchmark。
- 全量安全 Fixture。
- 升级 Migration 和恢复演练抽查。

## 7. 覆盖率

覆盖率用于发现盲区，不是唯一质量标准：

- Domain、权限、路径和引用校验要求高分支覆盖。
- Parser 优先 Golden Test。
- Adapter 优先契约测试。
- UI 按用户风险测试。

禁止为了提高覆盖率写没有断言价值的测试。

## 8. Flaky Test

- 失败测试不能简单自动重跑后忽略。
- 标记 flaky 必须创建 Issue、负责人和到期时间。
- CI 输出随机种子、请求 ID 和必要 Artifact。
- E2E 保存截图、Trace 和服务日志。
- 网络依赖默认 Mock，真实网络测试单独分组。

## 9. 发布验收

- [ ] 空库 Migration 成功。
- [ ] 上一版本升级成功。
- [ ] Docker Compose 可从 README 启动。
- [ ] 三个示例仓库索引成功。
- [ ] 所有引用指向正确 Commit 和行号。
- [ ] 无模型时静态功能可用。
- [ ] Ollama 和 External Provider 路径可用。
- [ ] 私有仓库不会生成公共分享。
- [ ] 安全 Fixture 通过。
- [ ] Benchmark 没有未解释回归。
- [ ] README、CHANGELOG 和 Release Notes 已更新。

## 10. Bug 优先级

| 级别 | 示例 | 处理 |
|---|---|---|
| P0 | 私有源码泄露、远程执行、越权 | 立即停止发布并修复 |
| P1 | 引用错误、索引数据损坏、核心流程不可用 | 当前版本优先 |
| P2 | 部分仓库解析失败、明显性能退化 | 下个补丁或小版本 |
| P3 | 视觉、文案和低影响体验问题 | 正常排期 |
