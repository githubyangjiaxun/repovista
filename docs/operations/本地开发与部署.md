# 本地开发与部署

状态：v1.1 可复现 Bundled Demo 已完成验收（2026-08-27）

## 1. 前置条件

- Node.js 22+。
- pnpm 10.30.3（建议 Corepack）。
- Docker 与 Docker Compose。
- Git。
- 可选 Ollama 或 OpenAI-compatible Endpoint。

## 2. 端口

| 服务 | 默认端口 | 覆盖变量 |
|---|---:|---|
| Web | 3000 | `WEB_PORT` |
| API | 4000 | `API_PORT` |
| PostgreSQL | 5432 | `POSTGRES_PORT`（Compose） |
| Ollama | 11434 | 外部服务，不在 Compose 中 |

当前 Compose 没有 MinIO、Redis、Telemetry Collector 或 Ollama Container。

## 3. 最快启动

```bash
docker compose up --build -d
```

Compose 启动 PostgreSQL、API、Worker、Web。API 健康前执行 Migration，Worker 与 Web 等待 API Ready。
首次启动还会运行一次性 `demo-seed`：它从仓库内 Fixture 创建 Full Base、Incremental Head 和两条
Fake Provider Verified Explanation，然后退出。普通 Worker 只在 Seed 成功后启动。

```bash
curl http://localhost:4000/v1/health/ready
docker compose ps
docker compose logs -f worker
```

浏览器打开 <http://localhost:3000>。

首页选择 **Open the bundled demo**，或执行：

```bash
pnpm install --frozen-lockfile
pnpm demo:smoke
```

这个 Smoke 不访问 GitHub、Ollama 或外部模型。Fixture Commit 是内容 manifest 的稳定合成修订，
不是 GitHub 托管 Commit。

## 4. 停止与数据

```bash
docker compose down
```

这会停止容器但保留 `postgres-data` Volume。只有明确要删除本项目本地数据库时才执行：

```bash
docker compose down -v
```

不要对不确定的 Docker Volume 使用删除命令，也不要操作其他项目的 PostgreSQL/Supabase Volume。

## 5. 本地源码开发

```bash
corepack enable
pnpm install --frozen-lockfile
docker compose up -d postgres
pnpm db:migrate
pnpm dev
```

`pnpm dev` 使用 Node `--env-file-if-exists=.env` 加载根 `.env`，然后通过 Turborepo 并行启动 Web、API、Worker。没有 `.env` 时使用安全本地默认值。

默认 API/Worker 连接：

```text
postgresql://repovista:repovista@localhost:5432/repovista
```

如果端口或数据库不同，复制并修改：

```bash
cp .env.example .env
```

## 6. 环境变量

`.env.example` 只列当前代码解析的配置。主要分类：

- 服务：`APP_ENV`、`LOG_LEVEL`、`WEB_PORT`、`API_PORT`、Origins。
- 数据库：`DATABASE_URL`、`DATABASE_MAX_CONNECTIONS`。
- Chat 模型：`MODEL_PROVIDER`、Base URL、Key、`CHAT_MODEL`。
- Embedding：`EMBEDDING_PROVIDER`、`EMBEDDING_MODEL`、Batch/Input/Timeout；与 Chat 独立。
- 仓库限制：Allowed Hosts、File/Byte/File Size。
- Worker：Timeout、Poll、Lease、Worker ID。
- 限流：每小时匿名 Import/Question/Share。
- Migration：`RUN_MIGRATIONS_ON_START`。
- GitHub 自动更新与私有访问：`GITHUB_WEBHOOK_SECRET`、`GITHUB_APP_SLUG`、`GITHUB_APP_ID`、
  `GITHUB_APP_PRIVATE_KEY`、OAuth Client、`GITHUB_OAUTH_ORIGIN` 和 Body Size。
- 身份与 Workspace：`AUTH_SESSION_TTL_SECONDS`、`AUTH_OAUTH_STATE_TTL_SECONDS`,
  `AUTH_COOKIE_DOMAIN`, `AUTH_COOKIE_SECURE`, `AUTH_TOKEN_TTL_DAYS`, `AUTH_ALLOW_SIGNUP`。

### GitHub OAuth/App private access

Create a GitHub OAuth App and GitHub App for the deployment. Set the OAuth callback to
`<API_ORIGIN>/v1/auth/github/callback`, the App setup callback to
`<API_ORIGIN>/v1/integrations/github/setup`, and the App webhook URL to
`<API_ORIGIN>/v1/integrations/github/webhooks`. Grant only read metadata, contents, and pull-request
permissions needed by RepoVista. Put the PEM private key in a deployment secret; do not commit it or
paste it into a repository URL.

For production, use HTTPS origins and `AUTH_COOKIE_SECURE=true`. The configuration loader rejects
insecure production origins. Local Compose defaults to `APP_ENV=development` so HTTP localhost can be
used safely for development.

真实密钥只放本地 `.env`、Shell Secret 或部署平台 Secret，不提交 Git。

## 7. 模型模式

### 默认 fake

无需配置。它确定性总结检索证据，适合评估完整流程。

### Ollama

先在宿主机启动模型，然后：

```bash
MODEL_PROVIDER=ollama \
CHAT_MODEL=qwen3:8b \
OLLAMA_BASE_URL=http://host.docker.internal:11434 \
docker compose up --build -d
```

源码模式运行 API 时可使用 `http://localhost:11434`。Linux Docker 需要确保 `host.docker.internal` 映射到 Host Gateway，或改为容器可访问的地址。

### OpenAI-compatible

```bash
MODEL_PROVIDER=openai-compatible \
OPENAI_COMPATIBLE_BASE_URL=https://your-endpoint.example/v1 \
OPENAI_COMPATIBLE_API_KEY=replace-me \
CHAT_MODEL=your-model \
docker compose up --build -d
```

Base URL 应是包含 `/models` 和 `/chat/completions` 的 API Root。

### Semantic Embedding

Semantic Search 默认关闭；`MODEL_PROVIDER=fake` 不会创建假向量。本地 Ollama 示例：

```bash
ollama pull nomic-embed-text
EMBEDDING_PROVIDER=ollama \
EMBEDDING_MODEL=nomic-embed-text \
OLLAMA_BASE_URL=http://host.docker.internal:11434 \
docker compose up --build -d
```

OpenAI-compatible 使用同一 Base URL/Key，但调用 `/embeddings`；必须显式设置
`EMBEDDING_MODEL`。API 与 Worker 必须获得相同配置。Provider 停止时 Hybrid 仍可返回 Lexical，
Semantic-only 会显式失败。

## 8. Migration

源码开发：

```bash
pnpm db:migrate
pnpm db:seed
```

Seed 命令使用正式 Scanner、Parser、Graph、Worker Lease 与 Store 创建或复用两版 Bundled Demo。
它只领取自己刚创建的 Job；重复运行不增加目标 Snapshot、Job 或 Explanation。

不需要 Demo 时：

```bash
DEMO_SEED_ENABLED=false docker compose up --build -d
```

生产环境不要运行 Demo Seed，使用[《生产部署加固》](./生产部署加固.md)的 Overlay 与检查清单。

## 9. CLI

```bash
pnpm --filter @repovista/cli dev doctor
pnpm --filter @repovista/cli dev analyze https://github.com/octocat/Hello-World --wait
pnpm --filter @repovista/cli dev repositories --json
pnpm --filter @repovista/cli dev embed <snapshot-id> --wait
pnpm --filter @repovista/cli dev search <snapshot-id> "where is request timeout enforced" --mode hybrid
```

API 非默认 Origin 时设置 `REPOVISTA_API_URL` 或传 `--api-url`。首次使用 CLI 时，在 Web Settings
创建一次性 API Token，然后运行：

```bash
printf '%s\n' "$REPOVISTA_TOKEN" | pnpm --filter @repovista/cli dev auth login
pnpm --filter @repovista/cli dev workspace list
pnpm --filter @repovista/cli dev github installations
pnpm --filter @repovista/cli dev analyze https://github.com/owner/private-repo --installation 123 --wait
```

CLI token 只保存在本地 `0600` 配置文件中，不能通过 `--token` 参数传入；撤销后服务端立即拒绝。

## 10. 构建与验证

```bash
pnpm check
pnpm test:e2e

```

数据库集成测试需要 `DATABASE_TEST_URL`。Playwright 首次运行需要安装 Chromium：


## 11. 故障排查

### API Ready 503

检查 `docker compose ps postgres`、数据库日志、`DATABASE_URL` 和 Migration 输出。

### Job 一直 queued

检查 Worker 是否运行、是否使用相同 Database、`WORKER_ID`、Poll Interval 和 Worker Log。

### Job 卡在 cloning

检查 GitHub 网络、仓库是否公开、Ref 是否存在、DNS、代理和 Job Timeout。

### Job failed: symlink

这是安全拒绝。当前 Scanner 不跟随仓库符号链接；需要删除/忽略该路径或后续实现经过验证的安全策略。

### 地图只有少量节点

确认仓库是 JS/TS/Python/Go，查看 Snapshot Stats、Parser Version 和解析 File。其他文本可浏览/
搜索但当前不产生语言 Symbol Graph。

### Linux 容器报告 Python Parser 原生绑定缺失

使用仓库锁定的 pnpm 配置和 Dockerfile 构建；`pnpm-workspace.yaml` 已允许
`tree-sitter-python` 的安装脚本，Worker Builder 包含 `g++`、`make`、`python3`。不要用
`--ignore-scripts` 构建 Worker 运行时依赖。

### AI 失败但地图正常

检查 Provider/Base URL/Model/Key。切回 `MODEL_PROVIDER=fake` 可验证检索和 Citation 路径。

### Semantic Index disabled/not ready

检查 API 与 Worker 的 `EMBEDDING_PROVIDER/EMBEDDING_MODEL` 是否相同、Ollama Base URL 是否从两者
可访问，再通过 Web 或 CLI `embed --wait` 构建。Text/Symbol 无需等待 Index。

### Hybrid degraded / Semantic 503

检查 Embedding Provider 是否运行、模型是否存在以及 Profile 是否与当前配置匹配。Hybrid 的
Lexical 结果是预期降级；不要把它误报为 Semantic 成功。

### 端口占用

为 Compose 设置 `WEB_PORT`、`API_PORT`、`POSTGRES_PORT`。注意 Web 的浏览器 API Origin 需要与对外 API Port 一致后重新 Build。

## 12. 生产说明

当前 Compose 是本地演示基线，不包含 TLS、认证、Secret Manager、备份、HA、WAF 或多租户隔离。若公开部署，至少添加反向代理/TLS、网络访问控制、数据库备份、日志收集、资源限额和独立 Worker 临时存储策略。
