# 本地开发与部署

状态：v0.2 已实现基线

## 1. 前置条件

- Node.js 22+。
- pnpm 10.30.3（建议 Corepack）。
- Docker 与 Docker Compose。
- Git。
- 可选 Ollama 或 OpenAI-compatible Endpoint。

## 2. 端口

| 服务 | 默认端口 | 覆盖变量 |
|---|---:|---|
| Web | 3000 | `WEB_PORT` |
| API | 4000 | `API_PORT` |
| PostgreSQL | 5432 | `POSTGRES_PORT`（Compose） |
| Ollama | 11434 | 外部服务，不在 Compose 中 |

当前 Compose 没有 MinIO、Redis、Telemetry Collector 或 Ollama Container。

## 3. 最快启动

```bash
docker compose up --build -d
```

Compose 启动 PostgreSQL、API、Worker、Web。API 健康前执行 Migration，Worker 与 Web 等待 API Ready。

```bash
curl http://localhost:4000/v1/health/ready
docker compose ps
docker compose logs -f worker
```

浏览器打开 <http://localhost:3000>。

## 4. 停止与数据

```bash
docker compose down
```

这会停止容器但保留 `postgres-data` Volume。只有明确要删除本项目本地数据库时才执行：

```bash
docker compose down -v
```

不要对不确定的 Docker Volume 使用删除命令，也不要操作其他项目的 PostgreSQL/Supabase Volume。

## 5. 本地源码开发

```bash
corepack enable
pnpm install --frozen-lockfile
docker compose up -d postgres
pnpm db:migrate
pnpm dev
```

`pnpm dev` 使用 Node `--env-file-if-exists=.env` 加载根 `.env`，然后通过 Turborepo 并行启动 Web、API、Worker。没有 `.env` 时使用安全本地默认值。

默认 API/Worker 连接：

```text
postgresql://repovista:repovista@localhost:5432/repovista
```

如果端口或数据库不同，复制并修改：

```bash
cp .env.example .env
```

## 6. 环境变量

`.env.example` 只列当前代码解析的配置。主要分类：

- 服务：`APP_ENV`、`LOG_LEVEL`、`WEB_PORT`、`API_PORT`、Origins。
- 数据库：`DATABASE_URL`、`DATABASE_MAX_CONNECTIONS`。
- 模型：`MODEL_PROVIDER`、Base URL、Key、`CHAT_MODEL`。
- 仓库限制：Allowed Hosts、File/Byte/File Size。
- Worker：Timeout、Poll、Lease、Worker ID。
- 限流：每小时匿名 Import/Question/Share。
- Migration：`RUN_MIGRATIONS_ON_START`。
- GitHub 自动更新：`GITHUB_WEBHOOK_SECRET`、可选 `GITHUB_APP_SLUG` 和 Body Size。

真实密钥只放本地 `.env`、Shell Secret 或部署平台 Secret，不提交 Git。

## 7. 模型模式

### 默认 fake

无需配置。它确定性总结检索证据，适合评估完整流程。

### Ollama

先在宿主机启动模型，然后：

```bash
MODEL_PROVIDER=ollama \
CHAT_MODEL=qwen3:8b \
OLLAMA_BASE_URL=http://host.docker.internal:11434 \
docker compose up --build -d
```

源码模式运行 API 时可使用 `http://localhost:11434`。Linux Docker 需要确保 `host.docker.internal` 映射到 Host Gateway，或改为容器可访问的地址。

### OpenAI-compatible

```bash
MODEL_PROVIDER=openai-compatible \
OPENAI_COMPATIBLE_BASE_URL=https://your-endpoint.example/v1 \
OPENAI_COMPATIBLE_API_KEY=replace-me \
CHAT_MODEL=your-model \
docker compose up --build -d
```

Base URL 应是包含 `/models` 和 `/chat/completions` 的 API Root。

## 8. Migration

源码开发：

```bash
pnpm db:migrate
pnpm db:seed
```

Seed 命令确认初始 Migration 已创建 Public Demo User/Workspace，不添加示例 Repository。重复运行安全。

## 9. CLI

```bash
pnpm --filter @repovista/cli dev doctor
pnpm --filter @repovista/cli dev analyze https://github.com/octocat/Hello-World --wait
pnpm --filter @repovista/cli dev repositories --json
```

API 非默认 Origin 时设置 `REPOVISTA_API_URL` 或传 `--api-url`。

## 10. 构建与验证

```bash
pnpm check
pnpm test:e2e
docker compose config --quiet
docker compose build api worker web
```

数据库集成测试需要 `DATABASE_TEST_URL`。Playwright 首次运行需要安装 Chromium：

```bash
pnpm --filter @repovista/web exec playwright install chromium
```

## 11. 故障排查

### API Ready 503

检查 `docker compose ps postgres`、数据库日志、`DATABASE_URL` 和 Migration 输出。

### Job 一直 queued

检查 Worker 是否运行、是否使用相同 Database、`WORKER_ID`、Poll Interval 和 Worker Log。

### Job 卡在 cloning

检查 GitHub 网络、仓库是否公开、Ref 是否存在、DNS、代理和 Job Timeout。

### Job failed: symlink

这是安全拒绝。当前 Scanner 不跟随仓库符号链接；需要删除/忽略该路径或后续实现经过验证的安全策略。

### 地图只有少量节点

确认仓库是 JS/TS/Python，查看 Snapshot Stats、Parser Version 和解析 File。其他文本可浏览/搜索但当前不产生语言 Symbol Graph。

### Linux 容器报告 Python Parser 原生绑定缺失

使用仓库锁定的 pnpm 配置和 Dockerfile 构建；`pnpm-workspace.yaml` 已允许
`tree-sitter-python` 的安装脚本，Worker Builder 包含 `g++`、`make`、`python3`。不要用
`--ignore-scripts` 构建 Worker 运行时依赖。

### AI 失败但地图正常

检查 Provider/Base URL/Model/Key。切回 `MODEL_PROVIDER=fake` 可验证检索和 Citation 路径。

### 端口占用

为 Compose 设置 `WEB_PORT`、`API_PORT`、`POSTGRES_PORT`。注意 Web 的浏览器 API Origin 需要与对外 API Port 一致后重新 Build。

## 12. 生产说明

当前 Compose 是本地演示基线，不包含 TLS、认证、Secret Manager、备份、HA、WAF 或多租户隔离。若公开部署，至少添加反向代理/TLS、网络访问控制、数据库备份、日志收集、资源限额和独立 Worker 临时存储策略。
