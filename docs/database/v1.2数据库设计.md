# v1.2 数据库设计：Guardrail Reviews

## Migration 0009

新增 `guardrail_reviews`：

| 列 | 约束 | 说明 |
|---|---|---|
| `id` | UUID PK | 当前记录身份 |
| `workspace_id` | NOT NULL，Workspace FK | 租户边界 |
| `snapshot_id` | NOT NULL，复合 Snapshot FK | 不允许跨租户引用 |
| `finding_id` | 1–300 字符 | 当前 Snapshot 内 Finding ID |
| `subject_key` | `sha256:<64 hex>` | 服务端计算的逻辑身份辅助值 |
| `status` | `acknowledged/accepted_risk/false_positive` | `unreviewed` 用无记录表达 |
| `note` | 非空，最长 2,000 | 人类备注 |
| `reviewed_by` | User FK，可空 | 删除用户后保留 Review 状态 |
| `created_at`/`updated_at` | timestamptz | 变更时间 |

唯一键为 `(workspace_id, snapshot_id, finding_id)`；索引为
`(workspace_id, snapshot_id, updated_at DESC)`。`ON DELETE CASCADE` 只作用于 Workspace/Snapshot，
用户删除使用 `SET NULL`。

## 事务不变量

1. Store upsert 前锁定并验证 Snapshot 属于 Workspace 且为 `ready`。
2. upsert 与审计事件在同一事务中提交；冲突时保留 `created_at`、更新 `updated_at`。
3. clear 删除记录并在同一事务中追加审计；不存在记录时不产生重复事件。
4. 列表查询只接受 Workspace + Snapshot 条件；API 负责将当前 Report 的缺省状态补成
   `unreviewed`。
5. 数据库不保存完整 Report、源代码或模型输出；`subject_key` 不能作为授权依据。

## 保留与隐私

当前 Review 记录随 Snapshot 一起保留。变更历史由 append-only `audit_events` 提供；审计不写入
备注原文，避免把可能包含敏感信息的自由文本扩散到日志查询面。
