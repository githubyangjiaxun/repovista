# v0.3 数据库设计

## 迁移

新增前向 `0003_pr_impact.sql`，不修改已发布 Migration。所有表默认 `ON DELETE CASCADE` 只沿 Analysis → Impact → Evidence 删除；Base/Head Snapshot 仍由 Repository 生命周期管理。

## 核心表

### `pull_request_analyses`

`id uuid PK`、`repository_id`、`workspace_id`、`provider`、`pr_number`、`title`、`url`、`base_sha`、`head_sha`、`base_snapshot_id`、`head_snapshot_id`、`parser_version`、`algorithm_version`、`revision`、`status`、`progress`、`idempotency_key UNIQUE`、`error_*`、时间字段。

约束：同一分析的 base/head 必须来自同一 repository；SHA 为 40 位；status 为 `queued/running/ready/failed/cancelled`；`revision` 从 1 递增。

### `pull_request_files`

按 analysis 保存 `path`、`change_type`、base/head blob hash、旧/新路径、additions/deletions、is_binary、`UNIQUE(analysis_id,path,change_type)`。不依赖 GitHub 文件列表长期可用。

### `pull_request_impacts`

保存 `impact_id`、`analysis_id`、`snapshot_id`、`snapshot_side`、`symbol_id`、`path`、`impact_type`、`distance`、`risk_score`、`risk_level`、`risk_breakdown_json`、`truncated`。按 score、path、line、ID 稳定排序。

### `pull_request_impact_paths`

保存 impact 与路径顺序、固定 snapshot、from/to symbol、relation、edge 和 `evidence_id`；`UNIQUE(impact_id,ordinal)`，用于 Web 和扩展逐段展示最短证据链。

### `pull_request_evidence`

保存稳定 evidence ID、analysis、impact、snapshot、file、symbol、commit、line range、quote、content hash；复合外键同时约束 snapshot/commit/file/symbol，禁止跨快照引用。

### `analysis_jobs`

复用现有租约表，新增 `analysis_id` 与 `available_at`，并允许 `job_type='pull_request_analysis'`。idempotency key 必须包含 repository、PR、base/head、parser version、算法版本；重试不能创建第二条 Analysis。

## 查询与事务

- 创建请求、幂等查找、Analysis 和 job 插入在一个事务中完成。
- Worker 完成时在一个事务内写文件、impact、path、evidence，最后把 Analysis 标为 ready；任何异常整体回滚。
- 查询分页使用 `(risk_score DESC, path ASC, start_line ASC, impact_id ASC)` 游标，不使用不稳定 OFFSET。
- 不能删除或更新 ready Analysis；rerun 使用新 revision 和新 idempotency key。
