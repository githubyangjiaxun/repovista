# v0.9 数据库设计：Guardrail Explanations

## 1. 表 `guardrail_explanations`

字段：

- `id uuid primary key`
- `workspace_id uuid not null references workspaces`
- `snapshot_id uuid not null references repository_snapshots`
- `finding_id text not null`
- `finding_fingerprint text not null`
- `rule_id text not null`
- `commit_sha text not null`
- `parser_version text not null`
- `algorithm_version text not null`
- `profile_fingerprint text not null`
- `profile_json jsonb`（可空，兼容历史 Snapshot；fingerprint 仍必须固定）
- `finding_json jsonb not null`（服务端生成的固定 Finding 快照）
- `answer_json jsonb not null`（经 citation verifier 的答案，可包含服务端校验后的有界 citation 摘录）
- `provider text not null`
- `model_name text not null`
- `prompt_version text not null`
- `created_by uuid references users`
- `created_at timestamptz not null default now()`

## 2. 约束与索引

- 唯一键 `(workspace_id, snapshot_id, finding_fingerprint, provider, model_name, prompt_version)`，保证幂等复用。
- 外键 `(workspace_id, snapshot_id)` 与 Repository/Snapshot 访问范围保持一致。
- `answer_json` 和 `finding_json` 必须是 JSON object；文本长度和 provider/model 长度有上限。
- 表只插入不更新；新 Provider、模型或 Prompt 版本生成新记录。
- 不保存原始模型响应或完整源码文件；仅在 `answer_json.citations[].quote` 保存有长度上限、位置已校验的摘录。
- 索引 `(workspace_id, snapshot_id, created_at desc)` 和 `(snapshot_id, id)` 支持权限查询。

## 3. 迁移与兼容

新增 `0007_guardrail_explanations.sql`。旧数据库没有解释记录时 API 返回空/404，不影响既有问答、Guardrails 或 Snapshot。迁移不修改已有源码和历史 Finding。
