# 数据库设计

状态：proposal  
适用版本：v0.1  
数据库：PostgreSQL 17 + pgvector

## 1. 设计原则

1. 所有分析结果固定到 Repository Snapshot。
2. 相同文件内容跨 Commit 去重。
3. 核心查询字段结构化，JSON 只保存扩展元数据。
4. 任务可重试、可接管、可审计。
5. 全文、符号图和向量检索先统一在 PostgreSQL。
6. 多租户数据必须通过 workspace_id 隔离。
7. 删除采用明确生命周期，不依赖无边界软删除。

## 2. 扩展

~~~sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS citext;
~~~

UUIDv7 由应用层统一生成，避免数据库版本差异。时间字段统一使用 timestamptz，服务端保存 UTC。

## 4. 身份与工作区

### users

| 字段 | 类型 | 约束 |
|---|---|---|
| id | uuid | PK |
| email | citext | unique, nullable for anonymous bootstrap |
| display_name | text | not null |
| avatar_url | text | nullable |
| status | text | active、disabled |
| created_at | timestamptz | not null |
| updated_at | timestamptz | not null |

### workspaces

| 字段 | 类型 | 约束 |
|---|---|---|
| id | uuid | PK |
| owner_id | uuid | FK users |
| name | text | not null |
| slug | citext | unique |
| visibility | text | private、public |
| settings_json | jsonb | default empty object |
| created_at | timestamptz | not null |
| updated_at | timestamptz | not null |

### workspace_members

| 字段 | 类型 | 约束 |
|---|---|---|
| workspace_id | uuid | FK workspaces |
| user_id | uuid | FK users |
| role | text | owner、editor、viewer |
| joined_at | timestamptz | not null |

主键为 workspace_id + user_id。数据库约束保证 role 只允许合法值。

## 5. 仓库与快照

### repositories

~~~sql
CREATE TABLE repositories (
    id uuid PRIMARY KEY,
    workspace_id uuid NOT NULL REFERENCES workspaces(id),
    provider text NOT NULL,
    provider_repo_id text,
    canonical_url text NOT NULL,
    owner_name text NOT NULL,
    repo_name text NOT NULL,
    default_branch text,
    visibility text NOT NULL,
    latest_ready_snapshot_id uuid,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT repositories_provider_check
        CHECK (provider IN ('github', 'gitlab', 'local')),
    CONSTRAINT repositories_visibility_check
        CHECK (visibility IN ('public', 'private'))
);

CREATE UNIQUE INDEX repositories_provider_identity_uq
    ON repositories (workspace_id, provider, provider_repo_id)
    WHERE provider_repo_id IS NOT NULL;

CREATE UNIQUE INDEX repositories_url_uq
    ON repositories (workspace_id, canonical_url);
~~~

latest_ready_snapshot_id 在 snapshots 表创建后补外键，避免建表顺序循环。

### repository_snapshots

~~~sql
CREATE TABLE repository_snapshots (
    id uuid PRIMARY KEY,
    repository_id uuid NOT NULL REFERENCES repositories(id),
    commit_sha text NOT NULL,
    parent_commit_sha text,
    ref_name text,
    tree_hash text,
    status text NOT NULL,
    parser_version text NOT NULL,
    index_version integer NOT NULL DEFAULT 1,
    embedding_model text,
    stats_json jsonb NOT NULL DEFAULT '{}'::jsonb,
    requested_at timestamptz NOT NULL DEFAULT now(),
    ready_at timestamptz,
    failed_at timestamptz,
    CONSTRAINT snapshots_status_check CHECK (
        status IN (
            'requested', 'cloning', 'scanning', 'parsing',
            'building_graph', 'embedding', 'ready',
            'failed', 'cancelled'
        )
    )
);

CREATE UNIQUE INDEX repository_snapshots_version_uq
    ON repository_snapshots (
        repository_id, commit_sha, parser_version, index_version
    );

CREATE INDEX repository_snapshots_recent_idx
    ON repository_snapshots (repository_id, requested_at DESC);
~~~

Snapshot ready 后不修改 commit_sha、parser_version 和索引结果。需要重建时增加 index_version 或创建新 Snapshot 版本。

## 6. 内容寻址与文件

### content_blobs

~~~sql
CREATE TABLE content_blobs (
    hash text PRIMARY KEY,
    object_key text,
    inline_content text,
    byte_size bigint NOT NULL,
    mime_type text,
    created_at timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT content_location_check CHECK (
        (object_key IS NOT NULL AND inline_content IS NULL)
        OR
        (object_key IS NULL AND inline_content IS NOT NULL)
    )
);
~~~

小文件可以内联，大文件进入 MinIO/S3。hash 使用 sha256:hex 格式。

### snapshot_files

~~~sql
CREATE TABLE snapshot_files (
    id uuid PRIMARY KEY,
    snapshot_id uuid NOT NULL REFERENCES repository_snapshots(id)
        ON DELETE CASCADE,
    path text NOT NULL,
    blob_hash text NOT NULL REFERENCES content_blobs(hash),
    language text,
    byte_size bigint NOT NULL,
    line_count integer,
    is_generated boolean NOT NULL DEFAULT false,
    is_binary boolean NOT NULL DEFAULT false,
    parse_status text NOT NULL DEFAULT 'pending',
    parse_error_code text,
    created_at timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT snapshot_files_path_uq UNIQUE (snapshot_id, path),
    CONSTRAINT safe_relative_path CHECK (
        path <> ''
        AND path NOT LIKE '/%'
        AND path NOT LIKE '../%'
        AND path NOT LIKE '%/../%'
    )
);

CREATE INDEX snapshot_files_language_idx
    ON snapshot_files (snapshot_id, language);

CREATE INDEX snapshot_files_blob_idx
    ON snapshot_files (blob_hash);

CREATE INDEX snapshot_files_path_trgm_idx
    ON snapshot_files USING gin (path gin_trgm_ops);
~~~

路径还必须由应用层做标准化和目录穿越校验，数据库 CHECK 只是第二道防线。

## 7. 符号与关系图

### symbols

~~~sql
CREATE TABLE symbols (
    id uuid PRIMARY KEY,
    snapshot_id uuid NOT NULL REFERENCES repository_snapshots(id)
        ON DELETE CASCADE,
    snapshot_file_id uuid NOT NULL REFERENCES snapshot_files(id)
        ON DELETE CASCADE,
    stable_key text NOT NULL,
    kind text NOT NULL,
    name text NOT NULL,
    qualified_name text,
    signature text,
    start_line integer NOT NULL,
    start_column integer NOT NULL DEFAULT 0,
    end_line integer NOT NULL,
    end_column integer NOT NULL DEFAULT 0,
    doc_text text,
    content_hash text NOT NULL,
    metadata_json jsonb NOT NULL DEFAULT '{}'::jsonb,
    CONSTRAINT symbols_range_check CHECK (
        start_line > 0 AND end_line >= start_line
    ),
    CONSTRAINT symbols_stable_key_uq UNIQUE (snapshot_id, stable_key)
);

CREATE INDEX symbols_file_idx
    ON symbols (snapshot_file_id, start_line);

CREATE INDEX symbols_name_trgm_idx
    ON symbols USING gin (name gin_trgm_ops);

CREATE INDEX symbols_qualified_name_idx
    ON symbols (snapshot_id, qualified_name);

CREATE INDEX symbols_kind_idx
    ON symbols (snapshot_id, kind);
~~~

stable_key 建议由 language + normalized path + qualified name + signature digest 组成，但不能依赖行号，否则文件前面新增一行就会导致符号身份变化。

### symbol_edges

~~~sql
CREATE TABLE symbol_edges (
    id uuid PRIMARY KEY,
    snapshot_id uuid NOT NULL REFERENCES repository_snapshots(id)
        ON DELETE CASCADE,
    from_symbol_id uuid NOT NULL REFERENCES symbols(id)
        ON DELETE CASCADE,
    to_symbol_id uuid REFERENCES symbols(id)
        ON DELETE CASCADE,
    unresolved_target text,
    relation_type text NOT NULL,
    confidence real NOT NULL,
    evidence_json jsonb NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT symbol_edges_target_check CHECK (
        (to_symbol_id IS NOT NULL AND unresolved_target IS NULL)
        OR
        (to_symbol_id IS NULL AND unresolved_target IS NOT NULL)
    ),
    CONSTRAINT symbol_edges_confidence_check CHECK (
        confidence >= 0 AND confidence <= 1
    )
);

CREATE UNIQUE INDEX symbol_edges_resolved_uq
    ON symbol_edges (
        snapshot_id, from_symbol_id, to_symbol_id, relation_type
    )
    WHERE to_symbol_id IS NOT NULL;

CREATE INDEX symbol_edges_from_idx
    ON symbol_edges (snapshot_id, from_symbol_id, relation_type);

CREATE INDEX symbol_edges_to_idx
    ON symbol_edges (snapshot_id, to_symbol_id, relation_type)
    WHERE to_symbol_id IS NOT NULL;
~~~

v0.1 使用邻接表和递归 CTE。只有真实查询显示 PostgreSQL 无法满足延迟目标后，才评估图数据库。

## 8. 检索

### code_chunks

Embedding 维度由首个正式模型决定。示例使用 1536，切换不同维度模型时应新建列或独立表，不在同一索引混用。

~~~sql
CREATE TABLE code_chunks (
    id uuid PRIMARY KEY,
    snapshot_id uuid NOT NULL REFERENCES repository_snapshots(id)
        ON DELETE CASCADE,
    snapshot_file_id uuid NOT NULL REFERENCES snapshot_files(id)
        ON DELETE CASCADE,
    symbol_id uuid REFERENCES symbols(id) ON DELETE SET NULL,
    chunk_type text NOT NULL,
    start_line integer NOT NULL,
    end_line integer NOT NULL,
    content text NOT NULL,
    content_hash text NOT NULL,
    token_count integer NOT NULL,
    search_vector tsvector GENERATED ALWAYS AS (
        to_tsvector('simple', content)
    ) STORED,
    embedding vector(1536),
    embedding_model text,
    metadata_json jsonb NOT NULL DEFAULT '{}'::jsonb,
    created_at timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT chunks_range_check CHECK (
        start_line > 0 AND end_line >= start_line
    )
);

CREATE INDEX code_chunks_search_idx
    ON code_chunks USING gin (search_vector);

CREATE INDEX code_chunks_file_idx
    ON code_chunks (snapshot_file_id, start_line);

CREATE INDEX code_chunks_embedding_idx
    ON code_chunks USING hnsw (embedding vector_cosine_ops)
    WHERE embedding IS NOT NULL;
~~~

Chunk 去重可以额外添加 snapshot_id + content_hash + start_line 的唯一约束，最终形式需要结合增量索引实现验证。

## 9. 任务

### analysis_jobs

~~~sql
CREATE TABLE analysis_jobs (
    id uuid PRIMARY KEY,
    workspace_id uuid NOT NULL REFERENCES workspaces(id),
    repository_id uuid REFERENCES repositories(id),
    snapshot_id uuid REFERENCES repository_snapshots(id),
    job_type text NOT NULL,
    status text NOT NULL,
    priority smallint NOT NULL DEFAULT 100,
    progress real NOT NULL DEFAULT 0,
    phase text,
    processed bigint,
    total bigint,
    attempt_count integer NOT NULL DEFAULT 0,
    max_attempts integer NOT NULL DEFAULT 3,
    lease_owner text,
    lease_expires_at timestamptz,
    idempotency_key text NOT NULL,
    cancel_requested_at timestamptz,
    error_code text,
    error_message text,
    error_details_json jsonb,
    created_at timestamptz NOT NULL DEFAULT now(),
    started_at timestamptz,
    finished_at timestamptz,
    CONSTRAINT analysis_jobs_idempotency_uq UNIQUE (idempotency_key),
    CONSTRAINT analysis_jobs_progress_check CHECK (
        progress >= 0 AND progress <= 1
    )
);

CREATE INDEX analysis_jobs_claim_idx
    ON analysis_jobs (status, priority, created_at)
    WHERE status IN ('queued', 'running');

CREATE INDEX analysis_jobs_lease_idx
    ON analysis_jobs (lease_expires_at)
    WHERE status = 'running';
~~~

建议另建 job_events 表保存有限期事件，用于 SSE 断线恢复和调试，不把无限增长事件永久保留。

## 10. 对话、消息和引用

~~~sql
CREATE TABLE conversations (
    id uuid PRIMARY KEY,
    workspace_id uuid NOT NULL REFERENCES workspaces(id),
    repository_id uuid NOT NULL REFERENCES repositories(id),
    snapshot_id uuid NOT NULL REFERENCES repository_snapshots(id),
    created_by uuid REFERENCES users(id),
    title text NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE messages (
    id uuid PRIMARY KEY,
    conversation_id uuid NOT NULL REFERENCES conversations(id)
        ON DELETE CASCADE,
    role text NOT NULL,
    content text NOT NULL,
    answer_status text,
    model_provider text,
    model_name text,
    prompt_version text,
    token_usage_json jsonb,
    latency_ms integer,
    created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE message_citations (
    id uuid PRIMARY KEY,
    message_id uuid NOT NULL REFERENCES messages(id)
        ON DELETE CASCADE,
    snapshot_file_id uuid NOT NULL REFERENCES snapshot_files(id),
    symbol_id uuid REFERENCES symbols(id),
    start_line integer NOT NULL,
    end_line integer NOT NULL,
    quote text NOT NULL,
    evidence_hash text NOT NULL,
    retrieval_score real,
    ordinal integer NOT NULL,
    CONSTRAINT citation_range_check CHECK (
        start_line > 0 AND end_line >= start_line
    ),
    CONSTRAINT message_citation_ordinal_uq UNIQUE (message_id, ordinal)
);
~~~

保存 evidence_hash，使引用可以再次校验源码是否与生成答案时一致。

## 12. 多租户隔离

云端模式建议启用 PostgreSQL Row Level Security：

- 每个请求事务设置 app.workspace_id。
- Policy 要求 workspace_id 等于当前上下文。
- Worker 使用受限服务角色，并显式传 workspace。
- 超级管理员连接不用于普通 Web 请求。

即使启用 RLS，应用层仍需做权限检查并返回友好错误。

## 13. 数据保留

| 数据 | 默认策略 |
|---|---|
| 未完成临时 clone | Job 结束立即删除 |
| Job events | 7～30 天 |
| 失败详情 | 30 天后去敏或删除 |
| 公共 Snapshot | 用户主动删除前保留 |
| 私有源码 Blob | 工作区策略控制 |
| 撤销分享页 | 立即不可访问，延迟物理清理 |
| 无引用 Blob | 定期 GC，设置宽限期 |

Blob GC 先标记候选，再二次确认无引用，不能单次查询后直接删除。
