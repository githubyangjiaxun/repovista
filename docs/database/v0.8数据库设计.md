# v0.8 数据库设计：Policy Profiles

## 1. `guardrail_profiles`

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | uuid | 主键，每个版本独立 ID |
| `workspace_id` | uuid | Workspace 外键 |
| `profile_key` | citext | `^[a-z][a-z0-9-]{1,63}$` |
| `name` | text | 1–100 字符 |
| `description` | text | 最多 500 字符 |
| `version` | integer | 正整数，Workspace + key 内递增 |
| `algorithm_version` | text | 当前 `architecture-guardrails-v1` |
| `thresholds_json` | jsonb | 严格对应 GuardrailThresholds |
| `fingerprint` | text | 对 key/version/algorithm/thresholds 稳定 SHA-256 |
| `created_by` | uuid | 用户外键，可为 NULL |
| `created_at` | timestamptz | 创建时间 |

`(workspace_id, profile_key, version)` 唯一。不提供删除和原地更新。创建请求在事务锁内与最新
版本比较；名称、描述、算法版本和阈值完全相同则幂等复用，否则递增 `version`。

## 2. 快照快照

- `repositories.guardrail_profile_id` 表示当前默认策略，NULL 表示内置 default。
- `repository_snapshots.guardrail_profile_id` 表示创建时的快照。
- Repository 使用 `(workspace_id, guardrail_profile_id)` 复合外键，Snapshot 使用 Profile ID 外键；
  策略版本不删除，因此历史快照可重现。

## 3. 迁移与索引

`0006_guardrail_profiles.sql` 建表、增加两个外键字段，并为 Workspace + key/version 和 Snapshot profile 创建索引。迁移不改写旧 Snapshot；旧值 NULL 按内置 default 解析。

## 4. 事务边界

- 创建 profile 、递增 version 和 audit event 在同一事务。
- 仓库绑定与 audit event 在同一事务。
- Snapshot 创建与 profile 快照写入在同一事务，防止配置竞态。
