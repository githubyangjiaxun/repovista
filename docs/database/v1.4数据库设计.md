# v1.4 数据库设计：批量幂等与通知适配器快照

## Migration `0011_batch_reviews.sql`

### `guardrail_review_batches`

| 列 | 约束 | 说明 |
|---|---|---|
| `id` | UUID PK | 批量操作身份 |
| `workspace_id`/`snapshot_id` | 复合 FK | 租户与快照边界 |
| `idempotency_key` | 1–200 | 调用方幂等键 |
| `request_hash` | `sha256:` + 64 hex | 规范化请求哈希 |
| `result_json` | JSON object | 只存身份、状态、note 长度，不存 note 正文 |
| `created_by`/`created_at` | FK/时间 | 审计摘要与保留 |

唯一约束：`(workspace_id, snapshot_id, idempotency_key)`。结果 JSON 最多 50 项，数据库 CHECK 拒绝数组
和字符串过大，避免把批量请求变成任意存储。

### 现有表扩展

- `workspace_notification_endpoints.adapter text NOT NULL DEFAULT 'generic'`，CHECK 为 `generic/slack`。
- `notification_deliveries.adapter text NOT NULL DEFAULT 'generic'`，创建时复制 Endpoint 当前值。
- Delivery 的事件 CHECK 增加 `guardrail_review.batch_updated`。

## 原子性与并发

- 批量事务先锁定 Snapshot，再锁定幂等记录；同一 key 的并发请求通过唯一约束和重读收敛。
- 逐项 Review 使用既有唯一键；状态未变化不写历史。任何 SQL/校验异常回滚全部 Review。
- Outbox 唯一键仍为 `(endpoint_id,event_key)`；聚合事件 key 使用批量审计 ID。
- Endpoint 删除级联 Delivery，批量幂等记录随 Workspace/Snapshot 删除；不修改已发布 Migration。

## 隐私与保留

批量表、审计 metadata 和通知 payload 不保存 note 正文、源代码、模型 prompt/answer 或凭据。请求哈希使用
规范化 JSON（Finding 按请求顺序保留，note trim 后哈希），不能反推出原始备注。
