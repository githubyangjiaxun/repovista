# 领域模型与数据流

状态：proposal  
适用版本：v0.1

## 1. 核心领域对象

~~~text
User
 └── Workspace
      └── Repository
           └── RepositorySnapshot (固定到一个 Commit)
                ├── SnapshotFile
                │    ├── Symbol
                │    └── CodeChunk
                ├── SymbolEdge
                └── AnalysisJob

RepositorySnapshot
 ├── Conversation
 │    └── Message
 │         └── MessageCitation
 └── ShareReport
~~~

### 不可变边界

- RepositorySnapshot 代表一个固定 Commit，索引完成后内容不可修改。
- 新提交必须创建新的 Snapshot。
- AI 消息必须关联 snapshot_id，不能引用“当前最新”这种不稳定状态。
- 分享页默认固定到 Snapshot，避免同一链接内容悄悄变化。

## 2. 导入到分享的完整流程

~~~mermaid
sequenceDiagram
    participant User as 用户
    participant Web as Web
    participant API as API
    participant DB as PostgreSQL
    participant Worker as Index Worker
    participant Model as AI Provider

    User->>Web: 粘贴 GitHub URL
    Web->>API: POST /v1/repositories
    API->>DB: 创建 Repository + Snapshot + Job
    API-->>Web: 返回 repository_id / job_id
    Worker->>DB: 获取 queued Job
    Worker->>Worker: 安全 clone 固定 Commit
    Worker->>Worker: 扫描文件并计算内容哈希
    Worker->>Worker: Tree-sitter 解析符号和关系
    Worker->>DB: 写入文件、符号、边和 chunks
    Worker->>DB: 标记 Snapshot ready
    Worker-->>Web: SSE 推送进度
    User->>Web: 打开架构地图
    Web->>API: GET /v1/repositories/{id}/map
    API->>DB: 查询分层节点和边
    API-->>Web: 返回地图
    User->>Web: 提问
    Web->>API: POST /v1/conversations/{id}/messages
    API->>DB: 混合检索证据
    API->>Model: 发送问题和证据
    Model-->>API: 流式回答
    API->>DB: 校验并保存 citations
    API-->>Web: SSE 返回答案和引用
    User->>Web: 生成分享页
    Web->>API: POST /v1/share-reports
    API->>DB: 保存固定 Snapshot 的报告
    API-->>Web: 返回 share URL
~~~

## 3. Snapshot 状态机

~~~text
requested
   ↓
cloning ──失败──> failed(retryable)
   ↓
scanning
   ↓
parsing
   ↓
building_graph
   ↓
embedding (可选)
   ↓
ready
~~~

可从任意运行状态进入 cancelled。可重试的失败最多重试 max_attempts 次；超过次数后进入终态 failed。

状态变更必须：

- 在事务中更新。
- 写入结构化日志。
- 带上 job_id、snapshot_id 和 request_id。
- 允许 UI 查询当前状态，而不是只依赖 SSE。

## 4. 用户故事与验收标准

### 故事 A：第一次阅读陌生仓库

作为开发者，我粘贴一个公开 GitHub URL，希望在几分钟内知道项目入口、核心模块和推荐阅读顺序。

验收：

- 不登录可以分析允许的公共仓库。
- 页面显示阶段性进度和可理解的错误。
- 生成至少一个入口节点、三个核心模块和阅读路径（若仓库有足够信息）。

### 故事 B：验证一个架构问题

作为开发者，我想知道某个请求经过哪些函数，并验证答案是否真实。

验收：

- 答案包含文件路径、行号和 Snapshot Commit。
- 点击引用可以打开对应源码。
- 如果没有足够证据，系统明确说“无法确定”。

### 故事 C：分享项目理解结果

作为维护者，我想把架构导览分享给新贡献者。

验收：

- 分享页不要求安装 RepoVista。
- 分享页内容固定到指定 Commit。
- 可以复制 Markdown 或公开链接。

## 5. 失败和降级策略

| 场景 | 行为 |
|---|---|
| 仓库过大 | 在 clone 前拒绝并说明限制 |
| 文件类型不支持 | 忽略该文件并在报告中列出 |
| AST 解析失败 | 保留文件节点，标记符号数据不完整 |
| Embedding 不可用 | 继续提供全文和图检索 |
| AI Provider 超时 | 返回静态检索结果和重试按钮 |
| 引用无法验证 | 丢弃该引用，降低答案可信度或拒答 |
| SSE 中断 | 客户端回退为轮询 Job 状态 |
| Worker 崩溃 | 租约过期后重新领取任务 |

## 6. 版本和兼容性

- API 前缀使用 /v1。
- Snapshot 保存 parser_version、embedding_model 和 prompt_version。
- Parser 或切块逻辑改变时，不覆盖旧结果，创建新索引版本。
- 数据库迁移只能向前，破坏性迁移拆成多个发布步骤。
- 分享页的 URL 不因内部表结构变化而改变。
