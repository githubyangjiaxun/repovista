# 系统架构

状态：proposal  
适用版本：v0.1

## 1. 设计目标

RepoVista 的架构必须同时满足四个要求：

1. 静态分析结果可验证、可追溯到 Commit。
2. AI 是可替换的解释层，不绑定某一家模型。
3. 私有仓库可以 Local-first 运行，源码不会被默认上传。
4. 单人或小团队可以低成本启动，后续仍有水平扩展空间。

因此，v0.1 采用 **模块化单体 + 独立 Worker + PostgreSQL**，而不是一开始拆成微服务。

## 3. 组件职责

### 3.1 Web

- 渲染仓库总览、架构地图、源码面板、问答和分享页。
- 只通过 API 获取业务数据，不直接访问数据库或模型。
- 处理图布局、视口裁剪和本地交互状态。
- 对长任务使用 SSE 展示进度。

### 3.2 API

- 验证请求和权限。
- 创建仓库、快照和分析任务。
- 提供地图、源码、检索和分享接口。
- 负责短事务，不执行长时间解析。
- 统一错误格式、请求 ID 和审计日志。

### 3.3 Index Worker

- 在隔离工作目录中获取 Git 快照。
- 读取安全允许的文本文件。
- 运行 Tree-sitter 解析器。
- 写入文件、符号和边。
- 生成代码块和 Embedding（若启用）。
- 支持取消、重试和幂等。

### 3.4 Retrieval

- 将用户问题转换为检索计划。
- 组合全文、符号图和向量结果。
- 去重、排序并限制上下文 Token。
- 将证据交给模型。
- 校验模型引用后再返回答案。

### 3.5 PostgreSQL

- 保存业务元数据、快照、符号图、任务和对话。
- 使用全文索引和 pgvector 完成第一版检索。
- 通过事务保证跨表状态一致。

### 3.6 Object Storage

- 保存较大的源码快照、导出报告和分享图片。
- 数据库只保存对象键、哈希和元数据。

## 4. 依赖方向

~~~text
apps/web       -> packages/contracts, packages/ui
apps/api       -> packages/domain, packages/contracts, packages/repository
apps/worker    -> packages/domain, packages/git, packages/parser, packages/graph
packages/ai    -> packages/retrieval, external model providers
packages/domain -> no framework, no database driver
packages/repository -> PostgreSQL implementation
~~~

依赖只能从上层指向下层抽象，领域层不能反向依赖 Fastify、Next.js 或具体模型 SDK。

## 5. 运行模式

### 5.1 云端模式

- Web、API 和 Worker 分开部署。
- 公共仓库可以免登录试用。
- 私有仓库需要 OAuth 或 Personal Access Token。
- 模型调用可由用户配置 Provider。

### 5.2 本地模式

~~~text
Docker Compose
├── web
├── api
├── worker
├── postgres + pgvector
├── minio
└── optional: ollama
~~~

本地模式不要求 Redis。任务队列先使用 PostgreSQL 表和租约；只有 Benchmark 证明需要时才引入专用队列。

## 6. 关键架构决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 服务形态 | 模块化单体 + Worker | 降低部署和事务复杂度 |
| 主数据库 | PostgreSQL | 业务、全文和向量能力集中 |
| 图存储 | PostgreSQL 邻接表 | v0.1 查询规模足够，迁移成本低 |
| 解析器 | Tree-sitter | 多语言扩展边界清晰 |
| AI 接口 | OpenAI-compatible Adapter | 避免锁定供应商 |
| 进度推送 | SSE | 比 WebSocket 更简单，适合单向事件 |
| ID | UUIDv7 | 可排序且不暴露连续业务 ID |
| 文件去重 | SHA-256 内容寻址 | 快照之间复用未变内容 |

## 7. 非功能目标

- API 普通请求 p95 < 300ms（不含模型生成）。
- 已索引仓库首屏 < 1.5s 可交互。
- 所有答案引用可定位到固定 Commit、文件和行号。
- Worker 崩溃后任务可以自动接管。
- 分析仓库中的代码永远不被执行。
- 没有模型配置时，静态地图仍然可用。

这些是测量目标，不是未经 Benchmark 验证的宣传语。
