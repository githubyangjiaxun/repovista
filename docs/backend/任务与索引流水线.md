# 任务与索引流水线

状态：proposal  
适用版本：v0.1

## 1. 任务类型

| 类型 | 作用 | v0.1 |
|---|---|---|
| resolve_repository | 解析 URL、确认权限和 Commit | 必须 |
| index_snapshot | 获取和解析固定 Snapshot | 必须 |
| build_embeddings | 生成代码向量 | 可选 |
| generate_overview | 生成项目概览和导览 | 必须 |
| render_share_report | 生成分享报告和 OG 图片 | 必须 |
| cleanup_snapshot | 清理过期临时数据 | 运维 |

## 2. Index Snapshot 阶段

### A：准备

- 校验 canonical URL。
- 创建临时工作目录。
- 应用文件、文件数、仓库大小和超时限制。
- 记录目标 Commit SHA。

### B：获取

- 只获取需要的 ref。
- 默认 shallow clone。
- 不执行 hooks。
- 禁止读取工作目录之外的路径。
- clone 后再次确认 HEAD 等于目标 Commit。

### C：扫描

- 枚举文件。
- 遵循 .gitignore，同时应用系统黑名单。
- 跳过二进制、生成目录和超大文件。
- 计算 SHA-256。
- 记录跳过原因。

默认黑名单：

~~~text
.git/
node_modules/
vendor/
dist/
build/
.next/
.env*
*.pem
*.key
~~~

### D：解析

- 根据扩展名选择 Tree-sitter grammar。
- 先提取文件级 import/export。
- 再提取函数、类、接口、方法和变量。
- 能确认时提取 calls、extends、implements、reads、writes。
- 解析失败不终止整个 Snapshot，记录 warning。

### E：建图

- 为每个符号生成稳定 stable_key。
- 将关系转换为有向边。
- 计算模块重要性、入度、出度和入口候选。
- 保存 evidence（文件、行号、语法节点类型）。
- 用唯一约束去重。

### F：切块和检索

- 优先按符号切块，避免任意截断函数。
- 大符号按语句边界拆分并保留父符号。
- 每个 chunk 保存路径、行号、符号和内容哈希。
- 先写全文索引。
- Embedding 可异步执行；失败不阻塞地图。

### G：概览和完成

- 由规则生成基础摘要。
- 若启用 AI，基于证据生成自然语言概览。
- 校验所有路径和行号。
- 标记 Snapshot ready。
- 删除临时工作目录。

## 3. 任务状态和租约

analysis_jobs 使用数据库行作为队列：

1. Worker 开启事务。
2. 使用 SELECT FOR UPDATE SKIP LOCKED 获取 queued 或租约过期任务。
3. 写入 running、lease_owner 和 lease_expires_at。
4. 提交事务后执行耗时工作。
5. 定期 heartbeat 延长租约。
6. 成功或失败时用条件更新写回状态。

条件更新必须包含当前 lease_owner，避免旧 Worker 覆盖新 Worker 的结果。

## 4. 幂等策略

- 每个阶段写入带 Snapshot 和 parser_version 的结果。
- 重试前清理或复用该阶段的临时结果。
- 文件、符号、边和 chunk 使用内容哈希和唯一约束。
- 完成标记只能从当前 running 状态转换。
- 失败重试不能重复产生 Embedding 费用。

## 5. 进度事件

~~~json
{
  "job_id": "018f...",
  "snapshot_id": "018f...",
  "phase": "parsing",
  "progress": 0.42,
  "processed": 128,
  "total": 342,
  "message": "正在解析 TypeScript 文件"
}
~~~

进度不是严格线性百分比。UI 应同时展示阶段名称和已处理数量。

## 6. 取消

1. API 将 Job 标记为 cancel_requested。
2. Worker 每个批次检查取消标记。
3. 中断 Git、解析和模型调用。
4. 清理临时目录。
5. 将 Job 置为 cancelled。

不能通过直接杀进程作为正常取消机制。

## 7. 资源限制

- 最大仓库字节数。
- 最大文件数。
- 最大单文件字节数。
- 最大解析时长。
- 最大内存。
- 最大 Embedding 数量。
- 最大外部模型 Token。

限制应配置化，并在错误中显示实际限制。

## 8. 失败分类

| 类别 | 示例 | 是否重试 |
|---|---|---|
| 用户输入 | URL 无效、仓库过大 | 否 |
| 外部暂时性 | GitHub 429、模型超时 | 是 |
| 解析局部 | 单个文件语法损坏 | 跳过文件 |
| 资源耗尽 | 内存、超时 | 按策略重试一次 |
| 系统错误 | 数据库不可用 | 是 |
| 安全拒绝 | SSRF、恶意路径 | 否并审计 |

## 9. 观测与告警

- 队列等待时间。
- Job 运行时间。
- 各阶段失败率。
- 租约接管次数。
- 临时目录清理失败。
- 单仓库 CPU、内存和存储。
- 每个模型 Provider 的超时率和成本。

同一 parser 版本在固定 Benchmark 上显著回归时阻止发布。
