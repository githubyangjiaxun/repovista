# RepoVista v0.5 后端开发文档

状态：自动化开发与验收完成；真实 GitHub Fixture 待联调（2026-08-22）

## 1. 后端目标

v0.5 后端要同时保留公开匿名 Demo，并建立可审计的私有仓库访问链。一次完整请求的安全上下文是：

```text
Cookie/Bearer
  -> Principal
  -> Active Workspace + Membership Role/Scope
  -> Repository/Snapshot/Job/Analysis Access Context
  -> Business Operation
  -> Audit Event
```

任何业务方法不得从用户提供的 `workspaceId` 直接信任归属；Workspace 必须来自已验证 Principal 或
GitHub Installation 映射。

## 2. 模块边界

### `packages/github`

新增纯 GitHub 协议模块：

- RS256 App JWT 生成。
- OAuth Code Exchange 与 `/user`、`/user/emails` 读取。
- Installation Metadata、Installation Repository 分页、Installation Token Mint。
- Repository/PR Metadata 读取，同一 Client 同时支持 Public Token 和 Installation Token。
- 内存 Token Cache，Key 为 Installation ID，不对外暴露 Token。
- 统一的 GitHub Error Mapping，Error Details 不包含 Authorization Header/Body。

### `packages/database`

- 身份、Session、API Token、Workspace/Member、Installation、Audit 原子方法。
- `AccessContext` 查询：Repository、Snapshot、Job、PR Analysis、Share 返回 Workspace/Visibility。
- 所有新建私有业务写入都带服务端解析的 Workspace ID 和 Actor ID。

### `apps/api`

- `auth.ts`：Cookie Parse/Serialize、Token Hash、Principal Resolver、CSRF/Origin、Role/Scope Guard。
- `auth-routes.ts`：OAuth、Session、Workspace、Member、API Token。
- `github-routes.ts`：Installation Connect/List/Repositories 和 Webhook。
- `routes.ts`：原有路由改为显式 Access Guard，不再普遍硬编码 Public Workspace。

### `apps/worker` / `packages/git`

- Claimed Job 包含 `githubInstallationId: number | null`。
- Worker 只在进入 Clone 阶段时 Mint Token，并将它传给受限 Clone Credential 参数。
- Clone 结果和 Error 进入业务层前统一红洗。

## 3. Principal 与权限

```ts
type WorkspaceRole = "owner" | "editor" | "viewer";
type ApiScope = "repo:read" | "repo:write" | "workspace:admin";

interface Principal {
  kind: "anonymous" | "session" | "token";
  userId: string | null;
  workspaceId: string;
  role: WorkspaceRole;
  scopes: readonly ApiScope[];
  sessionId: string | null;
  tokenId: string | null;
}
```

角色矩阵：

| 操作 | Anonymous | Viewer | Editor | Owner |
|---|---:|---:|---:|---:|
| 读 Public Workspace Public Repo | 是 | 是 | 是 | 是 |
| 读所属 Workspace Repo/Snapshot/Source | 否 | 是 | 是 | 是 |
| Import / Cancel / Rerun / Embedding / Ask / PR | Public 限额 | 否 | 是 | 是 |
| Create Private Share | 否 | 否 | 是 | 是 |
| Create Public Share | Public Repo 限额 | 否 | 否 | Public Workspace 限定 |
| Manage Members / Workspace | 否 | 否 | 否 | 是 |
| Manage Installation / API Token | 否 | 否 | 否 | 是 |

API Token 还要同时通过 Scope：Viewer 等价操作需 `repo:read`，Editor 操作需 `repo:write`，Owner 管理操作需
`workspace:admin`。Session 拥有当前 Role 的隐式 Scope。

## 4. Cookie、Session 与 CSRF

Cookie：

| Cookie | HttpOnly | SameSite | Secure | 用途 |
|---|---:|---|---:|---|
| `repovista_session` | 是 | Lax | Production 是 | 随机 Session Token |
| `repovista_csrf` | 否 | Lax | Production 是 | Double-submit CSRF Token |
| `repovista_oauth_state` | 是 | Lax | Production 是 | OAuth 一次性 State |

- Cookie 均为 Host-only，`Path=/`；OAuth State Cookie 限制到 Callback Path 也可接受。
- Production 只允许 HTTPS `WEB_ORIGIN`/`API_ORIGIN`，否则启动失败。
- Session 默认 30 天，OAuth State 10 分钟，可配置但有上限。
- Mutation 的 Session Principal 要求 `Origin === WEB_ORIGIN`、Header `X-RepoVista-CSRF` 与 Cookie 原值相同，且
  Hash 与 Session Row 相同。
- Bearer Principal 不读 Cookie，不使用 CSRF。
- `GET /v1/auth/session` 在 Session 有效时轮换/Reset CSRF Cookie，不返回 Session Token。

## 5. OAuth 流程

### `GET /v1/auth/github/start`

Query：`returnTo` 仅允许 Web Origin 内相对路径。

1. 生成 32-byte State。
2. 保存 State Hash、Return Path、Expiry。
3. 设置 State Cookie。
4. 302 到 `https://github.com/login/oauth/authorize?client_id=&state=&scope=read:user user:email`。

### `GET /v1/auth/github/callback`

1. Query State 必须与 Cookie 原值完全一致。
2. 数据库原子消费 State，拒绝重放和过期。
3. 用 Code 换取临时 GitHub User Token，只用于读取当前 User/Primary Verified Email。
4. 不保存 GitHub User Token。
5. 原子 Upsert User/Identity/Personal Workspace/Membership，创建 Session。
6. 设置 Session/CSRF Cookie，清除 State Cookie，302 回 Return Path。

OAuth 失败回调重定向 `/auth/error?code=<stable-code>`，不把 GitHub 原始响应放入 URL。

| GET | `/v1/auth/session` | Optional | Auth Session/Capabilities |

### Repository 变更

`POST /v1/repositories` Body：

```json
{
  "url": "https://github.com/acme/private-service",
  "installationId": 12345678,
  "ref": "main",
  "ignore": ["dist"]
}
```

- Anonymous 不允许 `installationId`，写入 Public Workspace。
- Authenticated 写入 Active Workspace。带 Installation ID 时必须验证归属并从 GitHub API 获取真实
  `providerRepoId/visibility/defaultBranch/cloneUrl`。
- 不带 Installation ID 的 Authenticated Import 仅按 Public Repository 处理。
- Job 返回前 Repository 和 Installation 归属必须在一个事务内确认。

`RepositorySummary` 新增 `visibility`、`workspaceId`、`githubInstallationId`（只对成员返回）。

### Share 变更

`POST /v1/share-reports` 可接受 `visibility: "private" | "public"`。服务端最终决策：

- Private Workspace/Repository：只能 `private`。
- Public Workspace Public Repository：可 `public` 或 `private`。
- 省略时：Private Context -> private，Public Context -> public。

`GET /v1/share-reports/:slug` 先查 Visibility；Public 可匿名，Private 要求 Repository Access。

## 7. GitHub Webhook

所有 Event 首先进入幂等 Delivery 表。支持：

- `ping`：记录 ignored/accepted 状态，不更改权限。
- `installation created/unsuspend/suspend/deleted`：只更新已连接 Installation 状态；未连接 Installation 等待 Setup Callback。
- `installation_repositories added/removed`：更新 Sync Time；Removed Repository 停止 Auto Update，但不删除历史 Snapshot。
- `push`：
  - deleted ref 忽略；
  - non-default branch 忽略；
  - zero SHA 忽略；
  - Private 必须 Installation ID + Provider Repo ID 匹配已导入 Repository；
  - Public 仍可使用 Public Workspace 旧流程，但有 Installation 时优先精确归属。
- `pull_request`：v0.5 只在 `opened/synchronize/reopened` 且 Repository 已导入时记录审计与可选自动分析；
  默认不自动消耗 AI。

## 8. 错误码

| Code | HTTP | 语义 |
|---|---:|---|
| `AUTH_REQUIRED` | 401 | 需要 Session/Bearer |
| `AUTH_INVALID` | 401 | Token/Cookie 无效 |
| `AUTH_EXPIRED` | 401 | 凭据过期 |
| `CSRF_INVALID` | 403 | Origin/Cookie/Header 失配 |
| `WORKSPACE_FORBIDDEN` | 403 | 已知 Workspace 中 Role/Scope 不足 |
| `RESOURCE_NOT_FOUND` | 404 | 资源不存在或对 Principal 不可见 |
| `GITHUB_AUTH_DISABLED` | 503 | OAuth 配置不完整 |
| `GITHUB_APP_DISABLED` | 503 | App JWT/Installation 配置不完整 |
| `GITHUB_INSTALLATION_NOT_FOUND` | 404 | Installation 未连接到 Workspace |
| `GITHUB_INSTALLATION_SUSPENDED` | 409 | Installation 被 Suspend |
| `GITHUB_REPOSITORY_NOT_GRANTED` | 403 | Repository 不在 Installation 授权集 |
| `GITHUB_TOKEN_FAILED` | 502/503 | 生成短期 Token 失败 |

错误不包含 Cookie、Authorization Header、GitHub Response Header、Private Key、Access Token 或 Clone 凭据环境变量。

## 9. 可观测性

- Request Log 只记录 Principal Kind、User ID、Workspace ID、Route、Status、Latency；不记录 Token。
- Audit Metadata 仅允许结构化 Allow-list 字段，不保存源码、Email 全文或 GitHub API Payload。
- GitHub Token Cache 可记录 hit/miss/expiry second，不记录 Token。
- Clone Error 只输出稳定 Domain Code 和经过红洗的 Git stderr。
