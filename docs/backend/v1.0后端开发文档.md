# v1.0 后端开发文档：Explanation History and Comparison

状态：已实现并验收（2026-08-25）

## 1. 逻辑 Finding 身份

新增服务端函数 `guardrailFindingSubjectKey(finding)`，与 Guardrails Snapshot baseline 的配对键
共用同一实现：

- `dependency_cycle`：规则 + 有序 package 集合；
- `large_file` / `parse_failure`：规则 + path；
- `large_symbol` / `high_fan_in`：规则 + path + symbol；
- `unresolved_import`：规则 + path + startLine + target。

该键不包含 Snapshot ID、Finding fingerprint、severity 或可变化的统计值，因此能连接跨 Snapshot 的
同一逻辑对象；它不是安全边界，Workspace/Repository 外键和访问检查仍是授权依据。

## 2. API

### `GET /v1/snapshots/{snapshotId}/guardrails/explanations`

Query：

- `findingId`：必填，当前 Snapshot 报告中的精确 Finding ID；
- `limit`：默认 20，范围 1～50；
- `cursor`：可选，服务端生成的有界 opaque cursor。

处理顺序：

1. 检查 Snapshot 访问权限和 Ready 状态。
2. 使用 Snapshot 固定 Profile 重新计算 Guardrails 报告。
3. 精确匹配 `findingId`，服务端计算 `subjectKey`。
4. 只查询同 Workspace、同 Repository、同 `subjectKey` 的持久化解释。
5. 按 `createdAt DESC, id DESC` 返回摘要和 `nextCursor`。

摘要包含 Explanation ID、Snapshot/Commit/parser/algorithm、Profile fingerprint、固定 Finding 摘要、
Answer status/summary/provider/model/step 与 citation 数、prompt 和创建时间；不返回 citation quote。

### `GET /v1/repositories/{repositoryId}/guardrails/explanations/compare`

Query：`baseExplanationId`、`headExplanationId`，两者必须不同。

服务端在同一个 Repository/Workspace 范围读取两条完整解释，并要求 `subjectKey` 相同。结果包含：

- base/head 完整已验证解释；
- provenance 各字段是否完全相同；
- Finding severity、message、location、metric、evidence 是否变化；
- Answer status、summary、steps、limitations、citations 是否变化；
- 总体 `changed` 布尔值。

所有比较使用稳定结构化序列化；不调用 AI Provider，不产生“更好/更差”的推断。

## 3. 权限、缓存和错误

- 历史入口沿用 `requireSnapshotAccess`；比较入口沿用 `requireRepositoryAccess`。
- 私有 Repository 响应为 `private, no-store`；公开 Demo 为
  `public, max-age=0, must-revalidate`。
- Viewer 可以读取；两个 GET 不需要 CSRF，也不消耗 AI 生成限流。
- 稳定错误码：`GUARDRAIL_FINDING_NOT_FOUND`、`GUARDRAIL_EXPLANATION_NOT_FOUND`、
  `GUARDRAIL_EXPLANATION_COMPARISON_INCOMPATIBLE`、`PAGINATION_CURSOR_INVALID`。
- 跨 Workspace/Repository 的 Explanation ID 返回 Not Found，不能泄露记录是否存在。

## 4. CLI

- `repovista guardrails explanations history <snapshot-id> <finding-id> [--limit <n>] [--json]`
- `repovista guardrails explanations compare <repository-id> <base-id> <head-id> [--json]`

人类可读输出显示 Commit、status、provider/model、prompt、Profile fingerprint 和变化矩阵；JSON 输出
严格使用共享 Contract。
