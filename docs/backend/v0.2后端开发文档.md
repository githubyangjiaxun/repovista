# v0.2 后端开发文档

状态：已冻结，待实现

## 1. 后端边界

Fastify 仍只处理短请求、验证、查询和任务入队；Clone、Scan、Parse、Link 与 Persist 仍由 Worker 执行。GitHub Webhook 只负责验签、事件筛选和幂等创建 Job，不在 HTTP 生命周期内 Clone 仓库。

## 2. 增量索引流水线

### 基线选择

Worker 在 Clone/Scan 后向 Store 请求：

```text
latest Ready Snapshot
where repository_id = current repository
and parser_version = current parser version
and id != current snapshot
order by ready_at desc
```

Store 返回基线的文件 Blob Hash 以及可还原的 ParsedFile。不得把 v0.1 Parser 结果复用到 v0.2 组合 Parser。

### Planner

Planner 是无数据库依赖的纯函数：

- Current Hash == Base Hash 且 Base Parse Status == parsed：复用 ParsedFile。
- Current Parseable File 新增或 Hash 变化：进入 Parser。
- Current Unsupported File：保存文件，但不进入 Parser。
- Base Path 在 Current 中不存在：计入 Deleted。
- 同路径语言发生变化：视为 Changed，不复用。

合并 `reused + newlyParsed` 后，对完整 ParsedFile Set 再运行 Import Linking。完成对象必须携带：

```ts
{
  indexMode: "full" | "incremental";
  baseSnapshotId: string | null;
  baseCommitSha: string | null;
  treeHash: string;
  stats.indexing: {
    scannedFiles: number;
    changedFiles: number;
    reusedFiles: number;
    parsedFiles: number;
    deletedFiles: number;
  };
}
```

Tree Hash 使用排序后的 `path + NUL + content_hash + LF` 计算 SHA-256，便于证明同一文件树，而不依赖平台时间戳。

### Lease 安全

- 读取基线、批次解析、Link 前、Persist 前都必须经过 Lease Checkpoint。
- 只有持有有效 Lease 的 Worker 能提交完整 Snapshot。
- Persist 事务写入 `base_snapshot_id/index_mode/tree_hash` 后再把 Snapshot 设为 Ready。
- 失败或 Lease Lost 不得更新 Repository Latest Ready Pointer。

## 3. Parser Adapter

`packages/parser` 暴露统一入口和组合 `PARSER_VERSION`：

```text
typescript/javascript -> TypeScript Adapter
python                -> Python Adapter
other                 -> unsupported
```

每个 Adapter 都输出领域层 ParsedFile，不把 Tree-sitter Node 泄露到 Worker/Database。稳定键必须包含文件路径、Kind、Qualified Name 和 Signature Hash；相同源码重复解析得到相同 Key。

Python 最低语义：

- Module、Function、Class、Method、Variable。
- Import、Call、Extends。
- Decorated Function/Class 不能丢失声明范围。
- `from .service import run` 和 `from package.service import run` 能解析仓库内模块。
- 无法唯一解析的目标保留 `unresolved_target`，不能猜测一条错误边。

## 4. GitHub Webhook

### 配置

```text
GITHUB_WEBHOOK_SECRET=<high-entropy secret>
GITHUB_APP_SLUG=<optional display slug>
```

Secret 不出现在 Status API、日志、错误详情或 OpenAPI Example 中。

### 请求验证顺序

1. 限制请求 Content-Type 与 Body Size。
2. 读取原始 Body Buffer。
3. 验证 `X-GitHub-Delivery` 格式与长度。
4. 验证 `X-GitHub-Event`。
5. 计算 `sha256=<hex>`，使用恒定时间比较 `X-Hub-Signature-256`。
6. 签名成功后才解析 JSON 和读取 Payload 字段。
7. 对 `push` 校验 Public、默认分支、非删除、40 位 `after` SHA 和 canonical GitHub URL。
8. 在一个数据库事务中记录 Delivery，并创建 Repository/Snapshot/Job。

重复 Delivery 返回第一次处理结果并设置 `duplicate: true`，不再创建记录。未知事件、非默认分支、删除 Push 返回 `ignored` 并记录原因。

## 5. API 变更

### `GET /v1/integrations/github`

返回非敏感能力：

```json
{
  "enabled": true,
  "appSlug": "repovista-local",
  "events": ["ping", "push"],
  "scope": "public-repositories"
}
```

### `POST /v1/integrations/github/webhooks`

- Header：`X-GitHub-Delivery`、`X-GitHub-Event`、`X-Hub-Signature-256`。
- Enqueued 返回 202；Ping/Ignored/Duplicate 返回 200。
- 错误签名返回 401，未配置返回 503，Payload Contract 错误返回 400。

### `GET /v1/snapshots/:snapshotId/exports/markdown`

- Ready Snapshot only。
- `Content-Type: text/markdown; charset=utf-8`。
- `Content-Disposition: attachment`。

### `GET /v1/snapshots/:snapshotId/exports/svg`

- Query：`level=package|file|symbol`，默认 `package`。
- Ready Snapshot only；最多导出 250 Node。
- `Content-Type: image/svg+xml; charset=utf-8`。

四个 Operation 必须同步共享 Contract（适用部分）、OpenAPI、API Test 和文档。文本/图片响应不使用 JSON Success Envelope，但错误仍使用统一 ApiFailure。

## 6. Exporter

新建无框架依赖的 `packages/exporter`：

- 输入 Repository、Snapshot、GraphView 和 File Summary。
- Markdown 生成 Provenance、Stats、Language、Package Map、Reading Path 和限制说明。
- SVG 生成 Title、Commit、Legend、Node、Edge；布局只由排序后的 Node/Edge 决定。
- XML/Markdown 中的仓库控制字符串必须按目标格式转义。
- 不调用 Model Provider，不读数据库，不访问网络。

## 7. 错误码

- `GITHUB_APP_DISABLED`
- `GITHUB_WEBHOOK_HEADERS_INVALID`
- `GITHUB_WEBHOOK_SIGNATURE_INVALID`
- `GITHUB_WEBHOOK_PAYLOAD_INVALID`
- `EXPORT_NOT_AVAILABLE`
- 继续复用 `SNAPSHOT_NOT_FOUND`、`SNAPSHOT_NOT_READY`、`REPOSITORY_HOST_NOT_ALLOWED`。

Error Handler 必须把签名失败映射 401、Disabled 映射 503；不得用 500 隐藏可预期配置状态。
