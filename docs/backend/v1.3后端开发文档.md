# v1.3 后端开发文档：Review 历史与签名通知

## 设计原则

Review 当前状态仍由 `guardrail_reviews` 提供；历史只从 append-only `audit_events` 查询。通知 outbox
在 Review 事务内写入，Worker 之外的请求线程不发起下游网络请求。

## API

### Review 历史

`GET /v1/snapshots/{snapshotId}/guardrails/reviews/history`

- 需要已认证的 Workspace 成员；Viewer 可读，匿名公开读取不返回协作时间线。
- Query：`findingId`（可选）、`status`（可选）、`limit`（1–50）、`cursor`。
- 结果按 `audit id DESC`，返回 `entries` 与 `nextCursor`。
- 每项包含 `fromStatus/toStatus`、`fromNoteLength/toNoteLength`、`noteChanged`、操作者摘要和时间；不含备注正文。
- 服务端重新检查 Snapshot 为 Ready，并验证审计 metadata 的 Snapshot/subject key。

### Notification Endpoint

路径：`/v1/workspaces/{workspaceId}/notification-endpoints`

- `GET`：Owner/Editor 可读 Endpoint 元数据；响应不返回签名秘密。
- `POST`：仅 Owner；返回一次性 `signingSecret`，之后只能通过删除并重建轮换。
- `PATCH`：仅 Owner；可改名、URL、事件订阅和 enabled 状态。
- `DELETE`：仅 Owner；删除 Endpoint 并级联未完成投递，审计保留。
- `POST /{endpointId}/test`：Owner/Editor 可请求一个不含敏感内容的测试投递。

支持事件：`guardrail_review.updated`、`guardrail_review.cleared`。

### 投递查询

`GET /v1/workspaces/{workspaceId}/notification-deliveries`

成员可读，按 Workspace 游标分页；可按 Endpoint/status 过滤。错误信息经过截断和脱敏，不返回请求体或
签名秘密。

## 授权与安全

- Workspace 参数必须等于当前 Principal Workspace；Endpoint 管理要求 Owner 和 `workspace:admin`（Session
  仍需 CSRF），投递查看要求成员读取权限。
- Review 历史不接受客户端提供的 subject key；服务端从当前 Report 与审计 metadata 交叉验证。
- API 只排队投递，禁止同步请求外部 URL；Worker 使用 DNS/IP 检查、`redirect: error`、HTTPS（生产）和超时。
- 签名秘密由 `NOTIFICATION_SIGNING_SECRET` 与 Endpoint ID 派生，不写数据库；配置轮换会使既有接收方秘密失效。

## 错误码

`AUTH_REQUIRED`、`AUTH_SESSION_REQUIRED`、`WORKSPACE_FORBIDDEN`、`PAGINATION_CURSOR_INVALID`、
`GUARDRAIL_REVIEW_HISTORY_UNAVAILABLE`、`NOTIFICATION_CONFIG_INVALID`、`NOTIFICATION_ENDPOINT_NOT_FOUND`、
`NOTIFICATION_URL_INVALID`、`NOTIFICATION_HOST_BLOCKED`、`NOTIFICATION_DELIVERY_UNAVAILABLE`。
