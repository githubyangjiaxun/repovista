# v0.8 后端开发文档：Guardrails Policy Profiles

## 1. 边界与不变式

- 策略只能修改现有 Guardrails 阈值；规则 ID、Finding 语义和执行代码由版本固定。
- 策略版本是不可变读模型，不允许 `PATCH`/删除。
- Snapshot 创建时将 repository 当前 profile ID 写入快照；报告不读取仓库当前配置。
- 任何报告和比较都不包含源码正文或凭据。

## 2. Contracts

`GuardrailProfile` 包含：

```text
id, workspaceId?, profileKey, name, description, version,
algorithmVersion, thresholds, fingerprint, builtIn, createdBy?, createdAt
```

`GuardrailReport.profile` 是可选的 profile provenance；新 API 对新 Snapshot 始终返回值，旧 Snapshot
或旧客户端数据可兼容 `null`。`Snapshot.guardrailProfileId` 同样保持 nullable/optional，以兼容
迁移前的历史记录。

## 3. Store 与迁移

`guardrail_profiles` 表为 Workspace 范围，使用 `(workspace_id, profile_key, version)` 唯一约束。
`repositories.guardrail_profile_id` 只记录当前绑定；`repository_snapshots.guardrail_profile_id`
记录创建时快照。內置 default 不写入表，`NULL` 统一解析为内置 ID。

Store 提供：

- `listGuardrailProfiles(workspaceId)`
- `getGuardrailProfile(profileId, workspaceId)`
- `createGuardrailProfile(input)`（内容相同幂等复用，内容变化才递增版本）
- `getRepositoryGuardrailProfile(repositoryId, workspaceId)`
- `assignRepositoryGuardrailProfile(repositoryId, workspaceId, profileId, actor)`
- `getSnapshotGuardrailProfile(snapshotId)`

## 4. HTTP 路由

### `GET /v1/guardrail-profiles`

返回当前 Workspace 可见的内置 default 和自定义版本，按 key 、version 降序排序。

### `POST /v1/guardrail-profiles`

请求字段：`profileKey`、`name`、`description` 和 `thresholds`。只有 editor/owner 或
`repo:write`/`workspace:admin` Token 可创建。请求不接受任意规则代码、prompt 或 model 字段。

### `GET /v1/guardrail-profiles/{profileId}`

内置 default 对所有 Workspace 可读；自定义 profile 必须属于当前 Workspace。无权限统一 404。

### `GET/PUT /v1/repositories/{repositoryId}/guardrail-profile`

GET 返回当前绑定；PUT 请求 `{ profileId }` 并执行 Repository Access Check。绑定 default 时使用内置 ID，仓库字段可清空。

## 5. 报告管道

`loadGuardrailReport` 的顺序必须是：

1. Snapshot Access Check。
2. 检查 Ready 和完整 Commit。
3. 从 Snapshot 快照解析 profile（`NULL` → default）。
4. 将不可变 profile（其中包含 thresholds）传入 `buildGuardrailReport`。
5. 返回 profile provenance 和指纹。

`compareGuardrailReports` 除了 algorithm/threshold 外，还要校验 profile fingerprint；不一致映射
`GUARDRAIL_COMPARISON_INCOMPATIBLE` → HTTP 409。

## 6. 安全与观测

- 记录 `guardrail_profile.create` 和 `repository.guardrail_profile_assign` audit event。
- 不在日志中记录不必要的用户凭据。
- 私有策略、策略绑定和使用该策略的报告继承 `private, no-store`。
