# v0.3 后端开发文档

## 模块边界

- `packages/contracts`：PR 请求、Analysis 状态、Impact、Evidence、分页和错误 schema。
- `packages/domain`：Go/PR/Impact 类型、风险算法输入、状态机和不变量断言。
- `packages/parser`：Go Tree-sitter adapter；不访问数据库或网络。
- `packages/git`：Go module 识别、公共仓库 Clone/Scan；不执行仓库代码。
- `packages/graph`：跨语言 Import Linking、反向邻接和影响 BFS 的纯函数。
- `packages/database`：Migration、快照复用、PR Analysis 事务、分页查询和幂等。
- `apps/worker`：租约化 `pull_request_analysis` job，复用/等待双快照并调用 impact calculator；不在租约中重复拉取 GitHub 元数据。
- `apps/api`：验证输入、鉴权边界、GitHub 元数据拉取、任务投递和固定证据响应。

## PR 状态机

HTTP 创建请求先完成 `fetching_metadata` 预检，再持久化 `queued → ensuring_base_snapshot → ensuring_head_snapshot → computing_impact → ready`；异常进入 `failed`，可重试错误保留 retryable 标记并使用 `available_at` 退避。取消在计算与完成事务前都要检查；ready 后结果不可修改。

## Snapshot 复用

按 `(repository, commitSha, parserVersion)` 查找 Ready Snapshot。若不存在，创建普通 `index_snapshot` job；PR job 等待其完成。不得用 requested/failed Snapshot 作为影响输入，不得用不同 Parser Version 的旧快照。

## GitHub client

请求 `GET /repos/{owner}/{repo}/pulls/{number}` 和分页 `GET .../files`；校验响应 owner/name、PR number、base/head SHA、文件路径和变更状态。使用 `If-None-Match` 可选缓存；429/403 rate limit 记录 retry-after 并标记可重试。Token 是可选只读配置，绝不写库。

## 影响算法

1. 用 Base/Head 的 `path + blobHash` 构建文件差异。
2. 用 `stableKey`、`contentHash` 和行范围构建符号差异。
3. 对 changed symbols 在 Head 图反向遍历 `calls/imports/extends/implements/reads/writes`；删除符号在 Base 图遍历。
4. BFS 去重 `(snapshot, symbolId)`，记录最短距离和边序列，最大深度 5、节点 2,000；超限返回 `truncated=true`。
5. 用公开 API 线索（module export/interface/Go exported name）和语言权重计算风险；所有中间值落 JSON，便于前端解释。
6. Evidence 由数据库行拼出，包含 source snapshot、commit、path、symbol、range、edge 和 path；任何缺失均降级为 unknown，而不是虚构。

## API 实现纪律

- 每个新 Fastify route 立即同步 `openapi/openapi.json` 和 contract schema。
- 所有 ID、SHA、PR number、cursor、limit、depth 先 Zod parse；路径走现有安全相对路径校验。
- 每个响应检查 Repository → Analysis → Snapshot 归属；错误使用稳定 DomainError code。
- SSE 复用 v0.2 的 Last-Event-ID 语义，终态后关闭连接。
- API 不直接执行 Git；所有长任务由 Worker 租约处理。
