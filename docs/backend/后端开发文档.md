# 后端开发文档

状态：proposal  
适用版本：v0.1

## 1. 后端目标

后端负责把 Git 仓库转换为可查询、可验证、可分享的 Snapshot，并为前端提供稳定 API。后端不承担 UI 状态，不让模型直接决定事实，也不在 Web 请求中执行长时间解析。

## 2. 推荐技术栈

- Runtime：Node.js LTS。
- Language：TypeScript，开启 strict。
- HTTP：Fastify。
- Schema：TypeBox 或 Zod，项目初始化时统一选择。
- API 文档：OpenAPI 3.1。
- Database：PostgreSQL + pgvector。
- Git：受限 Git CLI 封装，未来可替换 libgit2。
- Parser：Tree-sitter。
- Logging：Pino JSON。
- Telemetry：OpenTelemetry。
- Tests：Vitest + Testcontainers。

## 4. 请求生命周期

~~~text
request
  -> request-id
  -> auth
  -> rate limit
  -> schema validation
  -> permission check
  -> use case
  -> repository / external service
  -> response mapper
  -> structured log
~~~

每个请求都必须带 request_id。响应头返回 X-Request-ID，便于用户报告问题。

## 5. 错误模型

统一返回：

~~~json
{
  "error": {
    "code": "REPOSITORY_TOO_LARGE",
    "message": "仓库超过当前版本支持的大小限制。",
    "details": {
      "max_files": 10000,
      "request_id": "018f..."
    },
    "retryable": false
  }
}
~~~

错误码分层：

- AUTH_*：身份和权限。
- REPOSITORY_*：仓库输入和来源。
- SNAPSHOT_*：快照状态。
- JOB_*：后台任务。
- AI_*：模型或检索。
- RATE_LIMITED：限流。
- INTERNAL_ERROR：对外隐藏内部细节。

不要把原始 Git、数据库或模型错误直接返回给用户。原始错误只写入受保护日志。

## 6. 身份与权限

### v0.1

- 公共仓库的只读示例可以匿名访问。
- 创建分析任务需要匿名配额或登录后的 workspace。
- 私有仓库使用 GitHub OAuth 或短期 Token。
- API 每次读取资源都检查 workspace 归属。

### 角色

| 角色 | 读取 | 导入/重索引 | 分享管理 | 成员管理 |
|---|---|---|---|---|
| owner | 是 | 是 | 是 | 是 |
| editor | 是 | 是 | 是 | 否 |
| viewer | 是 | 否 | 按策略 | 否 |

不要只在前端隐藏按钮；权限检查必须位于 use case 或 repository 查询边界。

## 7. URL 和仓库安全

导入 URL 时：

- 只允许 HTTPS。
- 解析后校验 hostname 白名单。
- 禁止 file、ssh 和自定义协议。
- 拒绝 URL 中的用户名、密码和 Token。
- 禁止重定向到内网地址。
- DNS 解析后拒绝私网、回环、链路本地地址。
- 限制重定向次数。
- clone 使用固定临时目录和资源限制。

Worker 永远不执行仓库脚本，不运行 package manager install，不读取工作目录之外的路径。

## 8. 速率限制

| 操作 | 匿名 | 登录用户 |
|---|---:|---:|
| 创建公共仓库分析 | 3 / 小时 | 30 / 小时 |
| 地图查询 | 120 / 分钟 | 600 / 分钟 |
| AI 问答 | 10 / 小时 | 按 workspace 配额 |
| 分享页创建 | 10 / 小时 | 100 / 小时 |

具体数值在压测后调整。模型调用还要有并发上限、Token 上限和费用预算。

## 9. 幂等与并发

幂等键：

- 导入：workspace_id + canonical_repo_url + commit_sha + parser_version。
- Webhook：provider delivery ID。
- 分享页：snapshot_id + report_type + content_version。

并发控制：

- 同一 repository 同时只允许一个 active snapshot job。
- 同一 snapshot 的索引步骤使用数据库状态和租约保护。
- 取消任务必须是幂等操作。
- 写入符号边时使用唯一约束防止重复。

## 10. API 版本规则

- 外部 API 使用 /v1 前缀。
- 新增字段默认向后兼容。
- 删除或改变语义必须新建版本或经历弃用期。
- OpenAPI 文件进入仓库并在 CI 中校验。
- API 类型从 schema 生成，避免前后端手写两份。

## 11. 可观测性

每个请求、Job 和模型调用至少记录：

- request_id / job_id。
- workspace_id（日志脱敏后）。
- repository_id / snapshot_id。
- 操作名、耗时、状态、错误码。
- Token 和成本（模型调用）。

禁止记录原始 Token、完整私有源码、密码和敏感 Prompt。

关键指标：

- API p50/p95/p99。
- 导入成功率。
- 各索引阶段耗时。
- Job 重试次数。
- AI 引用验证失败率。
- 模型首 Token 延迟。
- 每仓库分析成本。

## 12. 开发顺序

1. 配置、健康检查、数据库连接和错误处理。
2. Repository / Snapshot 创建接口。
3. Job 查询和 SSE 进度接口。
4. 地图、源码和搜索查询。
5. 对话、检索和引用。
6. 分享页。
7. OAuth、限流、审计和指标。
