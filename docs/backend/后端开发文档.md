# 后端开发文档

状态：v0.1 已实现基线

## 1. 服务边界

后端由两个独立进程组成：

- `apps/api`：Fastify，同步 HTTP、SSE、检索、模型调用和分享内容生成。
- `apps/worker`：PostgreSQL Job Loop，执行 Clone、扫描、解析、建图和持久化。

长任务不能放进 API Request。两个进程只通过 PostgreSQL 状态协作，没有内存队列或 Redis。

## 2. API 结构

```text
apps/api/src/
├── server.ts   配置、可选 Migration、监听端口
├── app.ts      Fastify、CORS、限流、错误处理、Health
└── routes.ts   v1 路由和 Use Case 编排
```

共享实现位于：

```text
packages/config     环境变量 Zod Schema
packages/contracts  HTTP 数据结构
packages/database   Store、Pool、Migration
packages/domain     DomainError 与领域类型
packages/git        GitHub URL 和安全 Clone/Scan
packages/graph      多级图构建
packages/retrieval  Query Token 与 RRF
packages/ai         Provider 与 Answer Verification
```

## 3. 请求处理顺序

1. Fastify 分配或接收 Request ID。
2. CORS 与 Rate Limit 执行。
3. Route 使用 Zod 解析 Params/Query/Body。
4. Ref 和仓库路径执行额外安全校验。
5. Store 读取或写入 PostgreSQL。
6. 返回统一成功信封，或由全局 Error Handler 返回失败信封。

不要在 Route 中直接拼 SQL；数据库行为进入 `RepoVistaStore`。不要让 Store 返回 Fastify Reply 或 HTTP Status。

## 4. 响应和错误

普通成功响应：

```json
{
  "data": {},
  "meta": { "requestId": "request-id" }
}
```

失败响应：

```json
{
  "error": {
    "code": "SNAPSHOT_NOT_READY",
    "message": "The requested snapshot is not ready yet.",
    "retryable": true,
    "requestId": "request-id"
  }
}
```

`DomainError` 保存稳定 Code、Message、Details 和 Retryable。Zod 失败转换为 `VALIDATION_FAILED`。未知异常返回通用服务端错误，不能泄露 SQL、密钥、源码或临时路径。

Health 是例外：`/v1/health/live` 和 `/v1/health/ready` 直接返回 `{status}`，方便容器探针。

## 5. Request ID、CORS 与限流

- 所有响应头返回 `X-Request-ID`。
- Browser Origin 由 `WEB_ORIGIN` 控制。
- API 允许 `Content-Type`、`X-Request-ID` 和 `Last-Event-ID` 等需要的 Header。
- 匿名导入、问答和分享创建分别使用每小时配置上限。
- 列表、读取、Health 和 Share 读取当前不计入这三个业务限额。

v0.1 没有身份认证。`users/workspaces` 是数据库演进边界，不是已启用的 HTTP 权限系统。

## 6. 配置

所有配置由 `packages/config` 解析，非法值在进程启动时失败。主要变量：

| 变量 | 默认值 | 使用者 |
|---|---|---|
| `API_PORT` | `4000` | API |
| `WEB_ORIGIN` | `http://localhost:3000` | API CORS |
| `DATABASE_URL` | 本地 repovista | API/Worker |
| `DATABASE_MAX_CONNECTIONS` | `10` | API/Worker |
| `MODEL_PROVIDER` | `fake` | API |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | API |
| `OPENAI_COMPATIBLE_BASE_URL` | 空 | API |
| `OPENAI_COMPATIBLE_API_KEY` | 空 | API |
| `CHAT_MODEL` | Provider 默认值 | API |
| `REPOSITORY_ALLOWED_HOSTS` | `github.com` | API |
| `REPOSITORY_MAX_FILES` | `10000` | Worker |
| `REPOSITORY_MAX_BYTES` | `524288000` | Worker |
| `SOURCE_FILE_MAX_BYTES` | `2097152` | Worker |
| `JOB_TIMEOUT_SECONDS` | `900` | Worker |
| `JOB_POLL_INTERVAL_MS` | `1000` | Worker |
| `JOB_LEASE_SECONDS` | `30` | Worker |
| `WORKER_ID` | `local-worker` | Worker |
| `RUN_MIGRATIONS_ON_START` | `false` | API/Worker |

Compose 让 API 自动 Migration，Worker 不重复 Migration。

## 7. 数据库访问

`RepoVistaStore` 负责：

- 创建 Repository/Snapshot/Job。
- Claim/Renew/Fail/Cancel/Complete Job。
- 写入和读取 Snapshot 图、源码、文件、检索证据。
- 保存问题、验证后答案和 Citation。
- 创建和读取 Share Report。

跨表完成索引必须在一个事务内执行。所有动态值使用参数化 SQL。列表使用稳定排序和 Cursor；Source 查询同时过滤 Snapshot 和 Path。

## 8. 检索与问答编排

API 将原问题与最多六个 Query Token 并行搜索，每组取最多 12 条，再用 Reciprocal Rank Fusion 合并。单条 Evidence 内容在发给模型前限制约 8000 字符并重新计算内容哈希。

Provider 只产生 Draft。`verifyModelAnswer`：

- 删除不存在的 Evidence ID。
- 删除没有合法 Evidence 的 Step。
- 从服务端 Evidence 重建 Citation。
- 无 Citation 时强制 Refused。
- 部分 Step 无证据时降级 Partial 并增加 Limitation。

## 9. OpenAPI 纪律

`openapi/openapi.json` 是机器可读 Contract。`scripts/validate-openapi.mjs` 启动应用、收集 Fastify Route，并比较 Method/Path 集合，当前应为 17 个 Operation。

新增或删除路由时必须同时：

1. 更新 Route。
2. 更新共享 Contract。
3. 更新 OpenAPI。
4. 增加行为测试。
5. 运行 `pnpm openapi:check` 和 `pnpm check`。

## 10. 测试

- API Unit/Integration-style Test 使用内存 Store Fake 和 Fastify Inject，不监听端口。
- Database Integration Test 在真实 PostgreSQL 上执行完整持久化、图、源码、搜索、答案和分享路径。
- E2E 在浏览器网络层 Mock API，验证 UI Contract。
- 发布 Smoke Test 使用真实 API/Worker/PostgreSQL 和公共仓库。

单元测试通过不等于数据库或容器链路已经验证，发布审计必须运行对应层级的证据。
