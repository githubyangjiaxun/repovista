# v1.4 后端开发文档：原子批量 Review 与通知适配器

## API 契约

### 批量 Review

`POST /v1/snapshots/{snapshotId}/guardrails/reviews/batch`

- 需要 Session 或带 `repo:write` 的 Token；Session mutation 仍校验 CSRF，Viewer 和 Bundled Demo 拒绝。
- 请求头 `Idempotency-Key` 可选；存在时长度 1–200，只接受可打印 ASCII（不含控制字符）。未提供时
  服务端生成一次性 key，因此重试必须由调用方提供 key 才能收敛。
- 请求体严格为 `{items: [{findingId, status, note}]}`，数组 1–50；Finding ID 不得重复。
- `status` 支持 `unreviewed`、`acknowledged`、`accepted_risk`、`false_positive`。`unreviewed` 等价于
  清除当前 Review；note 会 trim，Unicode 长度最多 2,000。
- API 读取当前 Snapshot 的 Ready 报告，按 Finding ID 重新计算 `subjectKey`，客户端不能提交该字段。
- 所有 Finding 必须属于同一个 Snapshot；校验失败整个请求返回 400/404/409，事务不产生部分结果。

响应 `202`：

```json
{
  "batchId": "uuid",
  "snapshot": {"id": "uuid", "commitSha": "..."},
  "applied": [{"findingId":"...","subjectKey":"sha256:...","status":"acknowledged","noteLength":12,"changed":true}],
  "changed": 1,
  "unchanged": 0,
  "idempotentReplay": false
}
```

响应不回传备注正文，只返回 `noteLength`；`note` 不进入批量结果、通知或聚合审计。
幂等重放返回同一结构并将 `idempotentReplay` 设为 `true`。

### Notification Endpoint 适配器

已有 Endpoint CRUD 增加字段：`adapter: "generic" | "slack"`，默认 `generic`。创建响应仍只显示一次
`signingSecret`。Delivery 列表增加同名适配器快照字段。

错误码：

- `GUARDRAIL_REVIEW_BATCH_INVALID`：数组为空、超过 50、重复 Finding 或输入格式错误。
- `GUARDRAIL_REVIEW_BATCH_CONFLICT`：幂等键对应不同请求哈希。
- `GUARDRAIL_REVIEW_BATCH_UNAVAILABLE`：数据库能力未升级。
- `NOTIFICATION_ADAPTER_INVALID`：未知适配器或不支持的组合。
- `NOTIFICATION_URL_INVALID` / `NOTIFICATION_HOST_BLOCKED`：适配器 URL 安全策略失败。

## 事务与审计

1. 锁定 Workspace/Snapshot 的 Ready 行。
2. 查询并锁定批量幂等记录；已有记录按请求哈希重放或冲突。
3. 逐项读取当前 Review，执行 upsert/delete；只有状态、note 或身份实际变化时写逐项审计。
4. 至少一项变化时写 `guardrail_review.batch_update` 聚合审计，metadata 只保存 Finding 身份、状态和
   note 长度；随后为订阅 Endpoint 写一个 `guardrail_review.batch_updated` outbox 行。
5. 保存批量结果摘要（不保存备注正文），提交一个事务。

所有查询必须同时带 Workspace 条件和 Snapshot 条件；游标/幂等键不能跨租户复用。

## 通知渲染

`NotificationAdapter` 只接受服务端已经构造的事件对象：

- `generic`：返回原事件 JSON，保持 `schemaVersion: repovista.notification.v1`。
- `slack`：返回 `{text, blocks}`；文本包含事件类型、Snapshot 短 SHA 和变化数量，blocks 每个最多展示
  50 个 Finding 的 ID/状态转移，备注只显示“changed/unchanged”布尔摘要。

Worker 在发送前根据 Delivery 的 `adapter` 快照渲染，之后统一加入 HMAC 时间戳/签名头。适配器渲染错误
是不可重试的 DomainError；DNS、超时、429/5xx 仍沿用 v1.3 重试策略。
