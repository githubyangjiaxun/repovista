## 1. 交付内容

v0.8 为 Architecture Guardrails 增加 Workspace 隔离、不可变、可审查的策略 Profile。策略只能
调整既有确定性规则的阈值；不能上传规则代码、脚本、Prompt 或模型配置，AI 也不参与 Finding
判定和策略修改。

- 内置 `default` Profile 使用稳定 ID；自定义 Profile 按 `Workspace + profileKey + version`
  递增并拥有独立 UUID、算法版本和 SHA-256 fingerprint。
- 完全相同的最新创建请求幂等复用既有版本；名称、描述、算法版本或阈值变化才创建下一版本。
  Profile 不支持原地修改和删除。
- Repository 保存未来 Snapshot 的当前绑定；Snapshot 创建时复制 Profile ID。切换绑定不会改写
  历史 Snapshot，迁移前 `NULL guardrail_profile_id` 回退内置 `default`。
- Guardrails JSON、SARIF、CLI 和 Web 均展示策略 provenance；不同 Profile fingerprint 的
  baseline comparison 返回 `409 GUARDRAIL_COMPARISON_INCOMPATIBLE`。
- 新增五个 HTTP 操作：列出、创建、读取 Profile，以及读取/更新 Repository 绑定。写操作遵循
  Session + CSRF 或 Workspace-bound Bearer Token 权限，跨 Workspace 资源使用稳定 404/403。
- 新增 `0006_guardrail_profiles.sql`，并记录 `guardrail_profile.create` 与
  `repository.guardrail_profile_assign` 审计事件。

## 3. 兼容性与安全边界

- `Snapshot.guardrailProfileId`、`GuardrailReport.profile` 和 `GuardrailComparison.profile`
  保持 nullable/optional 兼容语义，旧 Snapshot 与旧客户端不会因 Required 字段升级而失效。
- Profile fingerprint 比较在算法版本、阈值或策略指纹不一致时拒绝比较，不返回源码正文。
- 私有 Workspace/Profile/Repository 结果使用 `private, no-store`；公开结果要求重新验证缓存。
- Repository 源码从未在测试或发布流程中执行；AI 仍是可选解释层。
- 未进行真实 GitHub Private App Fixture 或外部 SARIF 平台联调；这些需要专用、不含敏感数据的
  外部环境，本记录不将其冒充为本地通过项。

发布后使用以下命令核对本地与远端一致性：

```bash
git rev-parse HEAD
git rev-parse origin/main
gh repo view githubyangjiaxun/repovista --json isPrivate,defaultBranchRef
```

期望：两个 SHA 相同，`isPrivate=true`，默认分支为 `main`。本次操作不读取、不保存、也不在
文档中记录任何密码、Token 或 `.env` 内容。

## 5. 已知边界

- Profile 是阈值配置版本，不是通用静态分析规则编程平台；新增规则需要未来升级算法版本。
- 比较结果按请求即时重算，不持久化可变 Finding 表，也不是安全扫描、编译器证明或自动合并阻断器。
- 策略绑定只影响新 Snapshot；要让旧代码使用新阈值，必须创建新的不可变 Snapshot。
