## 1. 交付内容

v1.1 增加了一条不依赖 GitHub、Ollama、OpenAI-compatible Endpoint 或模型 Key 的公开体验路径。
它使用仓库内可审查的两版 TypeScript/Python/Go Fixture，通过正式 Scanner、Tree-sitter Parser、
Graph、增量 Planner、Worker Lease、Store、Guardrails 和 Citation verifier 生成完整数据。

- `@repovista/demo` 保存 Base/Head 目录树，并从稳定的 path/content manifest 生成合成 revision。
- Base 使用 Full Index；Head 使用以 Base 为基线的真实 Incremental Index。
- Seeder 只领取自己刚创建的精确 Job；重复 Seed 复用 Ready Snapshot 和 Explanation。
- 两版共同的 `dependency_cycle` Finding 各有一条 Fake Provider Verified Explanation，可在现有
  History/Comparison 页面查看固定 Citation。
- Compose 默认等待一次性 `demo-seed` 成功后再启动普通 Worker；生产 Hardened Overlay 强制关闭
  Demo Seed 并要求 HTTPS、安全 Cookie 和显式数据库密码。
- 首页、Repository List 和 Explorer 对 synthetic fixture 做明确标记，不把它链接成真实 GitHub
  仓库，也不开放依赖远端的 Reindex/PR Impact 操作。

Fixture canonical URL 为 `https://repovista-demo.invalid/polyglot-demo`。`.invalid` 是保留域名；它
不是 GitHub 仓库，合成 revision 也不是 GitHub Commit。

## 3. Fixture 与 Seed 事实

稳定合成 revision：

```text
Base: bf152e7933a545faf8d2db570c8a4193a525f51f
Head: d60f8685aace140722634534fd384bd1693a6831
```

实际 Seed 输出的核心统计：

```text
Base: 7 scanned, 7 changed, 0 reused, 7 parsed, 0 deleted, mode=full
Head: 7 scanned, 2 changed, 5 reused, 2 parsed, 1 deleted, mode=incremental
```

Fixture 测试证明：

- manifest 文件枚举顺序稳定，内容改变会改变 revision；
- Scanner 只读取允许的普通文本文件，不执行 Fixture 内容；
- TypeScript、Python、Go 都产生真实 Symbol；TypeScript `src/api` ↔ `src/core` cycle 形成稳定
  Guardrail Finding；
- Head 删除 `src/legacy/flags.ts`、修改 `python/trends.py` 和 `src/core/service.ts`，其余五个
  文件按内容哈希复用；
- Base/Head Finding 的 `subjectKey` 相同，两个 Explanation 的 Snapshot、Commit、路径、行号和
  citation content hash 均由服务端验证。

```bash

  pnpm --filter @repovista/database test
```

## 5. 安全与可信边界

- Fake Provider 只证明有界 Evidence、Citation verifier、幂等持久化和历史比较链路；不证明任何
  外部模型的准确率、推理能力、延迟或成本。
- Guardrails JSON/SARIF 仍是确定性 CI 决策来源；自然语言 Explanation 不是安全证明、漏洞结论
  或自动修复建议。
- 生产 Overlay 使用 HTTPS `WEB_ORIGIN`/`API_ORIGIN`、`AUTH_COOKIE_SECURE=true`、显式数据库密码、
  无 PostgreSQL Host Port、只读文件系统、Drop Capabilities 和 `no-new-privileges`。
- 真实 GitHub App 私有仓库、外部模型服务、TLS 终止、WAF、Secret Manager 和恶意多租户沙箱仍由
  部署环境负责，本记录不把它们标记为已联调。
