## 1. 交付内容

v0.9 在确定性 Architecture Guardrails 上增加可选解释层。模型不参与 Finding、Severity、
Fingerprint、Profile、Commit 或 Evidence 位置的选择；这些事实全部由服务端从指定 Ready Snapshot
重新计算并固定。

- 新增 `POST /v1/snapshots/{snapshotId}/guardrails/explanations` 与对应 GET 读取接口，OpenAPI
  总数从 57 增至 59。
- 请求严格只接受 `findingId` 和可选 `provider/model`，不接受客户端源码、Finding JSON、Prompt、
  Rule 或 provenance。
- 固定 `guardrail-explanation-v1` 指令将 Finding 与源码标为不可信数据；每个 Evidence 最多读取
  400 行并压缩到 8,000 字符，单个 Finding 最多 20 段。
- 模型 JSON 有字段、数组、字符串和总响应大小上限。Citation verifier 移除不存在的 Evidence ID
  和无证据步骤；完全无有效引用时强制 `refused`。
- 新增 `0007_guardrail_explanations.sql`。结果以 Snapshot/Finding fingerprint/provider/model/
  prompt 唯一，API 在模型调用前优先复用；并发写通过 `ON CONFLICT DO NOTHING` 收敛为一行。
- 响应显式返回 Snapshot/Commit/parser/algorithm、Profile fingerprint、固定 Finding、provider/model、
  prompt 和创建时间。Web 与 CLI 可从 Citation 打开同一 Snapshot 的固定源码范围。
- 不持久化原始模型响应、完整源码文件、Provider 密钥或客户端 Prompt；只允许保存 verifier 接受的
  有界 Citation 摘录。

## 3. 独立数据库验收

使用固定 digest 的 PostgreSQL 17 + pgvector 镜像创建独立容器，数据目录为 tmpfs，并绑定一个由
Docker 随机分配的 localhost 端口。没有复用、清空或写入用户已有数据库。执行：

```text
DATABASE_TEST_URL=postgresql://repovista_test:***@127.0.0.1:<random>/repovista_test \
  pnpm --filter @repovista/database test
```

结果：`src/store.integration.test.ts` 11/11 通过；Migration Runner 成功应用 0001～0007。覆盖：

- `repository_snapshots.workspace_id` 回填、非空和复合外键；
- explanation 创建、精确唯一键查询、按 Snapshot/Workspace/ID 读取；
- 相同请求顺序复用；
- 两个并发相同创建请求返回同一 ID，结果为一个 `reused=false`、一个 `reused=true`；
- 既有 Snapshot、Answer、Citation、Share、Profile、PR Impact 与权限数据回归。

容器随后使用 `docker stop` 停止；因以 `--rm` 创建，临时数据随容器自动删除。

## 4. 权限与可信边界

- POST 沿用 Snapshot Access Check、Session CSRF、Viewer 和 Bearer Scope 约束；匿名写只保留现有
  Public Demo 行为。Workspace ID 取自资源 Access 结果，不能由当前 Principal 猜测或客户端提交。
- GET 同时限定 `explanationId + snapshotId + workspaceId`。跨 Workspace 或跨 Snapshot 不返回记录。
- 私有结果为 `private, no-store`；公开 Demo 使用 `public, max-age=0, must-revalidate`。
- Fake Provider 是确定性演示和测试适配器，不是外部模型质量证明。未使用真实模型账户、真实私有
  GitHub Fixture 或外部 SARIF 平台，本记录不把这些项目写成通过。
- Deterministic Guardrails JSON/SARIF 仍是 CI 的权威结果；自然语言解释不是安全证明、自动修复或
  合并阻断依据。

## 6. 已知边界

- 相同键的两个请求若在首次写入前同时到达，数据库能保证只保存一个结果，但两个上游模型调用仍
  可能同时发生；结果持久化是强幂等，供应商费用的分布式 single-flight 需要未来的租约或锁设计。
- Citation verifier 能证明路径、范围和 Quote 来自给定 Evidence，但不能证明自然语言的每个细节
  都正确；用户仍应打开 Citation 复核。
- 解释当前在 Finding 卡片按需生成，不提供历史列表、删除、编辑或跨 Prompt 版本比较。
