# RepoVista v0.5 开发计划

状态：开发中（2026-08-20）  
版本主题：私有仓库安全接入与团队可部署能力  
目标版本：`0.5.0`

## 1. 版本结论

v0.5 将 RepoVista 从“只能分析公开仓库的单公共工作区”升级为可安全自部署的团队代码智能平台。
公开匿名体验仍然保留，但私有仓库、任务、源码、检索、问答、PR 影响分析和分享必须经过真实的
Workspace 授权。

本版本不会将 GitHub 密码、Personal Access Token 或 Installation Token 保存到数据库。GitHub App
Private Key 只能来自部署 Secret，Installation Access Token 只在 API/Worker 内存中短期存在。

## 2. 用户价值

1. 使用 GitHub 登录，获得自己的私有 Workspace。
2. 安装 RepoVista GitHub App，只授权选中仓库，不需要长期 PAT。
3. 列出已授权仓库，导入私有源码，并使 Push/PR 流程持续更新。
4. Owner、Editor、Viewer 拥有明确的最小权限，资源 UUID 泄露不会绕过 Workspace 边界。
5. Web 通过 HttpOnly Session 工作，CLI 通过可撤销且只显示一次的 API Token 工作。
6. 私有仓库生成的 Report 默认为 Private，不会意外生成匿名源码页面。

## 3. 完整范围

### 3.1 身份与 Workspace

- GitHub OAuth Web Login，使用一次性 State 和限时 HttpOnly Cookie。
- Session Token 和 CSRF Token 只保存 SHA-256 Hash；原值不记录、不打印。
- 首次登录原子创建 User、GitHub Identity、Personal Workspace 和 Owner Membership。
- 创建 Workspace，将已登录用户按 GitHub Login 加入 Workspace，调整角色或移除成员。
- Browser Session 可切换 Active Workspace；API Token 在创建时绑定一个 Workspace。
- 登录、登出、Workspace/Member、Token、Installation、Import、Share 产生 Audit Event。

### 3.2 GitHub App

- App JWT 使用 RS256 在内存中生成，Private Key 只来自环境 Secret。
- 支持 Installation Setup Callback、安装信息验证、存储和撤销。
- 使用短期 Installation Token 列出可访问仓库、获取 PR 信息并 Clone 私有仓库。
- Token 不放入 Clone URL、命令行、Job Payload、错误、Event 或 Log。
- Webhook 继续验证 HMAC Signature，并校验 Installation、Repository ID 和 Workspace 归属。
- 支持 `installation`、`installation_repositories`、`push`、`pull_request` 安全边界；未导入私有仓库的
  Push 不会自动创建任务。

### 3.3 权限隔离

- Anonymous 只能访问 Public Workspace 内的 Public Repository 和 Public Share。
- Viewer 可读取 Workspace 仓库及所有派生资源。
- Editor 可导入、重跑、取消、建立 Embedding、问答、PR 分析和创建 Private Share。
- Owner 额外可管理 Workspace、Member、API Token 和 GitHub Installation。
- 每个 Repository/Snapshot/Job/Analysis/Conversation/Share 路由在业务查询前完成归属验证。
- 不用“UUID 难猜”作为权限控制。对无权资源统一返回 Not Found，避免枚举。

### 3.4 Web 与 CLI

- Header 显示登录、当前 Workspace 和退出；未配置 Auth 时保留公开模式。
- Settings 页管理 Workspace、Member、GitHub App 和 API Token。
- Import 页可在公开 URL 与已授权私有仓库之间选择。
- Private Repository 和 Private Share 显示明确锁定标识。
- CLI 新增 `auth login/status/logout`、`workspace list/use`、`github installations/repos`，并为现有命令自动发送
  Bearer Token。

## 4. 非目标

- 不保存 GitHub 用户 Access Token，不实现代替用户写入 GitHub。
- 不支持仓库写权限、自动改代码、自动提交 PR 或执行仓库脚本。
- 不在 v0.5 实现 SAML/SCIM、GitHub Enterprise Server、Email/Password 登录或组织计费。
- 不实现 Email Invitation；Owner 只能添加已经登录过 RepoVista 的 GitHub User。
- 不为 Private Share 提供无认证的 Unlisted 链接。
- 不修改独立 Git 仓库 `extensions/vscode`。

## 5. 实现顺序

1. `0005_private_repository_auth.sql`：身份、Session、Token、Installation、Audit 表与约束。
2. Contracts/Config/GitHub App Client：定义全部稳定边界。
3. Store：登录原子事务、Workspace/Member、Token、Installation 和 Access Check。
4. API：Cookie/Bearer Principal、CSRF、OAuth、Workspace 路由、GitHub Installation 路由。
5. Repository/PR/Webhook/Share 改造：移除非必要的 `PUBLIC_WORKSPACE_ID` 硬编码。
6. Worker/Git：Job 只携带 Installation ID，执行时 Mint Token，使用临时 AskPass Clone。
7. CLI/Web：完成认证、Workspace、Installation 和 Private Import 用户路径。
8. OpenAPI/Compose/README/Changelog/Tests/真实验收同步。

## 6. 完成定义

- 空库和 v0.4 数据库都能幂等升级到 `0005`。
- OAuth State 重放、过期、Cookie 不匹配均失败；Session/API Token 撤销立即生效。
- 公开、Viewer、Editor、Owner、跨 Workspace 访问矩阵具有数据库和 API 自动化测试。
- 一个真实 Private GitHub Repository 可安装、列出、导入、Clone、索引、搜索、问答和 PR 分析。
- Push Webhook 仅更新已导入且归属正确的仓库；伪造 Installation/Repository ID 被忽略并审计。
- 进程列表、Git Remote、Job Event、API Error、App Log 和数据库不出现 Installation Token/Private Key。
- Private Repository 生成 Report 时默认 Private，匿名访问统一返回 404。
- `pnpm check`、PostgreSQL Integration、Playwright、Docker Build、OpenAPI 校验和 Git 审计全部通过。
- 版本升级为 `0.5.0`，完整验收记录使用 `yueliang` Git 身份提交。
