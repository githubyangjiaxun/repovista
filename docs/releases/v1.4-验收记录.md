# RepoVista v1.4 验收记录

状态：发布候选已完成本地代码门禁、容器构建与独立 PostgreSQL 验证；远端 CI/推送结果在提交后补记。

版本：`1.4.0`

主题：Batch Review Actions & Provider-specific Notification Adapters

本记录只写已经实际执行、能够由代码或命令输出复核的结果。不记录密码、Token、私钥、签名
Secret、`.env` 内容或可复用的数据库凭据。真实 Slack、真实私有 GitHub App、外部模型质量和
公网 Webhook 行为不属于本轮本地验收。

## 1. 交付内容

- 新增最多 50 个 Finding 的原子批量 Review API、CLI 和 Web 多选操作；服务端重新计算
  `subjectKey`，请求体严格校验，`Idempotency-Key` 按 Workspace/Snapshot 绑定请求哈希。
- 批量结果只返回 Finding 身份、状态、变化标记和 note 长度。逐项变化、聚合批次和 outbox
  写入同一事务；无变化项不产生额外审计或通知。
- 新增 `guardrail_review.batch_updated` 事件，以及 `generic`/`slack` 通知适配器。Generic
  保持原始 JSON；Slack 使用服务端固定模板、最多 50 个 blocks，并限制官方 HTTPS 默认端口。
- `notification_deliveries.adapter` 保存投递时的适配器快照；Endpoint 后续修改不会改变已排队消息。
- 新增前向 Migration `0011_batch_reviews.sql`，不修改 0001–0010；同步 Contracts、OpenAPI、
  API、Worker、CLI、Web、设置界面、README、Roadmap、Security 和 CHANGELOG。

## 4. 可信边界与已知限制

- Deterministic Guardrails 仍是唯一的 Finding、severity、阈值、报告状态和 CI 退出码来源；批量
  Review/通知不会改变这些值，也不会调用 AI。
- Review note 正文、源码、模型 prompt/answer 和凭据不进入批量结果、审计聚合、通知 payload 或
  Slack blocks；不执行用户模板、脚本或远程代码。
- Slack URL 只允许 `https://hooks.slack.com` 或 `https://hooks.slack-gov.com` 的默认端口；
  Worker 继续执行 DNS/IP SSRF、超时、禁止重定向、签名和有限重试。
- 本轮没有向真实 Slack Webhook、真实 GitHub App 私有仓库或外部模型发起请求；Fake fetch、
  deterministic Provider 和本地 Fixture 只证明协议、证据验证和安全边界，不证明第三方可用性、
  模型质量、生产容量或公网网络行为。
