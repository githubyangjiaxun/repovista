# RepoVista v0.7 开发计划：Guardrails Snapshot Baseline

状态：已实现并验收（2026-08-23）  
目标版本：`0.7.0`

## 1. 版本主题

v0.7 在 v0.6 Architecture Guardrails 的确定性报告之上增加“不可变快照基线比较”。用户可以把
一个旧的 Ready Snapshot 作为基线，与当前 Snapshot 比较，准确看到哪些架构问题新增、解决、持续
存在或指标发生变化。

比较仍然是读模型：不新增数据库表，不修改 Snapshot，不运行仓库代码，也不让 AI 参与判定。

## 2. 用户价值

1. CI 可以只关注本次提交引入的架构回归，而不是重复阅读历史问题。
2. 维护者可以确认某个 Finding 是否已经解决，并保留两个 Commit 的证据。
3. 结果绑定同一仓库、Parser Version、规则算法和阈值，避免跨版本比较产生误导。
4. 公共和私有仓库复用既有 Workspace 权限；私有基线不会被匿名探测。

## 3. 交付范围

### 3.1 比较模型

- 输入：`baseSnapshotId` 与 URL 路径中的 `headSnapshotId`。
- 两个 Snapshot 都必须是同一 Repository、`ready`、Parser Version 相同，并使用同一
  `architecture-guardrails-v1` profile。
- Finding 身份使用规则、路径、符号/包指标和证据位置的 Snapshot 无关稳定键；Snapshot ID
  不参与匹配，因此同一个问题可以跨快照识别。
- 状态：`added`、`resolved`、`unchanged`、`changed`。
- 总体状态：
  - `regressed`：新增或升级了 error/warning Finding。
  - `improved`：解决或降低了 error/warning Finding，且没有回归。
  - `unchanged`：没有可操作级别的回归或改善。
- 所有输出按状态、规则、路径、行号和稳定键排序；相同输入必须得到字节级稳定结果。

### 3.2 HTTP API

```http
GET /v1/snapshots/{headSnapshotId}/guardrails/compare?baseSnapshotId={baseSnapshotId}
```

两个 Snapshot 先分别执行 Workspace Access Check。跨 Workspace、跨 Repository、非 Ready 或
Parser/算法/阈值不兼容统一返回稳定的 Not Found/Conflict，不泄露另一个 Snapshot 是否存在。

响应是标准 `{ data, meta }` Envelope，`data` 为 `GuardrailComparison`。不包含源码正文；每个
Finding 的 base/head 仍带固定路径、行号、指标和证据，客户端可以跳转到对应 Snapshot。

### 3.3 CLI

```bash
repovista guardrails compare <base-snapshot-id> <head-snapshot-id>
repovista guardrails compare <base-snapshot-id> <head-snapshot-id> --json
```

默认输出摘要和变更 Finding；`--json` 输出完整比较报告。出现回归时退出码为 `2`，网络/契约错误
沿用既有 CLI 错误码。

### 3.4 Web

Repository Workspace 的 Guardrails 页面增加基线选择器。选择同一 Repository 的历史 Ready
Snapshot 后显示比较摘要、回归/改善状态和双侧证据按钮；未选择基线时继续显示当前快照报告。

## 4. 非目标

- 不自动阻断 Webhook、合并 Pull Request 或修改代码。
- 不比较不同 Parser Version、不同规则 profile 或不同仓库。
- 不把 Finding/比较结果持久化为可变表。
- 不宣称该比较替代安全扫描、编译器或完整架构审计。

## 5. 完成定义

- 纯函数比较在相同两个报告输入下字节级稳定，重复 Finding 不丢失。
- 新增、解决、持续、指标变化和严重级别升降均有单元测试。
- API 覆盖 Ready gate、跨 Workspace/Repository、兼容性和无源码泄露。
- CLI 覆盖摘要、JSON、回归退出码和参数错误。
- Web 覆盖基线选择、空/加载/错误、双侧固定证据导航。
- OpenAPI、README、CHANGELOG、Roadmap、文档索引和验收记录同步。
- 全量质量门禁、Compose 构建和 Git 远端同步通过。

## 6. 实施阶段

1. Contracts 与 `@repovista/guardrails` 比较纯函数及测试。
2. API 路由、权限/兼容性校验、OpenAPI 和 API 测试。
3. CLI compare 子命令、输出格式、退出码和 CLI 测试。
4. Web 基线选择与双快照证据视图、组件测试。
5. 版本/文档/验收记录、全量门禁、独立 Git 提交和 Push。
