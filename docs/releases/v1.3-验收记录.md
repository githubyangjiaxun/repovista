## 1. 交付内容

- 新增 Review append-only 历史投影和游标分页，按 Workspace、Snapshot、Finding `subjectKey`
  交叉过滤；历史只返回状态、备注长度变化和操作者摘要，不保存备注正文。
- 新增 `workspace_notification_endpoints` 与 `notification_deliveries`，前向 Migration
  `0010_notifications.sql`；Endpoint+事件键幂等，支持租约、心跳、有限重试、投递历史和级联清理。
- Workspace Owner 可管理出站 Webhook Endpoint；创建响应只显示一次派生 signing Secret，Secret
  不落库、不进入 URL、日志、审计或通知 payload。
- Worker 发送 HMAC 签名 JSON，执行 HTTPS/URL 校验、DNS/IP SSRF 防护、禁止重定向、超时和指数退避；
  事件仅覆盖 `guardrail_review.updated` 与 `guardrail_review.cleared`。
- API、OpenAPI、Contracts、CLI、Web Settings/时间线、Worker、Compose 配置和运维文档同步更新；
  确定性 Finding、SARIF 状态、CI 退出码和 AI prompt/verification 边界保持不变。
- 所有 Workspace package、CLI User-Agent、SARIF 默认工具版本和 OpenAPI Info 版本统一为 `1.3.0`。

## 6. 可信边界与已知限制

- Review 和通知是协作元数据；不会改变确定性 Guardrail Finding、severity、报告状态、SARIF 或 CI
  退出码，也不会把备注发送给 AI Provider。
- Webhook payload 不包含备注正文、源代码、模型输出或凭据。接收方必须在时间窗口内校验
  `X-RepoVista-Timestamp` 与 `X-RepoVista-Signature`；生产部署仍需配置网络出口 Allowlist、TLS 终止、
  Secret Manager 和监控。
- 单元、API、Store Integration、Web、E2E 和 CI 使用本地/测试下游；没有向真实第三方 Webhook
  发出请求，也没有声称 Slack/Teams/Email 联调完成。
- 没有使用真实 GitHub App 私有仓库或外部模型账户做本轮验收；Fake/deterministic Provider 只证明
  证据与验证链路，不证明外部模型质量。
- Bundled Demo 的通知配置和写操作仍按设计受限；CI Demo smoke 验证了可复现启动、API journey、
  Seed 幂等和清理，但不是生产容量或多租户压力测试。
