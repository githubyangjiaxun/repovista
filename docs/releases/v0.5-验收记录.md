# RepoVista v0.5 验收记录

日期：2026-08-22
版本：`0.5.0`
提交身份：`yueliang <yueliang@users.noreply.github.com>`

这份记录只包含本机实际执行并可复核的结果。v0.5 的自动化安全边界已经完成；本轮没有配置
专用 GitHub App 和无敏感数据的 Private Fixture Repository，因此没有把“真实 GitHub 私有仓库
安装、Clone、Webhook、PR”写成已通过。仓库没有 Push，`extensions/vscode` 仍是独立 Git 仓库。

## 1. 本轮交付范围

- GitHub OAuth、HttpOnly Session、CSRF、Workspace 切换、Owner/Editor/Viewer 与 API Token。
- GitHub App Installation、授权仓库列表、短期内存 Token、Private Clone AskPass 与安全 Webhook。
- Repository/Snapshot/Job/PR/Share/Export 的 Workspace 隔离和公开兼容路径。
- Web 私有导入、私有分享 Metadata、Viewer 只读、Settings 与认证 Header。
- CLI `auth`、`workspace`、`github` 和 `analyze --installation`，配置文件权限为 `0600`。
- Cookie 认证的跨 Origin Export 使用 `credentials: include` 的 Fetch + Blob 下载；私有 Export
  返回 `Cache-Control: private, no-store`。
- OpenAPI 49 个 Operation、Compose/环境示例、README、安全文档和版本 `0.5.0` 同步。

## 4. 安全与凭据审计

按发布计划扫描了常见 Installation/API Token、Private Key、Webhook Canary、`password` 与
`token` 关键词，并额外对非测试、非文档运行文件执行了高置信格式扫描。

- 没有发现真实凭据、PEM 或可复用 Token。
- 关键词扫描命中的是安全文档、配置字段、测试专用假值、数据库 Hash 字段和实现变量。
- 私有 Clone Token 只作为 Worker 内存值传给临时 AskPass，不进入 Remote URL 或进程参数。
- Web Export 使用认证 Fetch；API 暴露必要的 `Content-Disposition` Header，私有响应不可共享缓存。
- 三个最终镜像的 Config/History 未出现 Private Key、Installation Token 或 RepoVista API Token；
  `.dockerignore` 排除 `.env`、Git 元数据、依赖和构建产物。
- 用户曾在聊天中提供的凭据未写入仓库、验收命令或本文。
