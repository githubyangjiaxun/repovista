## 1. 交付内容

v0.7 在 v0.6 Architecture Guardrails 上增加不可变 Snapshot 基线比较。比较是纯读模型：不新增
数据库表，不修改 Snapshot，不执行仓库代码，也不让 AI 参与 Finding 判定。

- 同一 Repository 的两个 Ready Snapshot 才能比较；跨 Workspace/Repository、非 Ready、Parser
  Version、算法版本或阈值不兼容会被拒绝。
- Finding 以不含 Snapshot ID 的稳定键配对，支持 `added`、`resolved`、`unchanged`、`changed`，
  并按 `info < warning < error` 计算回归/改善。
- API：`GET /v1/snapshots/{headSnapshotId}/guardrails/compare?baseSnapshotId=...`，返回标准
  Envelope，不含源码正文；私有结果 `private, no-store`，公开结果要求重新验证缓存。
- CLI：`repovista guardrails compare <base> <head>`，支持人类摘要和 `--json`；有回归时退出码 `2`。
- Web：历史 Ready Snapshot 选择器、比较摘要、竞态安全的加载/错误状态，以及 Base/Head 固定证据按钮。

## 3. Git 与远端审计

v0.7 使用独立提交，不改写历史，不把 `extensions/vscode` 独立仓库纳入主仓库：

```text
<提交后填写最终 SHA> feat(v0.7): add guardrails baseline comparison
```

推送后核验：

```bash
git status --short --branch
git ls-remote --heads origin main
gh repo view githubyangjiaxun/repovista --json isPrivate,defaultBranchRef
```

推送后确认远端仓库仍为 Private，`main` 的远端 SHA 与本地 HEAD 一致。

## 4. 已知边界

- 基线比较是架构维护提示，不是完整安全扫描、编译器证明、业务正确性证明或自动合并阻断器。
- Finding 稳定键依赖当前 `architecture-guardrails-v1` 规则语义；算法或阈值变更必须升级兼容版本。
- 比较结果按请求即时重算，当前不做可变 Finding 持久化或跨版本缓存。
