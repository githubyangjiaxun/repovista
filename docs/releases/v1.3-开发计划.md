# RepoVista v1.3 开发计划：Review Timeline & Signed Notifications

目标版本：`1.3.0`

v1.3 让 v1.2 的人审元数据可追溯、可协作。Review 当前状态仍然是唯一的确定性分析输入之外
的协作信息；历史从已有 append-only `audit_events` 投影，不复制 Finding 或模型结果。
通知采用通用出站 Webhook，便于接入 Slack、CI 编排或团队内部系统，但不绑定某一家 SaaS。

## 用户价值

- 维护者可以按 Snapshot/Finding 查看 Review 状态变化、操作者和备注长度变化。
- 团队可以为 Workspace 配置签名 Webhook，在 Review 变更或清除时收到可验证事件。
- Webhook 发送具备 outbox、幂等键、租约、指数退避和投递历史；临时下游故障不会丢事件。
- 通知不会传播 Review 备注正文、源代码、模型输出或凭据。

## 交付范围

1. Review 历史游标分页 API、CLI 和 Web 时间线；支持 Snapshot/Finding/status 过滤。
2. `workspace_notification_endpoints` 与 `notification_deliveries` 前向 Migration `0010`。
3. Workspace Owner 管理 Endpoint，Editor/Owner 查看投递状态，支持测试事件和禁用 Endpoint。
4. Review upsert/clear 在同一事务写入 outbox；Worker 负责签名 POST、超时、SSRF 防护和重试。
5. 新增 `NOTIFICATION_SIGNING_SECRET`、请求超时和最大重试配置；秘密不落库。
6. OpenAPI、Contract、后端/数据库/前端/AI 边界/运维文档、单元/集成/E2E 测试。

## 非目标

- 不保存或回放 Review 备注正文；历史只显示状态、备注长度与是否变化。
- 不改变 Guardrail Finding、severity、报告状态、CI 退出码或 AI prompt/verification。
- 不实现特定 Slack/Teams/Email SDK；Webhook 是唯一外部适配面。
- 不允许 Webhook 回调反向写入 RepoVista；所有写入仍走现有 Session CSRF/Token scope。
- 不为公开 Bundled Demo 创建通知 Endpoint，也不把公开 Snapshot 的协作历史匿名化暴露。

## 完成定义

- 历史查询严格按 Workspace 和当前 Snapshot/Finding subject key 隔离，游标不可篡改。
- Endpoint URL 在生产必须 HTTPS、无凭据/Fragment；投递拒绝 loopback、私网、link-local、云元数据地址，
  禁止跟随重定向并有硬超时。
- 每个投递有稳定幂等键；网络/5xx/429 按指数退避，达到上限进入 `failed`，不会无限重试。
- 签名为 `X-RepoVista-Timestamp` + `X-RepoVista-Signature: sha256=...`，接收方可独立验证。
- Outbox payload 只含事件身份、Snapshot/Finding、状态变化、备注长度和操作者摘要，不含备注正文。
- OpenAPI 与 Fastify 路由匹配，完整本地门禁和 GitHub Actions 通过；仓库保持 Private。
