## 4. Review 可信边界与导出不变量

- Review 是人类协作元数据，不是 AI 评分；备注不会发送给任何模型，也不会写入审计原文。
- 服务端从当前 Ready Snapshot Report 重新选择 Finding 和 `subjectKey`；客户端不能提交 severity、
  metric、message、Finding JSON 或 provenance。过期/伪造 subject key 会被过滤。
- Session 写入必须通过 Origin + CSRF；Viewer、缺少 `repo:write`/`workspace:admin` 的 Token、
  匿名写入和 Bundled Demo 写入均被拒绝。公开 Demo 仍可读取，但不可修改。
- `unreviewed` 用无数据库记录表示；Review 写入使用 Workspace/Snapshot/Finding 唯一键，清除
  操作幂等。私有列表和导出响应使用 `private, no-store`，公开响应要求重新验证。
- SARIF `level`、Finding 顺序/数量、deterministic report status 和 CLI error exit code 不受
  Review 影响。JSON 顶层分离 `deterministic` 与 `reviews`，并按 Finding ID 稳定排序。

## 7. 已知边界

- Review 当前是每个 Snapshot 的当前状态，不提供历史时间线、通知或批量操作；这些列为后续版本候选。
- 公开 Snapshot 的 Review 读取遵循现有公开访问策略；部署方若不希望公开协作备注，应将仓库设为
  Private，而不是依赖客户端隐藏。
- 本地自动化没有配置真实 GitHub App、真实私有仓库、外部 SARIF 平台或外部模型账户；这些联调
  仍需专用、不含敏感数据的环境。
