## 1. 交付内容

v0.6 的交付主题是 Architecture Guardrails。报告始终绑定一个 Ready Snapshot 的完整 Commit、
Parser Version 和算法版本 `architecture-guardrails-v1`，不把 Finding 持久化为可变状态。

已交付：

- `dependency_cycle`：只在已解析 `imports` 边上计算包级强连通分量。
- `large_file`：超过 800 行或 100 KiB。
- `large_symbol`：跨度超过 150 行。
- `high_fan_in`：至少 20 条非 `contains` 入边。
- `unresolved_import`：无法在 Snapshot 内解析的导入，级别为 info。
- `parse_failure`：非 `parsed` 文件，级别为 warning。
- JSON API、SARIF 2.1.0 API、CLI `guardrails` 和 Web Guardrails Workspace。
- public/private Workspace 访问检查、固定源码证据链接和私有 `no-store` 下载边界。

AI 不参与规则判定。未来的解释层只能读取已经存在的 Finding、Fingerprint 和证据。

## 3. API 与安全验收

- 非 Ready Snapshot 不计算报告。
- 跨 Workspace 或无权限 Snapshot 统一返回稳定 404。
- SARIF 只含规则结果、路径、行号和指标，不含源码正文、安装令牌或 API Token。
- 私有响应使用 `Cache-Control: private, no-store`；公开响应可以重新验证缓存。
- Finding 的 `path/startLine/endLine` 可跳转到指定 Snapshot，而不会跟随 Repository 最新版本漂移。
- CLI SARIF 文件使用服务端安全文件名；error finding 返回退出码 `2`，warning/info 返回 `0`。

## 5. 已知边界与后续

- 规则是架构维护提示，不是完整安全扫描、编译器证明或业务正确性证明。
- 包名当前由仓库相对路径的稳定启发式推导；未来可增加显式 workspace/package manifest 解析，
  但必须保持算法版本和报告重现性边界。
- 当前报告每次从 Snapshot 重算；基线比较、策略文件和 PR 阻断属于后续版本。
- 真实 GitHub App、私有仓库和外部 SARIF Code Scanning 接入需要不含敏感数据的专用 Fixture，
  不在本次本地自动化记录中冒充完成。
