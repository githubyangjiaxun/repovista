# RepoVista v1.1 开发计划：可复现公开 Demo 与部署体验

状态：已完成验收（2026-08-27）
目标版本：`1.1.0`

## 1. 版本目标

v1.1 不增加新的代码分析产品能力，而是让贡献者和第一次访问项目的人在没有 GitHub Token、
外部模型、Ollama 或待分析远端仓库的情况下，可靠看到 RepoVista 的完整主路径。

一条标准 Demo 应同时证明：固定 Snapshot、真实 Tree-sitter 多语言解析、增量复用、架构图、源码、
检索、确定性 Guardrails、Fake Provider 解释及跨 Snapshot Explanation History。所有结果来自仓库内
可审查 Fixture，不能把合成修订伪装成真实 GitHub Commit，也不能将 Fake Provider 宣称为模型质量。

## 2. 交付范围

- 新增 `@repovista/demo` 包，保存两版可审查的 TypeScript、Python、Go Fixture。
- 使用现有 Scanner、Parser、Graph、Worker Lease 与数据库完成路径生成 Base/Head Snapshot；Head 必须
  是对 Base 的真实增量索引，而不是直接插入结果 JSON。
- Seed 仅领取自己刚创建的精确 Job，不得误领普通用户队列中的任务。
- Seed 可重复运行：已经 Ready 的目标修订不重复创建 Snapshot、Job、Explanation 或 Audit 记录。
- 为两版共同的确定性 Finding 保存 Fake Provider Verified Explanation，使历史/比较开箱可见。
- Compose 默认运行一次性 `demo-seed` 服务；它成功后普通 Worker 才启动。
- 首页和 Repository 页面识别内置 Fixture，提供直接入口与明确标签，并禁用依赖真实 GitHub 远端的
  Reindex/PR 操作。
- 新增 API Smoke 脚本，验证健康、两版 Snapshot、增量统计、Map、Source、Search、Guardrails 和
  Explanation History。
- CI 增加真实 PostgreSQL + Compose Demo Smoke；发布门禁继续包含现有全量测试和镜像构建。
- 新增生产加固 Compose 覆盖层和部署说明：关闭 Demo Seed、要求 HTTPS/安全 Cookie/数据库密码、
  移除 PostgreSQL Host Port，并收紧容器权限。
- 更新 README、Contributing、Roadmap、Changelog、工程文档索引和版本号。

## 3. 明确不做

- 不新增公开托管 SaaS、云账户、域名、计费或遥测。
- 不依赖真实 GitHub API、外部模型或网络下载来构造 Demo 数据。
- 不为 Fixture 绕过 Workspace、Snapshot、Citation、Guardrail 或 Store 不变量。
- 不执行 Fixture 中的 package scripts、Python、Go 或任何二进制。
- 不新增 Demo 专用业务 API；首页通过现有 Repository 列表发现保留的 Fixture identity。
- 不把本地 Compose 默认配置描述成可直接暴露到公网的生产配置。

## 4. 完成标准

1. 空数据库执行一条 Compose 启动命令后，Web/API/Worker 健康且 Demo Head Snapshot 为 Ready。
2. Base 为 Full，Head 为 Incremental；统计至少包含 changed、reused、parsed 和 deleted 的可验证值。
3. 两个 Snapshot 都来自同一可审查 Fixture，Commit 字段是稳定合成修订并在 UI/文档中明确标记。
4. 同一逻辑 Guardrail Finding 有两条 Verified Explanation 历史，provider 为 `fake`，Citation 均能
   回到各自固定 Snapshot 源码。
5. 重复 Seed 后 Repository、目标 Snapshot、成功 Job 和对应 Explanation 数量不增加。
6. Seed 的精确领取测试证明不会处理已有的其他 queued Job。
7. 首页 Demo 入口在 Seed 可用时直达固定 Head；不可用时安全降级为 Repository 列表，不阻塞首页。
8. Hardened Compose 配置可解析，默认关闭 Demo，且缺少必要生产变量时快速失败。
9. 全量质量门禁、数据库集成、浏览器、Compose Smoke、镜像、安全扫描和 Git 审计通过后发布。
